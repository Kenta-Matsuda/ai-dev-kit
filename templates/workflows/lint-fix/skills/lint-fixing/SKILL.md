# lint-fixing

lint の指摘を、コードの振る舞いを変えずに **原因から** 直す手順と規約です。

## 変えないもの

- linter の設定（`eslint.config.*`、`.eslintrc.*`、`package.json` の `eslintConfig`）、ルールの強さ、`ignores`
- `// eslint-disable`、`// eslint-disable-next-line`、`/* eslint … */` のコメント（既にあるものも消さない）
- コードの振る舞い: 関数の戻り値、分岐、ループ、例外の扱い、副作用の順序。テストが通ることと振る舞いが同じことは別で、テストの無い部分も変えない

## ルールごとの直し方

| ルール | 直し方 | してはいけないこと |
| --- | --- | --- |
| `no-unused-vars` | 使われない変数・引数・import を消す。引数が API の形で要るなら（コールバックの第 1 引数など）そのままにして報告に挙げる | `_` を付ける、無意味に参照する、`void x` |
| `eqeqeq` | 両辺の型を確かめて `===` / `!==` にする。`null` と `undefined` を同時に見ている `== null` は `=== null \|\| === undefined` に展開するか、型が明らかならどちらかにする | 型を確かめずに置き換える（`'0' == 0` が true だった箇所は振る舞いが変わる） |
| `prefer-const` | 再代入が無い `let` を `const` にする | 再代入がある変数を無理に `const` にして処理を変える |
| `no-var` | `var` を `let` / `const` にする。関数スコープと巻き上げに依存した書き方（宣言より前の参照、ループ内のクロージャ）は、依存を外してから直す | 宣言の位置を変えて振る舞いを変える |
| `no-undef` | import / require の抜けを足す。グローバル（`process`、`window`）は設定の `globals` にあるべきもので、無ければ報告に挙げる | 設定に `globals` を足す |
| その他 | ルールのドキュメントの「正しい例」に合わせる。意図が分からない指摘は直さずに報告に挙げる | 推測で書き換える |

## 誤検知

- 指摘が誤りだと判断したら（ルールが意図を読めていない、直すと振る舞いが変わる）、黙らせずにファイル・行・理由を最終報告に挙げる。設定の見直しは人の仕事
- その場合そのファイルの lint は通らないので、fix step では失敗として戻される。review step でもう一度判断され、報告に残る

## 確かめ方

- 直したファイルだけを実行する: `npx eslint src/<file>`（review step は `npx eslint .` と `npm test`）。終了コード 0 が通った印
- 通らないときは出力の行とルールを読み、原因を直す。同じ直し方を繰り返さない
- `--fix` は使ってよいが、結果の差分を読んで振る舞いが変わっていないことを確かめる（`--fix` は `prefer-const` や `no-var` を自動で直すが、`no-unused-vars` は直さない）

## 書いてはいけないもの

- 設定の変更、`eslint-disable`、ルールの無効化、処理の削除による指摘の回避、テストの変更（lint の修正でテストが落ちるなら、修正の方を見直す）。テストを直す step では `src/` の外（実行の notes ディレクトリを除く）に書かない
