# 0.2 設計案 — コマンド体系・設定・導入手順（承認待ち）

作成: 2026-09-21。対象: `tmp.md`（9/21 追記）、`tmp2.md`、`docs/user-guide`（0.2 草稿）を統合した、利用者目線の設計案。

**状態（2026-09-21）**: S1 実装済み（CLI・テンプレート・テスト・ユーザーガイド・保守者 docs を更新）。S2 の一部（init の対話 4 問、`aidev status`、廃止コマンド削除）も同時に実装。残りは S3（GitHub/GitLab hosting、他ツール adapter、`task start`）。
承認後に段階実装し、ユーザーガイドは **実装済みの範囲だけ** を説明する形に改めます（「設計のみ」を利用者向け文書に書かない）。

## 1. 前提（確定事項）

| 項目 | 決定 | 根拠 |
| --- | --- | --- |
| 形態 | 端末に1回だけ入れる CLI。PKG を submodule にしない、wrapper リポジトリを作らない | tmp.md 9/21 追記 |
| PKG 固有設定の置き場所 | **PKG リポジトリに commit**（`aidev.yaml` と `.aidev/` の一部） | tmp2.md、ユーザー回答 |
| kit が配るもの | 既定設定、Agents / Skills / hooks / MCP のテンプレート、PKG 非依存の標準動作 | tmp2.md |
| 誰がやるか | PKG 固有設定と Wiki の初回生成は **PKG メンバーのうち1人（導入担当者）**。他メンバーは clone して `aidev init` だけ | tmp2.md |
| 更新通知 | CLI 実行時に新版があれば「新しいバージョンがあります。更新してから実行しますか？」 | tmp2.md |
| Wiki の生成方式 | survey + batch + 完了報告（実装済み） | 本日の実装 |

0.2 docs から **変える** 点: 中央 kit の `profiles/<pkg-id>/` と `aidev profile propose` は採用しない（設定は PKG に commit するため不要）。provider / tool adapter の抽象は保つが、初版は Claude Code + Azure DevOps + generic に限定する。

## 2. PKG リポジトリ側のファイル配置

```
my-pkg/
├─ aidev.yaml                 PKG 固有設定（commit）
├─ .aidev/
│   ├─ policy.yaml            承認済み権限（commit。CLI だけが配置）
│   ├─ overrides/             kit テンプレートへの PKG 固有差分（commit、任意）
│   │    ├─ agents/  skills/  CLAUDE.md
│   ├─ knowledge/             LLM Wiki（commit。manifest / inventory / *.md）
│   ├─ workflows/             PKG 固有 workflow（commit、任意）
│   └─ .gitignore             CLI が生成: cache/ leases/ tasks/ sync.lock materialized.json を除外
├─ .claude/  CLAUDE.md  .mcp.json   kit テンプレート + overrides から生成（Git 管理外: .git/info/exclude）
└─ <PKG の通常ファイル>
```

- 生成物（`.claude/` 等）は commit しない。`aidev update` で全員に kit の改善が自動反映され、マージ衝突も起きない。
- PKG で変えたい内容は `.aidev/overrides/` に置いて commit する。生成時に kit テンプレートへ重ねる。
- Wiki は PKG リポジトリに commit する（**要確認 A**）。理由: リポジトリが1つで済み、`git pull` だけで全員が同じ Wiki を持つ。別 knowledge repository は後から選べる設計にする。

## 3. コマンド体系（16 → 10）

| 場面 | コマンド | 役割 |
| --- | --- | --- |
| 端末 | `aidev update` | CLI 本体の更新と、登録済み全 PKG の生成物の再生成 |
| 端末 | `aidev doctor` | Node / Git / ツール / token / 登録済み PKG の診断 |
| PKG | `aidev init` | 導入担当者: 対話で `aidev.yaml` と policy 候補を作る。メンバー: 質問なしで生成物を用意 |
| PKG | `aidev status` | 3SHA、pending prose、drift、lease を1画面で表示（`check` + `knowledge status` の統合） |
| PKG | `aidev check` | `status` と同じ検査を終了コードで返す（CI 用。`--strict`） |
| PKG | `aidev knowledge build \| status` | Wiki 生成（本日の仕組み）。`status` は `aidev status` の Wiki 部分 |
| PKG | `aidev sync` | tracking branch への追従 → Wiki 更新 → PR |
| PKG | `aidev permission configure \| reconfigure \| show` | policy 候補の生成と承認（`init` からも呼ぶ） |
| PKG | `aidev task …` / `aidev workflow …` | 既存どおり（issue-to-pr、loop） |
| PKG | `aidev eject` | 管理解除 |
| 内部 | `aidev hook …` / `aidev mcp …` | ツールから呼ばれる |

廃止: `plan`、`kit apply`（wrapper 専用）、`config`、`pkg`、`profile`（中央 profile 前提）、`evolve`（`self_evolution` は journal 記録のみに縮小し、提案は将来）。
似た名前の整理: `init --refresh` → `update` に一本化。`knowledge build --refresh/--resume` → 廃止済み（増分が既定、全件は `--full`）。

## 4. 設定項目（`aidev.yaml` v2）

利用者が触るのは上段だけ。下段は既定のままで動き、ユーザーガイドには載せない（maintainer docs に記載）。

```yaml
version: 2
package:
  name: my-pkg                 # init が remote から推測
  include: ["src/**", "docs/**"]   # Wiki の生成対象。init が構成から推測して確認
  exclude: ["**/node_modules/**", "**/generated/**"]
secrets_paths: [".env*", "**/secrets/**"]
hosting:                       # init が remote URL から自動判定
  type: azure-devops           # azure-devops | generic（github / gitlab は後続）
  organization: <org>
  project: <project>
  repository: my-pkg
  auth_env: AZURE_DEVOPS_PAT
  tracking_branch: main
tools:
  default: claude              # 対話で使うツール。複数可 [claude, copilot]
  agent: claude                # CLI が Wiki 生成などで起動するツール
  agent_model: sonnet
knowledge:
  agent_timeout_ms: 1800000
  agent_batch_size: 20
quality_gates:                 # 任意
  lint: npm run lint
```

内部既定（非公開ノブ）: `knowledge.inventory_shard_size`、`max_files_per_dir`、`evidence`、`sync.lease_ttl_minutes`、`remote_check_*`、`task.*`。`subagent_concurrency` は現在 agent に渡していないため削除。

## 5. 導入手順（ユーザーガイドの骨子）

**導入担当者（PKG につき1人）**

1. インストール（1回）: `install.ps1` / `install.sh` → `aidev --version`
2. `cd my-pkg && aidev init` — 質問は4つ: 使うツール / 生成対象 include（推測値を確認）/ 秘密パス / hosting の確認。終わると `aidev.yaml`、policy 候補、生成物、`.git/info/exclude` が揃う
3. 表示された候補を確認して `aidev permission configure --approve`
4. `aidev knowledge build --agent`（時間がかかる旨と進捗を表示。途中で止まっても同じコマンドで続き）
5. `git add aidev.yaml .aidev && git commit` → PR → マージ

**メンバー（全員）**

1. インストール（1回）
2. `git clone …` → `cd my-pkg` → `aidev init`（質問なし。ツールだけ未設定なら聞く）
3. `claude`（または選んだツール）

各手順の直後に `aidev status` の期待出力を載せ、「結果がこれと違うときは → トラブルシューティング §」を対応させる。

## 7. 決定事項（2026-09-21 ユーザー回答）

- **A. Wiki の置き場所**: PKG リポジトリに commit（`.aidev/knowledge/`）。
- **B. 生成物の扱い**: `.claude/`、`CLAUDE.md`、`.mcp.json` などのツール設定も **PKG 固有の設定値として PKG リポジトリに commit** する（使うツールが PKG ごとに違うため）。したがって §2 の `.aidev/overrides/` と `.git/info/exclude` は採用しない。kit の改善は `aidev update` が 3-way で適用し、差分を通常の commit / PR で取り込む。`.aidev/materialized.json` に適用した kit commit とファイル hash を記録し（commit）、`aidev check` が手編集をドリフトとして検出する。
- **C. 移行**: 運用中の wrapper リポジトリはないため、0.1 形式からの移行コマンドは作らない。
- **追加要望（tmp2.md 10 行目）**: 開発規約を knowledge 層から生成するエージェント、ユニット / IT テスト生成エージェントは S3 以降の候補として roadmap に置く。

改訂後の PKG 側配置:

```
my-pkg/
├─ aidev.yaml                  PKG 固有設定（commit）
├─ .claude/  CLAUDE.md  .mcp.json   選んだツールの設定（commit。aidev update が更新差分を作る）
├─ .aidev/
│   ├─ policy.yaml             承認済み権限（commit）
│   ├─ materialized.json       適用済み kit commit と hash（commit）
│   ├─ knowledge/              LLM Wiki（commit）
│   ├─ workflows/              PKG 固有 workflow（commit、任意）
│   └─ .gitignore              CLI が生成: cache/ leases/ tasks/ sync.lock を除外
└─ <PKG の通常ファイル>
```
