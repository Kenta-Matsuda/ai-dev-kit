[[environment-reference]]
[appendix]
== 環境変数リファレンス

[cols="2,2,4",options="header"]
|===
|変数 |利用箇所 |説明

|`AZURE_DEVOPS_PAT`
|Azure DevOps REST、sync PR、MCP
|既定のPAT変数名です。実際の名前は`azure_devops.auth_env`で変更できます。値をfileやCLI引数へ保存しません。

|`AIDEV_BIN_DIR`
|POSIX installer
|launcher配置directoryを上書きします。未設定時は`$HOME/.local/bin`です。

|`TF_BUILD`
|installerの旧pipeline互換
|`True`のとき、installerの一部checkout判定に互換例外があります。通常のlocal installで設定しません。

|`ANTHROPIC_MODEL`
|Claude Code
|Claude Code自身のmodel解決に使われ得ます。CLIが明示する`--agent-model`やproject/local settingsとの優先関係に注意します。

|`HTTPS_PROXY`
|remote、npm、Claude Code
|HTTPS proxy URLです。credentialを含む値をlogへ出さないでください。

|`https_proxy`
|remote、npm、Claude Code
|toolによって参照されるlowercase形式です。

|`AIDEV_DEBUG`
|CLI error reporting
|truthyな値で予期しないerrorのstack traceを表示します。通常運用では未設定にし、共有前に出力をredactします。

|`NO_COLOR`
|CLI UI
|設定時にANSI colorを抑制します。CI logやsnapshotに使用できます。

|`USER`
|audit metadata
|POSIX環境のoperator名として参照され得ます。認証identityの正本ではありません。

|`USERNAME`
|audit metadata
|Windows環境のoperator名として参照され得ます。認証identityの正本ではありません。

|`AIDEV_BOT_NAME`
|scheduled sync pipeline
|automation commitに使うbot表示名です。

|`AIDEV_BOT_EMAIL`
|scheduled sync pipeline
|automation commitに使うbot emailです。

|`ADO_MCP_DEFAULT_PROJECT`
|Azure DevOps MCP child process
|`aidev mcp azure-devops`がconfigから解決してchildへ渡します。通常は手動設定しません。

|`PERSONAL_ACCESS_TOKEN`
|Azure DevOps MCP child process
|launcherが設定済みPATをchildへ渡す内部変数です。通常は直接設定せず、`azure_devops.auth_env`を使用します。

|`PATH`
|installer、`claude`、`npx`、Git、Node.js
|必要なexecutable解決に使います。CLI専用launcherのdirectoryを含めます。

|`HOME`
|POSIX installer
|既定のCLI checkoutやlauncher pathの基準です。

|`LOCALAPPDATA`
|Windows installer
|既定のCLI sourceとlauncher pathの基準です。
|===

[[environment-pat-examples]]
=== PATの設定例

.PowerShell
[source,powershell]
----
$env:AZURE_DEVOPS_PAT = "<your-pat>"
----

.bash
[source,bash]
----
export AZURE_DEVOPS_PAT="<your-pat>"
----

custom名を使う場合:

[source,yaml]
----
azure_devops:
  auth_env: MY_TEAM_AZDO_PAT
----

[source,powershell]
----
$env:MY_TEAM_AZDO_PAT = "<your-pat>"
----

[[environment-security]]
=== 環境変数の安全な扱い

* secret managerまたはpipeline secret variableからprocessへ注入します。
* shell historyへ残る永続化commandを安易に使いません。
* process dump、debug log、child process継承を信頼境界として評価します。
* PATのscope、有効期限、owner、rotation手順を管理します。
* proxy URLにcredentialが含まれる場合は、diagnostic出力を共有する前にredactします。
* `env`、`Get-ChildItem Env:`など全環境を表示するcommandの出力をissueやPRへ貼り付けません。
