[[permissions]]
[appendix]
== 権限と安全性

{project-name} は、AI が PKG の中で **書いてよい場所** を 2 段で決めます。

* **policy**（`.aidev/policy.yaml`）— どの agent も対話セッションも常に書ける場所と、常に書けない場所。人間が CLI で置き、PR でレビューします。
* **workflow のステップの `writable`** — 承認済みの workflow を `aidev run workflow` で実行している間だけ、いま動いているステップの agent が追加で書ける場所。PKG のソースを AI が書けるのはこれだけです。

workflow のステップの agent は、書ける場所に加えて、**使えるツールと MCP server** も制限されます（xref:permissions-agent-tools[workflow のステップで使えるツール]）。

AI ツールの hook が毎回の書き込みを検査します。token はファイルに書かず、環境変数だけで渡します。

[[permissions-policy]]
=== policy の区分

[cols="1,2,3",options="header"]
|===
|区分 |既定 |意味

|`protected`
|`.claude/**`, `CLAUDE.md`, `.aidev/policy.yaml`, `.aidev/materialized.json` など ADK のファイル + `secrets_paths`
|常に書き込み禁止。policy から消しても CLI が付け直します。workflow のステップの `writable` にも書けません。

|`read_only`
|`**`（PKG 全体）
|agent も対話セッションも書けません。書けるのは、承認済み workflow の、いま動いているステップの `writable` の中だけです（xref:permissions-source[ソースを AI に書かせるには]）。

|`writable_during_sync`
|`.aidev/knowledge/**`
|Wiki が無い・読めないときに、`aidev sync wiki` が構造を書き直す間だけ書けます。

|`writable`
|`.aidev/knowledge/**`, `.aidev/workflows/**`, `.aidev/agents/**`, `.aidev/skills/**`, `.aidev/conventions/**`, `aidev.yaml`
|通常時に、どの agent も対話セッションも書けます。Wiki、workflow の定義、PKG 固有の agent と skill、開発規約、設定です。いずれも PR でレビューされ、`main` にあるものだけが効きます。
|===

判定は上から順です。

. リポジトリ外、`secrets_paths`、`protected` は常に拒否。
. Wiki が無い・読めない間は、`aidev sync wiki` が書く `.aidev/knowledge/**` を除き、すべて拒否。
. `writable` に当たれば許可。
. `aidev run workflow` が起動したセッションで、その workflow が承認済み（`origin/main` と同じ）で、パスがいま動いているステップの `writable` に当たれば許可。ただし、そのステップの `unchanged` にも当たるパスは拒否。判定は書き込みのたびに行うので、実行中に定義を変えると拒否に変わります。
. `read_only` に当たれば拒否。
. どれにも当たらなければ許可。

.書き込み 1 件ごとの判定順
[mermaid]
----
flowchart TD
  w["書き込み先のパス"] --> q1{"リポジトリ外 /<br/>secrets_paths / protected?"}
  q1 -- "はい" --> deny1["拒否"]
  q1 -- "いいえ" --> q2{"Wiki が無い・読めない?"}
  q2 -- "はい（.aidev/knowledge/** 以外）" --> deny2["拒否"]
  q2 -- "いいえ" --> q3{"writable に当たる?"}
  q3 -- "はい" --> allow1["許可"]
  q3 -- "いいえ" --> q4{"aidev run workflow のセッションで<br/>承認済み workflow の、いま動いている<br/>ステップの writable に当たる?"}
  q4 -- "はい" --> allow2["許可"]
  q4 -- "いいえ" --> q5{"read_only に当たる?"}
  q5 -- "はい" --> deny3["拒否"]
  q5 -- "いいえ" --> allow3["許可"]
----

[[permissions-hooks]]
=== hook の動作

配布される hook 設定（Claude Code は `.claude/settings.json`、GitHub Copilot CLI は `.github/hooks/aidev.json`、OpenAI Codex CLI は `.codex/hooks.json`、Kiro CLI は `.kiro/agents/aidev.json`）は 5 つの hook を登録します。実機で検証済みなのは Claude Code です。

[cols="1,1,3",options="header"]
|===
|イベント |コマンド |動作

|SessionStart
|`aidev hook session-start`
|Wiki の状態と進行中の publish をセッションのコンテキストに入れます。

|PreToolUse（Write / Edit / Bash など）
|`aidev hook guard-write`
|書き込み先を policy といま動いている workflow ステップの `writable` で判定し、拒否なら理由を返します。policy が読めないときも拒否します。workflow のステップの中では、その agent に許していないツールの呼び出しも拒否します。Claude Code では MCP ツールの呼び出しもここを通ります。

|PostToolUse（Write / Edit）
|`aidev hook quality-gate`
|PKG のファイルを編集した後、`quality_gates` のコマンドを実行し、失敗の出力を AI に返します。

|PostToolUse（Bash）
|`aidev hook after-bash`
|コミットで HEAD が変わり Wiki が遅れたら、構造を更新し、本文が必要なら knowledge-builder をサブエージェントで起動するようセッションに指示します（xref:knowledge-hook-flow[コミット後の処理]）。

|Stop
|`aidev hook session-stop`
|Wiki が HEAD より遅れたままなら 1 回だけ終了を拒否して同じ指示を出します。
|===

拒否されると、AI には次のような理由が返ります。

[source,text]
----
ai-dev-kit: "src/api/auth.ts" is read-only (**). this session was not started by "aidev run workflow"; PKG source is written only inside the writable of an approved workflow step. …
ai-dev-kit: "src/api/auth.ts" is read-only (**). workflow write-tests is approved but the writable of step write (tests/**) does not cover this path. …
ai-dev-kit: mcp__ado__update_work_item is not among the MCP servers of agent ticket-reader (none); the agent's frontmatter grants them
ai-dev-kit: ".claude/settings.json" is protected (.claude/**). …
ai-dev-kit: Wiki consistency error (…) All writes are blocked; run "aidev sync wiki" …
----

hook を外す編集は `aidev check` が終了コード 2 で検出し、CI がマージを止めます（検査するのは `.claude/settings.json` です）。

[[permissions-source]]
=== AI にソースを書かせる方法

既定では PKG のソースは `read_only` で、対話中の AI も、それが呼ぶサブエージェントも書けません。AI にソースを書かせたいときは、**その仕事を workflow として定義し、各ステップの `writable` にそのステップが書いてよい範囲を書き、PR でレビューして `main` に入れます**（xref:workflows[AI への作業委譲]）。

[source,yaml]
----
steps:
  - id: survey
    agent: test-investigator
    writable: []                   # 調べるだけ。何も書けない
    prompt: …
  - id: write
    agent: test-writer
    writable: [src/**, tests/**]   # このステップだけが書ける
    prompt: …
----

この範囲は `aidev run workflow <name>` が起動した agent にだけ効きます。`aidev` が起動時に workflow 名とステップの `id` を子プロセスの環境変数 `AIDEV_WORKFLOW`・`AIDEV_WORKFLOW_STEP` に入れ、hook がそれを見て「その workflow が今も `origin/main` と同じか」「パスがそのステップの範囲内か」を判定します。人が `claude` で対話中に同じ agent を呼んでも、この範囲は効きません。

すべての agent と対話セッションにいつでも開きたい場合だけ、policy の `writable` に足します。`protected` と `secrets_paths` はどちらの方法でも書けません。policy の変更は PR でレビューし、必要な期間だけ広げることを勧めます。

[[permissions-agent-tools]]
=== workflow のステップで使えるツール

workflow のステップの agent が使えるツールは、その agent の frontmatter の `tools`（組み込みツール）と `mcp`（MCP server）で決まります（xref:workflows-agents-skills[agent と skill]）。workflow 側で広げることはできません。権限の違う仕事は、別の agent にします。

Claude Code では、2 段で守ります。

. `aidev run workflow` は、agent の `tools` にあるツールと、`mcp` にある server だけを渡して Claude Code を起動します。`mcp` を書かない agent には MCP server を 1 つも渡しません。PKG の `.mcp.json` や個人の設定にある他の server は読み込まれません。
. `guard-write` hook は、workflow のステップの中で、その agent に許していないツールや MCP ツールの呼び出しを拒否します。workflow の外の MCP の呼び出しには何も答えず、許可するかは Claude Code 自身の設定に任せます。

`tools` や `mcp` を書いた agent は、Claude Code でしか起動しません。GitHub Copilot CLI、OpenAI Codex CLI、Kiro CLI は渡すツールを絞れないため、workflow は何も始めずに止まります。

`Bash` を渡した agent は、MCP を通さずに外部のシステムへ出られます。外部システムに触る agent には `Bash` を渡さないでください。テストの実行は `until` で ADK が行います。

[[permissions-commands]]
=== policy の設置と変更

policy は AI が作れません。 Engineering Manager が CLI で置きます。

[%autowidth.stretch,options="header"]
|===
|コマンド |動作

|`aidev create policy --approve`
|候補 `.aidev/policy.candidate.yaml` を `.aidev/policy.yaml` として置きます。`aidev init` で `N` と答えた後に使います。

|`aidev create policy` → `aidev create policy --approve`
|`secrets_paths` を変えたときなどに候補を作り直して置きます。保護を弱める変更には `--force` も必要です。候補は `aidev.yaml` から作り直されるので、チームが policy に手で足した `writable` は消えます。置いた後にもう一度足してコミットしてください。

|`aidev check` / `aidev doctor --package <name>`
|有効な policy の要約（protected の数、置かれているか）を表示します。全文は `.aidev/policy.yaml` を読みます。
|===

[[permissions-secrets]]
=== 秘密情報

* `secrets_paths` のファイルは、AI が読まず、書かず、Wiki からも隠されます。
* PAT は `hosting.auth_env`（既定 `AZURE_DEVOPS_PAT`）の環境変数だけで渡します。`aidev.yaml` に書くと起動を拒否します。
* `aidev doctor` と `aidev init` は token の有無だけを報告し、値は読みません。
* workflow の実行記録（`.aidev/workflows/*/runs/`）にはコマンドの出力が入るため、gitignore 済みでコミットされません。

=== 禁止事項

* `.claude/**`、`CLAUDE.md` の ADK 由来の部分を黙って書き換えない（チームの変更は PR でレビューし、ADK 全体の改善は ADK への PR にする）
* `.aidev/policy.yaml` は人間だけが編集し、変更は PR でレビューする（AI には編集させない）
* workflow のステップの `writable` に `**` や設定・CI のパスを書かない。そのステップの仕事に必要な範囲だけにする
* agent の `tools` と `mcp` は、その仕事に必要な分だけにする
* AI が「拒否された」と報告したら、回避策を探さず理由を読む
* token をコミット・ログ・PR 本文に含めない
