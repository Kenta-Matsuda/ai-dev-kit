== Files in the package

The files {project-name} places in a package clone, and whether they are committed.

=== Committed

[cols="2,3,2",options="header"]
|===
|Path |Contents |Written by

|`aidev.yaml`
|Package settings
|`aidev init`, humans

|`.claude/agents/*.md`, `.claude/skills/*/SKILL.md`, `.claude/settings.json`
|Distributed agents, skills and hooks
|`aidev init` / `aidev sync tools`. The team may edit them; they are merged with new templates

|`CLAUDE.md`
|Shared instructions for Claude
|Same

|`.mcp.json`
|MCP server registration. The agent of a workflow step can use only the servers here that its frontmatter lists in `mcp`
|The package (the ADK does not ship it; edited by people)

|`.github/copilot-instructions.md`, `.github/agents/<agent>.agent.md`, `.github/skills/*/**`, `.github/hooks/aidev.json`, `AGENTS.md`, `.codex/hooks.json`, `.kiro/steering/ai-dev-kit.md`, `.kiro/agents/<agent>.json`, `.kiro/agents/aidev.json`
|Only when `tools.default` lists `copilot` / `codex` / `kiro`: the instructions, agents, skills and hooks for each tool
|Same. Removing the tool deletes them at the next `aidev sync tools` (kept if edited)

|`.aidev/policy.yaml`
|The approved write-permission policy
|`aidev create policy --approve`, `aidev init`. `writable` additions are edited in directly by humans

|`.aidev/materialized.json`
|The tool-configuration record: the ADK commit applied, per file the template hash and the hash at apply time, and unresolved conflicts. `aidev sync tools` merges against it and `aidev check` judges by it
|`aidev init` / `aidev sync tools`

|`.aidev/knowledge/index.md`, `overview.md`, pages
|The LLM Wiki
|The knowledge-builder agent

|`.aidev/knowledge/manifest.json`, `inventory/*.json`
|Wiki structure and progress
|The CLI only

|`.aidev/workflows/<name>/workflow.yaml`
|A workflow definition. It runs only when it is identical to the one on `origin/main`
|`aidev create workflow`, humans. `aidev submit workflow` turns it into a PR

|`.aidev/agents/<name>.md`, `.aidev/skills/<name>/SKILL.md`
|Agents and skills local to this PKG. Agents are referenced by name from workflow steps, and skills from an agent's frontmatter `skills`; they take precedence over a bundled one with the same name. An agent's frontmatter also decides the skills, tools and MCP servers that agent can use
|`aidev create workflow --describe` (the workflow-creator), the interactive AI, humans. They go into the PR together with the workflow

|`.aidev/conventions/`
|The development conventions of this package (`index.md`, `coding.md`, `testing.md`, `review.md`)
|Generated by the package's workflow (an agent that writes conventions), reviewed and committed by humans. Only humans write below `## チーム決定`

|`.aidev/.gitignore`
|Excludes the files listed under "Not committed"
|`aidev init` / `aidev sync tools`
|===

`.claude/settings.local.json` is personal and outside the ADK's management.

=== Not committed

Excluded by `.aidev/.gitignore`. If deleted, the next command recreates them.

[%autowidth.stretch,options="header"]
|===
|Path |Contents

|`.aidev/cache/`
|Remote-check cache, the HEAD the hook last saw (`last-head.json`) and the Stop hook counter (`wiki-stop.json`), the temporary worktree of a publish to the tracking branch (`wiki-worktree/`), task files handed to agents

|`.aidev/sync.lock`
|The lease of a publish to the tracking branch

|`.aidev/knowledge/.cache/`
|`plan.json` (the batches the hook hands to the session) and the agent's completion reports

|`.aidev/workflows/*/runs/`
|Workflow run records (`run.json`, `log.txt`, `reports/`, `logs/`, `diffs/`, `notes/`, `pull-request.md`). They contain command output, so they are never committed (xref:workflows-run[Running a workflow])
|===

Temporary files: `.aidev/policy.candidate.yaml` (removed on approval) and `.aidev/ejected.json` (written by `aidev uninstall --package`, removed by `aidev init`).

=== On this machine (AIDEV_HOME)

Holds `registry.json` (the registered packages) and `cache/update-check.json` (the result of the ADK update check). The ADK itself is not in `AIDEV_HOME`; it is the clone you ran the installer from. `aidev uninstall` removes both. On the machine of someone developing {project-name} itself there is also a `Developer.json` (irrelevant to users).
