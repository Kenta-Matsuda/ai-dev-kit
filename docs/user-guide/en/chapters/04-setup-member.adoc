[[setup-member]]
== Member steps

Start using Claude Code in a package that already has the kit. No questions, three commands.

=== What you need

* xref:install[Install aidev on your machine] is done
* The package owner's PR has been merged into `main`
* For an Azure DevOps package, `AZURE_DEVOPS_PAT` is set

=== Steps

. Clone the package, or pull the latest.
+
[source,bash]
----
git clone <pkg-url>
cd <pkg>
# if you already have a clone
git pull
----

. Run `aidev init`. The configuration already exists, so it asks nothing.
+
[source,bash]
----
aidev init
----
+
[source,text]
----
✓ aidev.yaml is present (set up by your team); nothing to ask.
✓ tool configuration is current (18 file(s) for claude)
✓ AZURE_DEVOPS_PAT is set (value not read)
✓ .aidev/policy.yaml is present
✓ LLM Wiki is present (.aidev/knowledge/)

ℹ ready. Run "aidev check" any time, then start your AI tool (e.g. "claude") in this directory.
----
+
* `⚠ AZURE_DEVOPS_PAT is not set` → xref:install[set the environment variable] and open a new terminal.
* `newer templates available` on the `tool config` line → the team has not taken in the newer kit templates yet. The package owner runs `aidev sync tools` and opens a PR (xref:daily-apply[aidev sync tools]).
* `the LLM Wiki is not in this clone yet …` is shown → the package owner's PR is not merged yet. Run `git pull` after the merge. Do not build it yourself.

. Check the state.
+
[source,bash]
----
aidev check
----
+
You are ready when the second line is `✅ the Wiki describes the code this work is based on.` For `⚠️` and `❌`, see xref:daily-check[Reading aidev check].

. Start Claude Code at the package root.
+
[source,bash]
----
claude
----
+
At the start of the session, one line about the Wiki state is added to the context. Claude begins its research from `.aidev/knowledge/index.md`.
