[[overview]]
== What {project-name} is

{project-name} is a kit that lets your whole team use AI coding tools (Claude Code and others) with **the same setup, the same permissions and the same background knowledge**. You adopt and maintain it with the `aidev` command.

[[overview-change]]
=== What adoption changes

You move from everyone using AI however they like, to **everyone using AI inside limits the team agreed on**.

[%autowidth.stretch,options="header"]
|===
|　 |Before |After

|AI tool setup
|Different for each person
|Shared by the team. It lives in the repository and everyone gets the same thing.

|What the AI knows going in
|You explain it from scratch every time
|A description of the code lives in the repository, and the AI reads it first.

|What the AI may rewrite
|Decided on the spot
|Only the range the team agreed on. Writes outside it are stopped automatically.

|Larger jobs handed to the AI
|Described verbally, in the moment
|The content and the range are decided and reviewed up front. Only approved jobs can run.
|===

One thing does not change: **a human decides what gets taken in.** Every change the AI makes goes through human review. {project-name} never takes one in on its own.

[[overview-roles]]
=== Roles and responsibilities

Responsibilities differ substantially by role. Determine which one applies to you first.

[%autowidth.stretch,options="header"]
|===
|Role |How many |Responsibilities

|**Engineering Manager**
|One per repository
|**You decide.** You decide what the AI may do, prepare the shared setup and the description of the code, and hand them to the team. You define the jobs handed to the AI. You review what comes back and take it in.

|**Developer**
|Everyone else
|**You use it.** You take the shared setup into your own environment and develop with the AI day to day. You have the AI run already-defined jobs, and send the results for review. **You decide nothing.**
|===


[[overview-flow]]
=== Overall flow

.What the Engineering Manager and the Developers each do
[mermaid]
----
sequenceDiagram
  participant L as Engineering Manager
  participant M as Developer

  rect rgb(232, 243, 250)
    Note over L,M: 1. Preparation (once, at the start)
    L->>L: prepare the shared setup
    L->>L: prepare the description of the code for the AI
    L->>M: review it, then hand it to the team
    M->>M: take it in and set up their environment
  end

  rect rgb(233, 247, 240)
    Note over L,M: 2. Day-to-day development
    M->>M: develop with the AI and commit
    M->>L: send the change for review
    L->>L: check it and take it in
  end

  rect rgb(242, 237, 255)
    Note over L,M: 3. Handing work to the AI
    L->>L: decide the content and the range of a job
    L->>L: review it, making it "approved"
    M->>M: have the AI run an approved job
    M->>L: send the result for review
    L->>L: check it and take it in
  end
----

3 runs alongside 2. You do not have to finish one before the other.

[[overview-terms]]
=== Terminology

These terms recur throughout the guide. Others are explained where they first appear.

[%autowidth.stretch,options="header"]
|===
|Term |Meaning

|PKG
|The repository you adopt {project-name} in — the repository you develop in day to day.

|kit
|{project-name} itself. It is what the `aidev` command runs from, and each machine keeps one.

|LLM Wiki
|The description of the code, written for the AI. It is generated from the PKG's code and shared with the team through the repository.

|workflow
|The definition of a job handed to the AI: what to do, how far it may rewrite, and how much it may spend.
|===
