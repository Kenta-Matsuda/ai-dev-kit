[[cli-submit]]
== aidev submit

Submits a workflow as a branch and a pull request. Merging the PR is the approval.

=== Synopsis

[source,text]
----
aidev submit workflow <name> [--no-push] [--dry-run] [--json]
----

=== Description

Validates the definition, commits `workflow.yaml` and the PKG-local agents (`.aidev/agents/`) and skills (`.aidev/skills/`) it references on the branch `aidev/workflow-<name>` as `aidev: workflow <name>`, pushes it and opens a PR (Azure DevOps; with `generic` hosting it pushes, and you open the PR by hand). The PR body states the objective, what each step does (order, `description`, agent, where it may write, that agent's skills, tools, MCP servers and the subagents it may start, the `for_each` targets and how many run at a time, the parallel group it runs with, `until`), the agent and skill files (new or changed), the limits, and that merging approves this workflow. When the definition has `inputs`, `provide` or `never_commit`, the body also has the sections **Inputs (--input name=value)** (name, description, required or default, `pattern`, whether it is a path in the repository, whether it reaches a command), **Provided from the checkout** and **Never committed** (xref:workflows-inputs[Taking values that change per run], xref:workflows-provide[Providing files the worktree lacks], xref:workflows-never-commit[What is never committed]).

When it submits a change to an approved workflow, the body also has:

* **What changed against the approved workflow**: the steps added, removed or reordered against the `origin/main` version, the fields that changed in each step (`prompt`, `writable`, `until` and so on), and top-level changes such as `limits`, `inputs`, `provide` and `never_commit`.
* **Estimate**: the cost estimate (optimistic to pessimistic) before and after.
* **Why this change**: for a change made with `aidev modify` (that started from the approved version), what was asked, why the `--from-run` run stopped and its failure output as recorded, the cause the agent found (`CAUSE:`) and its account. It also says when the definition was edited by hand after `modify`.

The whole text is also written to `.aidev/cache/submit/<name>.md` (paste it when you open the PR by hand with `generic` hosting). When it is over the Azure DevOps limit (4000 characters), the agent's account is left out first; if it is still over, the middle is cut at a line break. The cut names the file with the whole text, and **Files under review** and the statement that merging approves the workflow are kept. When a shortened body is sent, the command says so.

If it is already identical to `origin/main`, it prints `already matches origin/main; nothing to submit.` and does nothing.

=== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--no-push`
|Commit on the local branch only; do not push or open a PR

|`--dry-run`
|Show the branch, the destination and the files; create no branch, commit, push or PR

|`--json`
|Machine-readable output
|===

=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Opened a PR (or already approved). `--dry-run`

|1
|An object other than `workflow`, or no name. Invalid definition, or an agent or skill that exists neither in the PKG nor in the ADK. A referenced file is missing locally. Creating the branch, committing or pushing failed
|===

=== Examples

[source,bash]
----
git diff -- .aidev/workflows/write-tests/ .aidev/agents/ .aidev/skills/
aidev submit workflow write-tests
----

[source,text]
----
aidev submit workflow write-tests
✓ on branch aidev/workflow-write-tests
✓ committed 3f2a9c1b7d0e (1 file(s))
✓ pushed aidev/workflow-write-tests
✓ pull request !124 created (aidev/workflow-write-tests → main)
    Once it is merged, anyone with the branch fetched can run: aidev run workflow write-tests
----
