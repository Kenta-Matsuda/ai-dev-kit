[[cli-workflow]]
== aidev workflow

Runs an approved script within fixed limits.

=== Synopsis

[source,text]
----
aidev workflow new <name> [--force] [--dry-run] [--json]
aidev workflow approve <name> [--force] [--dry-run] [--json]
aidev workflow run <name> [--max-iterations <n>] [--max-minutes <n>] [--resume] [--dry-run] [--json]
aidev workflow list [--json]
----

=== Description

Runs `workflow.yaml` (limits, budget, allowed commands) and `steps.js` (the work) from `.aidev/workflows/<name>/`, exactly as a human approved them. `approve` records the hash of both files in `approval.json`; `run` only executes while the hashes still match.

`steps.js` exports `module.exports = async function steps(ctx)`. `ctx.run(cmd, args)` can only run commands listed under `commands` in `workflow.yaml`. Returning `{ done: true }` ends the run. The limits are 10 iterations, 60 minutes and 3 identical failures; you can lower them but not raise them. `cost.max_tokens` or `cost.max_usd` is required.

`ctx.agent(prompt, { name?, tool?, model?, timeoutMs? })` starts a bundled agent through an AI tool and returns `{ ok, result, reason, costUsd, durationMs, tool, agent, model }` (it does not throw on failure). The default agent, tool and model come from the `agent:` block of `workflow.yaml` (`name` required; `tool`, `model`, `timeout_ms` optional); anything left out follows `tools.agents.<name>` and `tools.agent` / `tools.agent_model` in `aidev.yaml`. Only tools listed in `tools.default` can be used. One run is cut off at the shorter of `timeout_ms` and the workflow's remaining time, and once the reported cost reaches `cost.max_usd` the next start is refused and the workflow stops.

It does not open pull requests.

=== Subcommands

[%autowidth.stretch,options="header"]
|===
|Subcommand |What it does

|`new <name>`
|Writes a scaffold. Needs `--force` if it already exists.

|`approve <name>`
|Validates the definition and records the hashes.

|`run <name>`
|Runs if the approval is valid. `--resume` continues an unfinished run.

|`list`
|Shows each workflow's approval state (`approved` / `not approved` / `CHANGED since approval`).
|===

=== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--json`
|Machine-readable output

|`--force`
|`new`: overwrite an existing workflow. `approve`: record again even if unchanged

|`--dry-run`
|`run`: show whether the approval is valid and the limits; do not run

|`--max-iterations <n>`
|`run`: lower the iteration limit further

|`--max-minutes <n>`
|`run`: lower the time limit further

|`--resume`
|`run`: continue from the last unfinished run
|===

=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Success

|1
|Bad name or definition, not approved, changed since approval, or stopped at a limit
|===

=== Examples

[source,bash]
----
aidev workflow new nightly-tests
# edit steps.js and workflow.yaml, review with git diff
aidev workflow approve nightly-tests
aidev workflow run nightly-tests --dry-run
aidev workflow run nightly-tests
----
