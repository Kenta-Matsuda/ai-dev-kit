[[cli-uninstall]]
== aidev uninstall

Removes `aidev` from this machine. With `<package>` it takes that PKG out of kit management instead (the former eject). `--all` does that for every registered PKG and then removes `aidev` from the machine.

=== Synopsis

[source,text]
----
aidev uninstall --dry-run
aidev uninstall --yes [--json]
aidev uninstall <package> --yes [--keep-assets] [--force] [--json]
aidev uninstall --all --yes [--json]
----

=== Description

==== No argument — remove from this machine

Removes what the installer placed: ① the launcher (Windows: `aidev.cmd` and `aidev.ps1`, POSIX: `aidev`; only the ones the installer generated), ② on Windows, the launcher directory that the installer added to your user PATH, ③ `registry.json` and `cache/` in `AIDEV_HOME`.

It shows what it keeps, with the command to remove each item:

* The kit clone. `aidev` runs from it, so run the `Remove-Item` / `rm -rf` shown afterwards, by hand.
* The files the kit placed in each registered package. They are committed and shared with the team, so removing them is a team change that goes through a PR. Either run `aidev uninstall <package> --yes` first (keeps the Wiki and `aidev.yaml`), or run the `git rm` shown in that package clone (removes the Wiki too).

There is no interactive confirmation. Without `--yes` it lists what would happen and stops with exit code 1. With nothing left to remove it still exits 0.

To install again, run the installer from a kit clone (xref:install[Install aidev on your machine]).

==== `<package>` — take a PKG out of kit management (the former eject)

`<package>` is the name of a PKG registered on this machine (listed by `aidev doctor`) or a path to one (`.` inside the PKG).

In order: ① removes the four `aidev hook` entries from `.claude/settings.json`, ② deletes the management files (`.aidev/policy.yaml`, `.aidev/materialized.json`, `.aidev/cache/` and so on), ③ unless `--keep-assets` is given, deletes the tool configuration files the kit placed (`.claude/**`, `CLAUDE.md`, and those of the other tools), ④ writes `.aidev/ejected.json` and unregisters the clone on this machine.

Kept: your package files, `.aidev/knowledge/` (the Wiki), `aidev.yaml`, `.aidev/workflows/`.

After ejecting, `aidev check` returns 0. Remove `aidev check` from CI. `aidev init` re-adopts the package.

There is no interactive confirmation. Without `--yes` it lists what would happen and stops with exit code 1. With a publish to the tracking branch in progress (a valid lease) it refuses unless `--force` is given.

==== `--all` — every PKG, then this machine

Does what `<package>` does for each registered PKG in turn, then removes `aidev` from the machine. If one PKG stops it, it stops there. Needs `--yes`.

=== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--yes`
|Run; you have confirmed

|`--dry-run`
|Show what would be removed and the commands for what is kept; write nothing

|`--json`
|Machine-readable output

|`--all`
|Take the kit out of every registered PKG, then remove the CLI from this machine

|`--force`
|`<package>`: run even if already ejected, a publish is in progress, or no trace of kit management is found

|`--keep-assets`
|`<package>`: keep the tool configuration files the kit placed (`.claude/**`, `CLAUDE.md`, …)
|===

=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Removed. Nothing left to remove. `--dry-run`

|1
|`--yes` missing. `<package>` not found. `<package>` shows no trace of kit management, or a publish is in progress (without `--force`). `<package>` and `--all` given together
|===

=== Examples

[source,bash]
----
aidev uninstall demo-pkg --dry-run          # preview taking the kit out of that PKG
aidev uninstall demo-pkg --yes
git -C C:\work\demo-pkg add -A && git -C C:\work\demo-pkg commit -m "chore: eject from ai-dev-kit"

aidev uninstall --dry-run
aidev uninstall --yes
rm -rf ~/ai-dev-kit            # the command shown for the kit clone
----
