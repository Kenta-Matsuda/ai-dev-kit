[[cli-hook]]
== aidev hook

Internal command called by Claude Code hooks. Not meant to be run by hand.

=== Synopsis

[source,text]
----
aidev hook session-start
aidev hook guard-write [--input <file>]
aidev hook quality-gate [--input <file>]
aidev hook session-stop
----

=== Description

Claude Code starts it from the distributed `.claude/settings.json`. It reads the hook input (JSON) on stdin and writes its decision (JSON) to stdout. To try it out, pass an input file with `--input <file>`.

[cols="1,4",options="header"]
|===
|Subcommand |What it does

|`session-start`
|Returns the Wiki state and any work in progress as session context

|`guard-write`
|Checks the target path against the policy and returns `allow` / `deny` with a reason. Returns `deny` when it cannot decide

|`quality-gate`
|Runs `quality_gates` after a package file was edited and returns the output of failures

|`session-stop`
|Records the state at the end of the session under `.aidev/cache/`
|===

=== Exit codes

0 whenever a decision was returned (also for `deny`; the decision is inside the JSON). 1 for an unknown hook name.

=== Example

Check a `guard-write` decision by hand:

[source,bash]
----
cat > /tmp/hook.json <<'EOF'
{"tool_name":"Write","tool_input":{"file_path":"src/api/auth.ts"}}
EOF
aidev hook guard-write --input /tmp/hook.json
----

[source,json]
----
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "ai-dev-kit: \"src/api/auth.ts\" is read-only (**): no work lease. …"
  }
}
----
