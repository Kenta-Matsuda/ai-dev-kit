= Command Reference

[[cli-reference]]
== How to read the command reference

Every `aidev` command has its own page. Each page follows the same order: **Synopsis → Description → Options → Exit codes → Examples**. The options are the same as `aidev <command> --help`.

[[cli-syntax]]
=== Common syntax

[source,text]
----
aidev <verb> [<object>] [<name>] [options]
----

A command starts with a verb, followed by an object (`workflow`, `policy`, `kit`, `wiki`, and so on) and a name.

* Options are `--name` or `--name <value>`. `--name=value` also works.
* An option the command does not accept is an error (`unknown option: --bogus`, exit code 1).
* `run`, `create`, `submit`, `list`, `remove`, `update`, `configure`, `show`, `evolve`, `hook` and `mcp` require an object.
* Commands for a PKG run inside the PKG clone (a subdirectory is fine; `init` needs the root). To run one on another PKG, name it with `--package <name|path>` (see xref:cli-common-options[Common options]).

[[cli-common-options]]
=== Common options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--json`
|Print only machine-readable JSON (supported commands only).

|`--dry-run`
|Show what would change and write nothing (supported commands only).

|`--package <name\|path>`, `-p <name\|path>`
|Run on this PKG instead of the current clone. `<name>` is a name shown by xref:cli-list[`aidev list packages`]; `<path>` is the path of a PKG clone. Accepted by the commands that act on a PKG (`init`, `check`, `doctor`, `create`, `remove`, `list`, `submit`, `run`, `sync`, `uninstall`). An error on `update`.

|`--help`, `-h`
|Show the command list, or the options of one command.

|`--version`, `-V`
|Print the kit version.
|===

Every command except `hook` and `update` (including `--help` and `--version`) tells you when a newer kit exists. It checks at most once an hour. In a terminal it also asks whether to update first (not with `--json` or `uninstall`). After an update, the command is run again with the new CLI. The notice goes to standard error, so `--json` output is unchanged. Set `AIDEV_NO_UPDATE_CHECK=1` to turn this off.

[[cli-exit-codes]]
=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Meaning

|0
|Success

|1
|General error (bad option, missing configuration, invalid workflow, network failure, agent failure, and so on)

|2
|drift: the tool-configuration record (`.aidev/materialized.json`) is missing, conflict markers from `aidev sync tools` are unresolved, or the kit's hooks are gone from `.claude/settings.json`

|3
|permission: the policy is missing or broken, or approval was refused

|4
|wiki: the Wiki is missing or broken, or a publish to the tracking branch stopped halfway
|===

[[cli-commands]]
=== Commands

.Develop (inside a PKG clone)
[%autowidth.stretch,options="header"]
|===
|Command |Summary

|xref:cli-create[`aidev create workflow\|agent\|skill <name>`, `aidev create policy`]
|Create a workflow, agent or skill (writes the files only; runs nothing). `policy` drafts the write-permission policy and places it with `--approve`

|xref:cli-list[`aidev list workflows\|agents\|skills\|packages`]
|List workflows (with approval state), agents and skills. `packages` lists the PKGs set up with {project-name} on this machine

|xref:cli-remove[`aidev remove workflow\|agent\|skill <name>`]
|Remove a workflow, agent or skill (a referenced agent or skill is refused)

|xref:cli-run[`aidev run workflow <name>`]
|Run an approved workflow (development starts here)

|xref:cli-submit[`aidev submit workflow <name>`]
|Submit a workflow as a branch and a pull request (merge = approval)
|===

.Maintain (inside a PKG clone)
[%autowidth.stretch,options="header"]
|===
|Command |Summary

|xref:cli-check[`aidev check`]
|Show the state of this PKG on one screen and return the consistency check as an exit code (for CI)

|xref:cli-init[`aidev init`]
|Set up {project-name} in this PKG (interactive the first time, no questions afterwards)

|xref:cli-sync[`aidev sync tools\|wiki`]
|`tools`: take the kit's latest templates into this PKG (edited files are merged). `wiki`: bring the LLM Wiki to HEAD and commit it as its own commit
|===

.For this machine
[%autowidth.stretch,options="header"]
|===
|Command |Summary

|xref:cli-doctor[`aidev doctor`]
|Diagnose the environment of this machine (Node.js, git, kit, AI tools). With `--package`, also that PKG's state

|xref:cli-uninstall[`aidev uninstall [--all]`]
|Remove `aidev` from this machine. With `--package`, takes that PKG out of kit management (the former eject)

|xref:cli-update[`aidev update`]
|Update the kit itself (CLI and templates). `aidev sync tools` takes it into a PKG
|===


.Called by tools
[%autowidth.stretch,options="header"]
|===
|Command |Summary

|xref:cli-hook[`aidev hook <…>`]
|Internal command called by the AI tool's hooks (not listed by `aidev --help`)

|===
