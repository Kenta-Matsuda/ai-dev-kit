= Command Reference

[[cli-reference]]
== How to read the command reference

Every `aidev` command has its own page. Each page follows the same order: **Synopsis → Description → Options → Exit codes → Examples**. The options are the same as `aidev <command> --help`.

[[cli-syntax]]
=== Common syntax

[source,text]
----
aidev <command> [subcommand] [options] [arguments]
----

* Options are `--name` or `--name <value>`. `--name=value` also works.
* An option the command does not accept is an error (`unknown option: --bogus`, exit code 1).
* `knowledge`, `agent`, `permission`, `task`, `workflow`, `hook` and `mcp` require a subcommand.
* Commands for a PKG run inside the PKG clone (a subdirectory is fine; `init` needs the root).

[[cli-common-options]]
=== Common options

[cols="1,3",options="header"]
|===
|Option |Description

|`--json`
|Print only machine-readable JSON (supported commands only).

|`--dry-run`
|Show what would change and write nothing (supported commands only).

|`--help`, `-h`
|Show the command list, or the options of one command.

|`--version`, `-V`
|Print the kit version.
|===

Every command except `hook`, `mcp` and `update` checks once a day whether a newer kit exists and, if so, asks whether to update first. Set `AIDEV_NO_UPDATE_CHECK=1` to turn this off.

[[cli-exit-codes]]
=== Exit codes

[cols="1,4",options="header"]
|===
|Code |Meaning

|0
|Success

|1
|General error (bad option, missing configuration, network failure, agent failure, and so on)

|2
|drift: the distributed files (`.claude/**`, `CLAUDE.md`, `.mcp.json`, the generated configuration of other tools) differ from what was recorded

|3
|permission: the policy is missing or broken, or approval was refused

|4
|wiki: the Wiki is missing or broken, or the previous sync stopped halfway
|===

[[cli-commands]]
=== Commands

.Inside a PKG clone
[cols="2,4",options="header"]
|===
|Command |Summary

|xref:cli-init[`aidev init`]
|Set up {project-name} in this PKG (interactive the first time, no questions afterwards)

|xref:cli-status[`aidev status`]
|Show the state of this PKG on one screen

|xref:cli-check[`aidev check`]
|Return the consistency check as an exit code (for CI)

|xref:cli-knowledge[`aidev knowledge <build\|status>`]
|Generate the LLM Wiki, or show its state

|xref:cli-sync[`aidev sync`]
|Follow `main`, update the Wiki and open a PR

|xref:cli-agent[`aidev agent <list\|show\|run>`]
|Start a bundled agent with the configured AI tool

|xref:cli-permission[`aidev permission <configure\|reconfigure\|show>`]
|Place or show the write-permission policy

|xref:cli-task[`aidev task <list\|show\|resume\|advance\|abandon>`]
|Handle the state of issue-to-pr tasks

|xref:cli-workflow[`aidev workflow <new\|approve\|run\|list>`]
|Create and run approved scripts
|===

.For this machine
[cols="2,4",options="header"]
|===
|Command |Summary

|xref:cli-update[`aidev update`]
|Update the kit and re-apply the distributed files to the PKG

|xref:cli-doctor[`aidev doctor`]
|Diagnose the environment of this machine and the PKG

|xref:cli-eject[`aidev eject`]
|Take the PKG out of kit management
|===

|===
