[[cli-agent]]
== aidev agent

Starts a bundled agent once, with the AI tool this PKG is set up for.

=== Synopsis

[source,text]
----
aidev agent list [--json]
aidev agent show <name> [--tool <tool>] [--model <model>] [--json]
aidev agent run <name> [<task>...] [--tool <tool>] [--model <model>] [--timeout <ms>] [--prompt-file <path>] [--dry-run] [--json]
----

=== Description

Hands one task to a bundled agent (`agents-creator`, `convention-builder`, `issue-to-pr`, `knowledge-builder`, `permission-setting`, `test-writer`, `workflow-creator`) through the same launcher that `aidev knowledge update` uses. The agent runs inside the PKG clone with the same configuration files, hooks and policy as an interactive session.

The tool and model are chosen in this order:

. `--tool` / `--model`
. `tools.agents.<name>` in `aidev.yaml`
. `tools.agent` / `tools.agent_model` in `aidev.yaml`

Only tools listed in `tools.default` can be used. Naming another tool stops with a hint to add it to `aidev.yaml` and place that tool's configuration files (`aidev apply`).

An agent started by `aidev agent run` gets the grant written under `agents.<name>` in `.aidev/policy.yaml` (paths of PKG source it may write, and an optional branch condition). The grant does not apply when a person calls the agent as a sub-agent in an interactive session (xref:permissions-source[Letting an agent edit source]).

Documents listed under `references` in `aidev.yaml` are appended to the task as a "Reference documents" section, grouped by topic. Missing paths and paths under `secrets_paths` are not passed; they are listed as unavailable and warned about. Only text files can be passed: export Excel, Word and PDF files to Markdown or CSV first (see `references` in the xref:configuration[aidev.yaml reference]). `show` prints the list that would be passed.

How the task reaches the tool differs. Claude Code receives it on standard input and selects the agent with `--agent <name>`. GitHub Copilot CLI and Kiro CLI receive one command-line sentence pointing at a task file written under `.aidev/cache/agents/`, and also select the agent by name. OpenAI Codex CLI cannot select an agent by name, so the task file starts with the agent's definition.

The adapters other than Claude Code follow each tool's published non-interactive mode, but the kit maintainers have not checked them against the real tools. Use `run --dry-run` or `show` to see the exact command line before relying on one.

=== Subcommands

[%autowidth.stretch,options="header"]
|===
|Subcommand |What it does

|`list`
|Lists the bundled agents with the tool and model each one runs with

|`show <name>`
|Shows the agent's description, definition file, tool, model and the command line that would run

|`run <name> [<task>...]`
|Starts the agent. The task comes from the arguments, `--prompt-file`, or standard input
|===

=== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--json`
|Machine-readable output

|`--tool <tool>`
|Tool for this run (`claude`, `copilot`, `codex`, `kiro`)

|`--model <model>`
|Model for this run; `""` passes no model flag

|`--timeout <ms>`
|`run`: time budget, 10000 to 7200000 (default 1800000 = 30 minutes)

|`--prompt-file <path>`
|`run`: read the task from a file

|`--dry-run`
|`run`: print the command line that would run; start nothing
|===

=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Success (for `run`: the agent finished normally)

|1
|Bad agent name, tool or model; the tool is not in `tools.default`; the tool was not found; the agent failed or timed out
|===

=== Examples

[source,bash]
----
aidev agent list
aidev agent show knowledge-builder --tool copilot
aidev agent run issue-to-pr "Triage work item 42 and propose an implementation plan" --dry-run
aidev agent run issue-to-pr "Implement work item 42 and open a PR"   # may edit the paths granted under agents.issue-to-pr in the policy
aidev agent run knowledge-builder --prompt-file task.md --model opus
aidev agent run convention-builder                                     # writes the conventions under .aidev/conventions/; review with git diff, then open a PR
aidev agent run test-writer "Write unit tests for src/services/order.ts"   # adds tests under the paths granted to agents.test-writer and opens a PR
----
