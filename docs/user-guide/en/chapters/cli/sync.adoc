[[cli-sync]]
== aidev sync

Brings this PKG in step with something that moved on: `tools` takes the ADK templates into this PKG's tool configuration, `wiki` brings the LLM Wiki to HEAD, `workflow <name>` takes a newer version of an ADK standard workflow into the copy this PKG made and edited.

=== Synopsis

[source,text]
----
aidev sync tools [--package <name|path>] [--dry-run] [--force] [--json]
aidev sync wiki [--package <name|path>] [options]
aidev sync workflow <name> [--from <standard>] [--package <name|path>] [--dry-run] [--force] [--json]
----

Without `--package`, the current PKG. `--package` takes a name shown by xref:cli-list[`aidev list packages`] or a path to a PKG. Use it after `aidev update` to bring several PKGs forward from one place.

[[cli-sync-tools]]
=== aidev sync tools

Takes the installed ADK's latest templates into this PKG's AI tool configuration.

Takes the templates of the ADK installed on this machine (the one `aidev update` brought forward) and applies them to the package, for every tool in `tools.default` of `aidev.yaml`. The team may have edited the files `aidev init` placed; `apply` behaves as a **merge**, not a copy.

[%autowidth.stretch,options="header"]
|===
|State of the file |What apply does

|Untouched since the last apply
|Replaced with the new template

|Edited, and the ADK did not change it
|Kept as it is

|Edited, and the ADK changed it too
|Merged three ways against the template the previous apply used. If the same lines changed, git-style conflict markers are written and the command stops with exit code 2

|No longer shipped by the ADK
|Removed if untouched, kept if edited

|A tool added to `tools.default`
|Its files are placed for the first time
|===

The package team resolves conflicted files. Once the markers are gone and the content is settled, run `aidev sync tools` again: files without markers are recorded as resolved and `aidev check` passes again. Until then `aidev sync tools` leaves those files alone and `aidev check` returns exit code 2.

The result is an ordinary diff in the package. Review it with `git diff`, commit, and open a pull request; after the merge the team only needs `git pull`.

The merge base is the template at the ADK commit of the previous apply. When the ADK clone lacks that history (a shallow clone, for instance) the file cannot be merged; it is reported as a conflict and left alone, to be fixed by hand or replaced with `--force`.

==== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--dry-run`
|Show what would change; write nothing (not even the record)

|`--force`
|Take the ADK version of every file, discarding local edits and conflicts

|`--json`
|Machine-readable output
|===

==== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Applied, or already current

|1
|No `aidev.yaml`, or the ADK has no templates

|2
|Conflicts remain (new ones, or markers from a previous apply not yet resolved)
|===

==== Examples

[source,bash]
----
aidev sync tools --dry-run
aidev sync tools
----

Another PKG, from anywhere:

[source,bash]
----
aidev list packages
aidev sync tools --package demo-pkg
----

[source,text]
----
aidev sync tools
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    2 file(s) with local edits kept as they are
    Review with "git diff", then commit so your team receives the update.
----

With a conflict (exit code 2):

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
    Resolve the conflict markers (or keep your version / take the kit's), then run "aidev sync tools" again
    to record the result. "aidev sync tools --force" takes the kit version of every file instead.
----

[[cli-sync-wiki]]
=== aidev sync wiki

Updates the LLM Wiki to match the HEAD of the current branch and commits `.aidev/knowledge/` as its own commit. Only the files changed since the last run and the files left unfinished last time are taken (the delta); pages of removed files are deleted, the inventory and manifest are written, and then the knowledge-builder agent is started once per batch to write the prose. When everything is done, only `.aidev/knowledge/` (and `.aidev/.gitignore`) is committed as `aidev: update Wiki for <sha12>`.

If the generation targets (`package.include` in `aidev.yaml`) have uncommitted changes, it lists those files and stops. Commit or stash them first. It does not matter if `.aidev/knowledge/` or the ADK's configuration files are dirty.

While prose is still pending, the exit code is 1 and nothing is committed. The remaining batches are written to `.aidev/knowledge/.cache/plan.json`. Run the same command again to continue from the checkpoint.

`--no-agent` writes only the inventory and manifest and leaves the prose ungenerated (exit code 1). It is used to finish up after subagents have written the prose on the hook's instructions. It then records the completion reports and commits if nothing is left.

`--no-commit` does not commit; the updated Wiki stays in the working tree. Use it during setup to put the configuration and the Wiki into one PR.

If a Wiki page has been edited by hand, it stops (`--force` overwrites).

[[cli-sync-wiki-publish]]
==== When run on the tracking branch

When `main` (the tracking branch) is checked out, or `--branch` is given, it updates in a temporary worktree `.aidev/cache/wiki-worktree/`, commits on the branch `aidev/wiki-<sha12>`, pushes it and opens a PR (on Azure DevOps when `sync.auto_pr` is `true` and a PAT is present; with `generic` hosting you open it by hand). Your checkout is not touched. It pushes only when the prose is complete.

If it fails part way, the lease (`.aidev/sync.lock`) and the worktree stay. The same command continues; `--abort` discards them.

==== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--scope <path>`
|Regenerate only the pages under this path. The research scope stays the whole PKG

|`--full`
|Regenerate every page instead of the delta

|`--dry-run`
|Show what would be taken; write nothing

|`--json`
|Machine-readable output

|`--force`
|Overwrite Wiki pages edited by hand. Take over the lease of an interrupted publish

|`--no-commit`
|Do not commit; leave the updated Wiki in the working tree

|`--branch`
|Update in a temporary worktree, commit on the branch `aidev/wiki-<sha12>` and open a PR (automatic on the tracking branch)

|`--no-push`
|With `--branch`: only commit on the local `aidev/wiki-<sha12>`; do not push or open a PR

|`--abort`
|Discard an interrupted `--branch` publish (remove the worktree, release the lease)

|`--no-agent`
|Write only the inventory and manifest; leave the prose for later. Record completion reports if there are any

|`--agent-name <name>`
|Start this agent instead of the knowledge-builder

|`--agent-tool <tool>`
|AI tool that runs the agent (`claude`, `copilot`, `codex`, `kiro`). Only those in `tools.default` of `aidev.yaml`. Default: `tools.agents.<name>.tool`, or `tools.agent` if not set

|`--agent-timeout <ms>`
|Time budget for one agent run (default 1800000 = 30 minutes)

|`--agent-model <model>`
|Model for the agent. `""` leaves it to the tool's default

|`--agent-batch-size <n>`
|Number of files handed to the agent per run (default 20)

|`--survey`
|Always rewrite `overview.md` and `index.md` first

|`--no-survey`
|Do not rewrite `overview.md` and `index.md`
|===

==== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|The Wiki describes HEAD and was committed, or there was nothing to do. `--dry-run`, `--abort`

|1
|Prose is still pending (`--no-agent`; the agent failed, timed out or stopped part way. Run again to continue). The generation targets have uncommitted changes. Hand edits exist and `--force` is missing. No file matches `--scope`. A publish for another target was left interrupted (`--abort` or `--force`). The object is neither `tools` nor `wiki`
|===

==== Examples

First generation (Engineering Manager; you commit it yourself together with the PR):

[source,bash]
----
aidev sync wiki --no-commit
----

Update (if it stops, the same command resumes):

[source,bash]
----
aidev sync wiki
----

Only see what would be taken:

[source,bash]
----
aidev sync wiki --dry-run
----

[source,text]
----
aidev sync wiki (dry run)
  target               9f8e7d6 (HEAD of feature/login)
  wiki describes       1a2b3c4
  generation targets   163
  ...
  queued now           7
✓ dry run complete; nothing was written.
    would then run the knowledge-builder agent with Claude Code for 7 generation target(s) in 1 batch(es).
----

After subagents have written the prose on the hook's instructions, record the reports and commit:

[source,bash]
----
aidev sync wiki --no-agent
----

Regenerate only `src/api`, in small batches:

[source,bash]
----
aidev sync wiki --scope src/api --agent-batch-size 10
----

Regenerate every page (discarding hand edits too):

[source,bash]
----
aidev sync wiki --full --force
----

Update the Wiki of `main` through a PR (the same as the nightly pipeline):

[source,bash]
----
aidev sync wiki --branch
----

Discard an interrupted publish:

[source,bash]
----
aidev sync wiki --abort
----

[[cli-sync-workflow]]
=== aidev sync workflow

Takes a newer version of an ADK standard workflow into the copy that `aidev create workflow <name> --from <standard>` made, keeping what this PKG changed (`cwd`, paths, `inputs`, the agents' steps). It is the same three-way merge `aidev sync tools` does for the templates.

The copy carries `.aidev/workflows/<name>/standard.json` (the standard it came from, the ADK commit, and per file the hashes of the ADK version and of what was written). From it, each file of the ADK's standard workflow (`workflow.yaml`, agents, skills) ends up as one of:

[%autowidth.stretch,options="header"]
|===
|Result |When |What happens

|`+ <path>` (created)
|A file the ADK's standard workflow gained
|Written

|unchanged
|Already identical
|Nothing

|`~ <path>` (updated)
|Not edited in this PKG; the ADK changed it
|Replaced with the ADK version (every file with `--force`)

|kept
|Edited in this PKG; the ADK has not changed it since the copy
|Left as it is

|`~ <path> (merged with your edits)`
|Edited here and changed by the ADK, in different places
|The three-way merge against the ADK version at the copy is written

|`! <path>` (conflict)
|Both changed the same lines
|git-style conflict markers are written, exit code 2. Resolve them and run again (the record is updated). While markers remain, the command refuses to run

|`! <path>` (conflict, no base)
|Edited here, and the version it was copied from is not in the record or not in the ADK checkout's history
|Merge by hand (`git diff --no-index <ADK file> <PKG file>`), or take the ADK version with `--force`

|`= <path>` (retired)
|Recorded, but no longer in the ADK's standard workflow
|Left as it is
|===

Afterwards the definition is validated (exit code 1 with the reason when it fails). Review the result with `git diff` and submit it with `aidev submit workflow <name>`: what runs is the submitted and merged version, so taking the update in changes nothing by itself (`--trial` tries it first).

**A copy without `standard.json`** (made before the record existed) needs `--from <standard>` to name where it came from. The newest version in the ADK checkout's history whose files match the copy becomes the base (`no standard.json was there; the copy matches the kit's … at <commit> (N of M file(s))`) and the record is written. When no file matches any version, there is no base and an edited file is a conflict (no base).

==== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--from <standard>`
|For a copy without `standard.json`: the standard workflow it came from. With a record, it has to match

|`--dry-run`
|Show what would change; write nothing (the record included)

|`--force`
|Replace every file with the ADK version, discarding local edits and conflicts

|`--json`
|Machine-readable output (`ok`, `from`, `kitCommit`, `baseCommit`, `bootstrapped`, `created`, `updated`, `merged`, `kept`, `retired`, `unchanged`, `conflicts`, `problem`)
|===

==== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Taken in, or already current

|1
|No such workflow; no `standard.json` and no `--from`; `--from` differs from the record; the ADK has no such standard workflow; the result fails validation

|2
|Conflicts remain (markers just written, no base, or markers from an earlier run still unresolved)
|===

==== Examples

After updating the ADK, take it into the copied `e2e-tests`:

[source,bash]
----
aidev update
aidev sync workflow e2e-tests --dry-run     # see what would change first
aidev sync workflow e2e-tests
git diff                                    # review, then
aidev submit workflow e2e-tests
----

[source,text]
----
aidev sync workflow e2e-tests
✓ took 3 change(s) from the kit's playwright-tests into workflow e2e-tests
    ~ .aidev/agents/playwright-test-writer.md
    ~ .aidev/skills/playwright-testing/SKILL.md
    ~ .aidev/workflows/e2e-tests/workflow.yaml (merged with your edits)
    Review with "git diff", then "aidev submit workflow e2e-tests" (the reviewed copy is what runs; try it first with "aidev run workflow e2e-tests --trial").
----

A copy without a record, naming where it came from:

[source,bash]
----
aidev sync workflow e2e-tests --from playwright-tests
----
