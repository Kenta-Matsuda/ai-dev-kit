[[cli-init]]
== aidev init

Sets up {project-name} in this PKG. Interactive the first time, no questions for everyone after that. It does not generate the Wiki (xref:cli-sync-wiki[`aidev sync wiki`]).

=== Synopsis

[source,text]
----
aidev init [options]
----

=== Description

Run it at the root of the PKG clone. If there is no `aidev.yaml`, it asks four questions (tools, Wiki generation targets, secret paths, hosting) and writes `aidev.yaml`. If the file already exists, it asks nothing. In both cases it then:

* writes `.aidev/.gitignore`
* places the configuration files of the chosen tools from the ADK templates (for `claude`: `.claude/**`, `CLAUDE.md`, `.mcp.json`) and records their hashes in `.aidev/materialized.json`. In a clone that already has the record it places nothing and only reports the state
* registers this clone on this machine
* if `.aidev/policy.yaml` is missing, shows the candidate and asks `Place this policy now? (y/N)`
* reports whether the Wiki is present. On the first run it shows the remaining steps as `next steps` (`aidev create policy --approve`, `aidev sync wiki --no-commit`, `git add … && git commit`, PR). For everyone after that it shows `ready. Run "aidev check" any time …`

If, on the first run, an existing `.claude/` or similar differs from the templates, it does not merge: it leaves those files alone and stops with exit code 2. `--force` replaces them with the ADK version.

Questions are asked only when stdin is a terminal and neither `--yes` nor `--json` is given.

=== Options

[%autowidth.stretch,options="header"]
|===
|Option |Description

|`--dry-run`
|Show what would be written; write nothing

|`--yes`
|Do not ask questions; use the values inferred or given by flags

|`--force`
|Replace distributed files that were edited by hand

|`--json`
|Machine-readable output

|`--name <value>`
|Package name (default: the repository name)

|`--include <value>`
|Wiki generation targets, comma-separated globs (default: inferred from the tree)

|`--exclude <value>`
|Globs excluded from generation targets, comma-separated

|`--secrets <value>`
|Paths never read by the AI, comma-separated globs

|`--hosting <value>`
|`azure-devops` or `generic` (default: inferred from the `origin` URL)

|`--org <value>` +
`--project <value>` +
`--repository <value>`
|Azure DevOps organization, project and repository name

|`--tracking-branch <value>`
|Branch the Wiki follows. Also the reference for workflow approval (default: `main`)

|`--tools <value>`
|AI tools to configure, comma-separated: `claude`, `copilot`, `codex`, `kiro` (default `claude`)

|`--agent-model <value>`
|Model for the agents `aidev` starts (default: `sonnet`)

|`--approve`
|Place the policy without asking
|===

=== Exit codes

[%autowidth.stretch,options="header"]
|===
|Code |Condition

|0
|Success

|1
|Not a git repository, no commits, run in a subdirectory, or the Azure DevOps organization and so on could not be determined

|2
|On the first run, existing `.claude/**`, `CLAUDE.md`, `.mcp.json` or similar differ from the ADK templates (`--force` replaces them)
|===

=== Examples

First time (interactive):

[source,bash]
----
aidev init
----

[source,text]
----
ℹ LLM Wiki is not generated yet. Run "aidev sync wiki --no-commit" to build it (it takes a while).

ℹ next steps (you are setting this package up for your team):
    1. aidev sync wiki --no-commit          # builds (or continues) the LLM Wiki
    2. git add aidev.yaml .aidev .claude CLAUDE.md && git commit
    3. open a pull request so everyone gets the same setup
----

Without questions, placing the policy at the same time:

[source,bash]
----
aidev init --yes --include "src/**,docs/**" --approve
----

Everyone after the first person:

[source,bash]
----
aidev init
----

[source,text]
----
✓ aidev.yaml is present (set up by your team); nothing to ask.
✓ tool configuration is current (18 file(s) for claude)
✓ AZURE_DEVOPS_PAT is set (value not read)
✓ .aidev/policy.yaml is present
✓ LLM Wiki is present (.aidev/knowledge/)

ℹ ready. Run "aidev check" any time, then start your AI tool (e.g. "claude") in this directory.
----
