[[maintain-update]]
=== Updating the ADK

When a newer ADK exists, running any `aidev` command shows this. Developers see it on their machines too.

[source,text]
----
⚠ a newer ai-dev-kit is available (9491efe → e0aa66c). Run "aidev update".
  Update now, before running this command? (y/N):
----

`y` updates the ADK (the CLI and its templates). **PKG files do not change at this point.** Once the update is in, the command you started is run again with the new CLI.

[source,text]
----
✓ updated ai-dev-kit 0.3.0 → 0.4.0 (499f940 → 7c1d2e3)
ℹ 1 package(s) on this machine still carry templates from an older kit:
    demo-pkg (applied 499f940)
    Run "aidev sync tools --package <name>" for each when convenient; it merges the new templates with your edits.
----

[[maintain-workflow-v2]]
==== Rewriting a 2.0.0 workflow.yaml

A workflow.yaml written for ADK 2.0.0 is refused by the current ADK's validation (`cost is not a workflow key; the budget is limits.max_usd now` and so on). `scripts/convert-workflow-v2.ps1` in the ADK clone rewrites it in the current syntax.

[source,powershell]
----
# Every .aidev/workflows/*/workflow.yaml in the PKG. -WhatIf shows the result without writing
powershell -ExecutionPolicy Bypass -File <ADK clone>\scripts\convert-workflow-v2.ps1 -Path <PKG clone> -WhatIf
powershell -ExecutionPolicy Bypass -File <ADK clone>\scripts\convert-workflow-v2.ps1 -Path <PKG clone>
----

[%autowidth.stretch,options="header"]
|===
|2.0.0 |Now

|`cost: { max_usd: N }`
|`limits.max_usd: N`

|`limits.max_minutes` omitted (60 minutes in 2.0.0)
|`limits.max_minutes: 60` is added (not with `-NoTimeLimit`)

|A step's `timeout_ms: N`
|`timeout_minutes: N / 60000`

|A step's `max_retries: N`
|`until.max_retries: N`

|`kind: pull-request` and `title: T`
|`pull_request: { title: T }`
|===

* Only the fields above change. Comments and every other line stay. A file already in the current syntax is left alone, so running it twice gives the same result.
* The result is checked with `node` and the ADK's validation before it is written. A file that does not pass is not written (`-Force` writes it).
* `-OutFile <path>` (with one input file) writes elsewhere; `-Backup` keeps the original as `workflow.yaml.v2.bak`.
* A rewritten workflow is unapproved again. Check the diff and put it in a PR with `aidev submit workflow <name>`.

[[maintain-sync-tools]]
=== Applying new templates

After updating the ADK, **the Engineering Manager** runs this at the PKG root when it suits them and turns it into a PR. Developers get the same state with `git pull` after the merge. The team may have edited files under `.claude/` and so on: untouched files are replaced, edited files are merged with the ADK's changes.

[source,bash]
----
aidev sync tools
----

[source,text]
----
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    Review with "git diff", then commit so your team receives the update.
----

When the team and the ADK changed the same lines, git-style conflict markers are written into the file and the command stops with exit code 2.

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
----

Resolve the markers, settle the content, run `aidev sync tools` again to update the record, and commit. Until then `aidev check` returns exit code 2. To take the ADK version of every file instead, run `aidev sync tools --force`.

[[maintain-model]]
=== Changing the model

The model is set in two places: the model for the agents `aidev` starts itself (Wiki updates, workflows, `aidev create`), and the model of the AI tool a Developer uses interactively.

==== Agents started by aidev

Change `tools.agent_model` in `aidev.yaml` and open a PR. To change one agent only, add `tools.agents.<name>.model`.

[source,yaml]
----
tools:
  agent: claude
  agent_model: "sonnet"           # default; "" passes no model and leaves it to the tool
  agents:
    knowledge-builder: { model: opus }
----

The value can be an alias such as `sonnet` or `opus`, or a full ID such as `claude-opus-5`. `aidev` checks only the shape of the string and passes it to the tool's `--model` as it is. A model that does not exist fails on the tool's side when the agent starts.

When one agent has several settings, they take precedence in this order.

. The setting for that one run: the `--agent-model <model>` flag of `aidev sync wiki` (`""` drops the configured model), or `model` in workflow.yaml for `aidev run workflow`
. `tools.agents.<name>.model`
. `tools.agent_model`

The `agent tool` row of `aidev doctor --package <name>` shows the model currently in effect.

==== Interactive sessions

`aidev.yaml` has no effect on interactive sessions. Claude Code takes its model from `"model"` in the PKG's `.claude/settings.json` (the ADK ships `sonnet`). To change it for the whole team, edit that file and open a PR. Your edit survives `aidev sync tools`. A Developer who wants a different model for themselves uses `.claude/settings.local.json` (not managed by the ADK) or `/model` during the session. The model of Copilot and the other tools is set in that tool's own configuration.
