[[permissions]]
== Permissions and safety

{project-name} defines **where the AI may write** inside the PKG in `.aidev/policy.yaml` (the policy), and a hook of the AI tool checks every write against it. Source code is read-only by default. Tokens are never written to files; they are passed only through environment variables.

[[permissions-policy]]
=== The policy categories

[cols="1,2,3",options="header"]
|===
|Category |Default |Meaning

|`protected`
|Kit files such as `.claude/**`, `CLAUDE.md`, `.mcp.json`, `.aidev/policy.yaml`, plus `secrets_paths`
|Never writable. If removed from the policy, the CLI adds them back.

|`read_only`
|`**` (the whole PKG)
|Agents cannot write here. To allow edits, add `agents.<name>.writable` for one agent, or `writable` for everyone (xref:permissions-source[Letting an agent edit source]).

|`writable_during_sync`
|`.aidev/knowledge/**`
|When the Wiki is missing or unreadable, writable only while `aidev knowledge update` rewrites the structure.

|`writable`
|`.aidev/knowledge/**`, `.aidev/workflows/**`, `.aidev/conventions/**`, `aidev.yaml`
|Writable at any time, by every agent and every interactive session.

|`agents.<name>.writable` +
`agents.<name>.branch`
|None
|Extra paths that only the agent `<name>` started by `aidev` may write. With `branch`, the grant applies only while that branch (a glob) is checked out.
|===

Rules are checked top to bottom. Paths outside the repository, `secrets_paths` and `protected` paths are always denied. While there is no Wiki, everything is denied (except `.aidev/knowledge/**` while `aidev knowledge update` writes it). After that, `writable` → `agents.<name>` → `read_only` are checked in that order, and the first match decides.

[[permissions-hooks]]
=== What the hooks do

The distributed hook configuration (`.claude/settings.json` for Claude Code, `.github/hooks/aidev.json` for GitHub Copilot CLI, `.codex/hooks.json` for OpenAI Codex CLI, `.kiro/agents/aidev.json` for Kiro CLI) registers five hooks. Claude Code is the tool verified against the real binary.

[cols="1,1,3",options="header"]
|===
|Event |Command |Action

|SessionStart
|`aidev hook session-start`
|Puts the Wiki state and any publish in progress into the session context.

|PreToolUse (Write / Edit / Bash, …)
|`aidev hook guard-write`
|Checks the target path against the policy and returns the reason when it denies. Also denies when the policy cannot be read.

|PostToolUse (Write / Edit)
|`aidev hook quality-gate`
|After the AI edits a PKG file, runs the `quality_gates` commands and returns failure output to the AI.

|PostToolUse (Bash)
|`aidev hook after-bash`
|When a commit moved HEAD and the Wiki fell behind, updates the structure and, if prose is needed, tells the session to start the knowledge-builder as a subagent (xref:knowledge-hook-flow[What happens after a commit]).

|Stop
|`aidev hook session-stop`
|While the Wiki is behind HEAD, refuses to stop once and repeats the instructions. On an ai-dev-kit developer's machine it also asks for a reflection.
|===

When a write is denied, the AI receives a reason like these.

[source,text]
----
ai-dev-kit: "src/api/auth.ts" is read-only (**). PKG source is not written by agents by default; this session was not started by the CLI as a named agent; …
ai-dev-kit: ".claude/settings.json" is protected (.claude/**). …
ai-dev-kit: Wiki consistency error (…) All writes are blocked; run "aidev knowledge update" …
----

An edit that removes a hook is caught by `aidev check` with exit code 2, and CI stops the merge (the file checked is `.claude/settings.json`).

[[permissions-source]]
=== Letting an agent edit source

By default the PKG source is `read_only` and no agent can write it. To let `issue-to-pr` or another agent implement changes, the team writes a **grant for that agent** in `.aidev/policy.yaml` and commits it.

[source,yaml]
----
agents:
  issue-to-pr:
    writable: ["src/**", "tests/**"]
    branch: "aidev/issue-*"     # optional: only on this branch
  test-writer:
    writable: ["tests/**"]
    branch: "aidev/tests-*"
----

A grant applies only to an agent that **`aidev` started**, such as `aidev agent run issue-to-pr "..."` (`aidev` tells the hook which agent it started; an agent cannot claim a name for itself). A sub-agent called from an interactive `claude` session stays read-only, because there is no reliable way to know its name there. With `branch`, writes are allowed only while that branch is checked out.

Add paths to `writable` only when every agent and interactive session should be able to write them. `protected` paths and `secrets_paths` stay unwritable either way. Review policy changes in a PR (adding `agents` requires `--force` at `reconfigure --approve`) and widen them only for as long as needed.

[[permissions-commands]]
=== Placing, changing and viewing the policy

The AI cannot create the policy. A human places it with the CLI.

[%autowidth.stretch,options="header"]
|===
|Command |Action

|`aidev permission configure --approve`
|Places the candidate `.aidev/policy.candidate.yaml` as `.aidev/policy.yaml`. Use it after answering `N` in `aidev init`.

|`aidev permission reconfigure` → `reconfigure --approve`
|Rebuilds and places the candidate, for example after changing `secrets_paths`. A change that weakens protection also needs `--force`. The candidate is rebuilt from `aidev.yaml`, so any `writable` or `agents` entries the team added to the policy by hand are lost. Add them again after placing it, and commit.

|`aidev permission show`
|Shows the policy in force.
|===

[[permissions-secrets]]
=== Secrets

* Files under `secrets_paths` are never read or written by the AI and are hidden from the Wiki.
* The PAT is passed only through the environment variable named by `hosting.auth_env` (default `AZURE_DEVOPS_PAT`). Writing it into `aidev.yaml` stops every command from starting.
* `aidev doctor` and `aidev init` report only whether the token is set. They never read the value.

=== What not to do

* Do not silently rewrite the kit-derived parts of `.claude/**`, `CLAUDE.md` or `.mcp.json` (review team changes in a PR; send improvements for the whole kit as a PR to the kit).
* Only humans edit `.aidev/policy.yaml`, and every change is reviewed in a PR (never let the AI edit it).
* When the AI reports a denied write, read the reason instead of looking for a workaround.
* Do not put tokens in commits, logs or PR descriptions.
