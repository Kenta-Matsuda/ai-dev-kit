[[daily]]
== Daily use

There are three things to do day to day. Look at `aidev status` before you start. After a commit, bring the Wiki to HEAD as the hook instructs (by hand: `aidev knowledge update`). Run `aidev update` when it says a newer kit is available.

[[daily-status]]
=== Reading aidev status

[source,bash]
----
aidev status
----

The symbol and sentence on the second line tell you what to do next.

[%autowidth.stretch,options="header"]
|===
|Shown |What to do

|`✅ the Wiki describes HEAD (…)`
|Nothing.

|`⚠️ the Wiki describes … but N file(s) differ at HEAD … — run "aidev knowledge update"`
|The code moved on and the Wiki is behind. Inside an AI tool session, the hook starts the update after your next commit. To do it now, run xref:daily-wiki[aidev knowledge update]. You can keep working.

|`⚠️ N page(s) still await prose regeneration`
|Some pages have no text yet. Run `aidev knowledge update` (or follow the hook's instructions if they were shown).

|`⚠️ origin/main has moved ahead …`
|`main` is ahead of your working branch. Merge or rebase at a good moment, then run `aidev knowledge update`.

|`⚠️ origin/main has new commits …`
|Run `git fetch`, then `aidev status` again.

|`ℹ️ remote unverified …`
|The remote could not be reached (offline, proxy). Your local state is consistent, so you can keep working.

|`❌ LLM Wiki has not been generated yet …`
|There is no Wiki. **While this lasts, every write by the AI is blocked.** If `git pull` should bring it, pull. If not, ask the package owner or run `aidev init`.
|===

For other messages, see xref:troubleshooting-status[Troubleshooting].

In the lines that follow, check `tool config` and `policy`. `tool config` starts with `applied from kit <sha>` and adds how many files the team edited (`customised`) and whether newer templates exist (`newer templates available: "aidev apply"`). `CONFLICTS` means an `aidev apply` conflict is unresolved; `kit hooks missing` means the hooks are gone from `.claude/settings.json` (xref:daily-apply[aidev apply]). `policy` shows `placed (N protected paths)` plus any grants the team added per agent (`agent grants: …`). `missing` is fixed with `aidev permission configure --approve`.

=== How the Wiki is used

Following the instructions in `CLAUDE.md`, the AI reads `.aidev/knowledge/index.md` and `overview.md` before it reads the source. Every statement in the Wiki links to the file it is based on, and the AI confirms it there.

You never need to fix the Wiki by hand. If you find a mistake, fix the source (a comment or the structure) and let the next update pick it up. Hand edits are detected, and the next generation asks for `--force` (xref:knowledge-handedit[Why not to edit by hand]).

[[daily-wiki]]
=== Keeping the Wiki up with the code

The Wiki describes the HEAD of the branch you are on. Every time you commit code, the Wiki is committed on the same branch as a separate commit.

When you run `git commit` inside an AI tool session, the hook updates the structure and, if prose is needed, tells the session to start the knowledge-builder as a subagent and then run `aidev knowledge update --no-agent`. Once the session has done that, `.aidev/knowledge/` is committed as `aidev: update Wiki for <sha12>`. If you try to end the session while the Wiki is behind, it is stopped once.

To do it by hand, run the following. It stops if generation targets have uncommitted changes, so commit first.

[source,bash]
----
aidev knowledge update
----

[source,text]
----
✓ manifest and 1 shard(s) written for 9f8e7d6
ℹ running the knowledge-builder agent: 7 generation target(s) in 1 batch(es) of up to 20
✓ batch 1/1 complete: 7/7 in 4m 2s ($0.5533)
✓ committed the Wiki as c0ffee1 (aidev: update Wiki for 9f8e7d6c5b4a)
----

Put the source commit and the Wiki commit in the same PR; the reviewer reviews both. Reviewing the generated Wiki is your responsibility. The kit never merges a PR.

* If it stops part way, run the same command again.
* Run on `main`, it commits on the branch `aidev/wiki-<sha12>` and opens a PR (xref:knowledge-publish[Updating on the tracking branch]).
* In a team whose nightly pipeline updates the Wiki of `main` through a PR, receive it with `git pull` after the merge.

[[daily-update]]
=== aidev update — update the kit

When a newer kit exists, running a command in the package shows this:

[source,text]
----
⚠ a newer ai-dev-kit is available (9491efe → e0aa66c). Run "aidev update".
  Update now, before running this command? (y/N):
----

`y` updates the kit (the CLI and its templates). Package files do not change at this point. Once the update is in, the command you started is run again with the new CLI.

[source,text]
----
✓ updated ai-dev-kit 0.3.0 → 0.4.0 (499f940 → 7c1d2e3)
ℹ 1 package(s) on this machine still carry templates from an older kit:
    C:\work\demo-pkg (applied 499f940)
    Run "aidev apply" in each when convenient; it merges the new templates with your edits.
----

[[daily-apply]]
=== aidev apply — take the new templates into the package

After updating the kit, run this at the package root when it suits you. The team may have edited files under `.claude/` and so on: untouched files are replaced, edited files are merged with the kit's changes.

[source,bash]
----
aidev apply
----

[source,text]
----
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    Review with "git diff", then commit so your team receives the update.
----

Review the diff, commit it and open a PR. After the merge, the other members get the same state with just `git pull`.

When the team and the kit changed the same lines, git-style conflict markers are written into the file and the command stops with exit code 2.

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
----

Resolve the markers, settle the content, run `aidev apply` again to update the record, and commit. Until then `aidev check` returns exit code 2. To take the kit version of every file instead, run `aidev apply --force`.
