[[setup-owner]]
== PKG への導入

PKG に {project-name} を初めて導入し、チーム共通の設定・AI の書き込み権限・AI 向けのコード説明書を用意して配ります。PKG につき 1 人が行います。**この PKG で AI に何を許し、何をさせるかを決めるのはこの人です。** Developer は決めません。

この章は導入の 1 回だけの手順です。導入後に継続して行うことは xref:maintain[環境の保守] にあります。

=== 事前準備

* xref:install[aidev のインストール] が終わっていて、`aidev doctor` で `claude` が `✓`
* PKG の clone。コミットが 1 つ以上あり、`origin` が設定されている
* Azure DevOps なら `AZURE_DEVOPS_PAT` を設定済み
* Wiki の生成には時間がかかります。目安は生成対象 20 ファイルごとに数分〜十数分です

=== 手順

. PKG のルートで作業ブランチを切ります。
+
[source,bash]
----
cd <pkg>
git switch -c feature/ai-dev-kit
----

. `aidev init` を実行し、4 つの質問に答えます。Enter で `[ ]` の既定値になります。
+
[source,bash]
----
aidev init
----
+
[%autowidth.stretch,options="header"]
|===
|質問 |答え方

|1/4 tools
|そのまま Enter で `claude`。複数使うなら `claude, copilot` のようにカンマ区切りで書きます（`claude`、`copilot`、`codex`、`kiro`）。どのツールを誰が使うかはチームで決め、`aidev.yaml` に残ります。

|2/4 Wiki の生成対象
|説明ページを作りたいパス（glob、カンマ区切り）。`src/**`, `docs/**` などが提案されます。Wiki の調査そのものは PKG 全体を対象にするので、ここは「ページが欲しい場所」だけで構いません。

|3/4 秘密パス
|AI に読ませないパス。既定の 5 つに、証明書や設定の置き場があれば追加します。

|4/4 hosting
|`origin` の URL から推定されます。Azure DevOps なら organization / project / repository を確認し、最後に Wiki が追いかけるブランチ（既定 `main`）を答えます。このブランチは workflow の承認の基準にもなります。
|===
+
質問のあと、設定ファイルが書かれ、policy の要約と `Place this policy now? (y/N)` が表示されます。`y` で policy が置かれます。`N` なら候補ファイルが書かれ、次の手順で承認します。最後に `next steps` として、残りの手順（policy の承認、Wiki の生成、コミット、PR）が表示されます。`aidev init` は Wiki を生成しません。
+
* `✗ N file(s) already exist here and differ from the kit templates` → `.claude/` などに kit のテンプレートと違う既存ファイルがあります。内容を退避してから `aidev init --force` を実行します。
* `run "aidev init" at the repository root` → ルートに移動して実行します。

. policy を承認します（手順 2 で `N` にした場合だけ）。候補を読み、納得したら置きます。
+
[source,bash]
----
cat .aidev/policy.candidate.yaml
aidev create policy --approve
----
+
policy の中身は xref:permissions[権限と安全性] を見てください。ソースを AI に書かせる範囲は policy ではなく、あとで作る workflow の `scope.writable` に書きます。

. Wiki を生成します。`--no-commit` で結果を作業ツリーに残し、次の手順で設定と一緒にコミットします。時間がかかります。途中で止まっても、同じコマンドをもう一度実行すると続きから再開します。
+
[source,bash]
----
aidev sync wiki --no-commit
----
+
[source,text]
----
ℹ running the knowledge-builder agent: 163 generation target(s) in 9 batch(es) of up to 20, after a survey run
✓ survey complete in 3m 12s ($0.4120)
ℹ batch 1/9: 20 target(s), src/api/auth.ts … src/api/users.ts
✓ batch 1/9 complete: 20/20 in 4m 2s ($0.5533)
...
✓ knowledge-builder completed 163/163 queued generation target(s) ($4.9012)
----
+
最後が `✓ knowledge-builder completed N/N` なら完了です。それ以外で止まったら、次を確認して同じコマンドをもう一度実行します。
+
* `⚠ the knowledge-builder agent did not run` → Claude Code が見つかりません。`aidev doctor` の `claude` 行を直します。
* `✗ … ran out of time` / `⚠ … partial Wiki progress` / Ctrl-C → 終わった分は保存されています。再実行します。
+
`aidev check` の 2 行目が `✅` になれば Wiki は完成です。

. コミットして PR を作ります。
+
[source,bash]
----
aidev check
git add aidev.yaml .aidev .claude CLAUDE.md
git commit -m "chore: adopt ai-dev-kit"
git push -u origin feature/ai-dev-kit
----
+
`aidev check` が `✓ environment is consistent.` であることを確認してから push します。`.aidev/.gitignore` が一時ファイルを除外するので、`git add .aidev` で余計なものは入りません。`copilot` / `codex` / `kiro` も選んだ場合は、そのツールの設定ファイル（`.github/`、`AGENTS.md`、`.kiro/`）も `git add` します（xref:files-and-state[PKG 内のファイル]）。

. PR をレビューしてもらい、`main` にマージします。レビュアーは設定（`aidev.yaml`、policy）と Wiki の内容を見ます。マージ後、 Developer は xref:setup-member[利用の開始] で参加できます。

[[setup-owner-guardrails]]
=== 必須設定

次の 2 つは導入と同時に必ず設定します。これが無いと、AI が書ける範囲を広げる変更がレビューを通らずに入ります。

[[maintain-branch-policy]]
==== branch policy の設定

workflow の承認は「`main` にマージされたこと」です。つまり **`main` の branch policy が承認の実体** です。次を設定してください。

* `aidev check` の pipeline を必須の build validation にする
* `.aidev/workflows/**`、`.aidev/agents/**`、`.aidev/skills/**`、`.aidev/policy.yaml`、`aidev.yaml` に必須レビュアーを付ける
* `main` への直接 push を禁止する

これが無いと、AI が書ける範囲を広げる変更や、書き込みの制限を外す変更が、レビューを通らずに入ってしまいます。

[[maintain-ci]]
==== CI の設定

CI が行うのは 2 つです。PR ごとに `aidev check` でマージを止めることと、夜間に `main` の Wiki を追従させることです。いずれもマージは人間が行います。

kit の `pipelines/` にある Azure Pipelines の例を PKG にコピーし、`AIDEV_KIT_URL` を中央 kit の URL に変えて使います。CI は kit を clone して `node cli/bin/aidev.js` を直接実行するので、`aidev` のインストールは不要です。

[%autowidth.stretch,options="header"]
|===
|ファイル |用途

|`pipelines/azure-pipelines-check.yml`
|PR ごとに `aidev check` を実行します。`main` の branch policy で **必須の build validation** にしてください。これが無いと、書き込みの制限を外す編集がマージできてしまいます。

|`pipelines/azure-pipelines-wiki.yml`
|毎日 18:00 UTC に `main` で `aidev sync wiki --branch` を実行します。Wiki 無しでマージされた分を拾い、`aidev/wiki-<sha12>` ブランチにコミットして PR を作ります。本文が完成したときだけ publish するので、pipeline に agent のツール（`tools.agent`。既定は Claude Code）とその認証情報が必要です。変数 `AZURE_DEVOPS_PAT`、`ANTHROPIC_API_KEY`、`AIDEV_BOT_NAME`、`AIDEV_BOT_EMAIL` を設定します。Wiki が既に `main` の HEAD を説明していれば何もしません。
|===

Developer がコミットのたびに Wiki を追従させていれば、夜間の pipeline は保険です。

`aidev check` の終了コードが CI との契約です。意味は xref:cli-exit-codes[コマンドリファレンス: 終了コード] を参照してください。

=== 導入後の作業

上記が済んだら、次を順に進めます。いずれも Engineering Manager が行い、PR にします。

[%autowidth.stretch,options="header"]
|===
|作業 |手段

|Developer に案内する
|→ xref:setup-member[利用の開始]

|AI に任せる仕事を定義する
|やりたいことを伝えて処理ワークフローを作り、書いてよい範囲を確認して提出します。マージされると Developer が実行できます。→ xref:workflows[AI への作業委譲]

|この PKG の開発規約を書き出す
|「Wiki と根拠ソースからこの PKG の開発規約を根拠付きで書く」処理ワークフローを作って提出し、マージ後に実行します。→ xref:workflows-define[workflow の定義]

|AI の編集後に lint / test を走らせる
|`aidev.yaml` の `quality_gates` に書きます。→ xref:configuration[aidev.yaml リファレンス]
|===
