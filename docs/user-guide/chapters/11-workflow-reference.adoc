[[workflow-reference]]
== workflow 定義リファレンス

workflow と、それが使う agent・skill の書き方を、項目ごとに説明します。考え方と使い方は xref:workflows[AI への作業委譲（workflow）] にあります。この章は、書いている途中に引くためのものです。

[[workflow-reference-files]]
=== ファイルと関係

[cols="2,3,3",options="header"]
|===
|ファイル |書くもの |誰が参照するか

|`.aidev/workflows/<name>/workflow.yaml`
|ステップの順番と、各ステップの制約（書ける場所、終わりの判定、上限）。この workflow で agent に足す能力（`agents:`）
|`aidev run workflow <name>`

|`.aidev/agents/<name>.md`
|agent の役割（本文）と能力（frontmatter の `skills`・`tools`・`mcp`・`subagents`）
|workflow のステップの `agent:`、`until.agent:`

|`.aidev/skills/<name>/SKILL.md`
|手順書
|agent の frontmatter の `skills:`、workflow の `agents.<agent>.skills`
|===

.workflow はステップで agent を名前で参照し、agent は skill を名前で参照する
[mermaid]
----
flowchart LR
  W["workflow.yaml"] -- "steps[].agent" --> A["agents/#60;name#62;.md"]
  W -- "steps[].until.agent" --> R["agents/#60;checker#62;.md"]
  A -- "frontmatter skills" --> S["skills/#60;name#62;/SKILL.md"]
  A -- "frontmatter mcp" --> M[".mcp.json の server"]
  W -- "agents.#60;name#62;.skills" --> S
  W -- "agents.#60;name#62;.mcp" --> M
  A -- "frontmatter subagents" --> SA["agents/#60;subagent#62;.md"]
  W -- "agents.#60;name#62;.subagents" --> SA
----

agent と skill は、PKG の `.aidev/` を先に探し、無ければ ADK 同梱のものを使います。同名なら PKG のものが優先です。

[[workflow-reference-skeleton]]
=== workflow.yaml の全体

すべての項目を書いた例です。`#` の後ろは説明です。

[source,yaml]
----
name: e2e-tests                    # 必須
description: 主要画面の IT テストを書いて PR にする
objective: |                       # 必須
  Add Playwright tests for the screens named in the task, from {inputs.spec}.
tool: claude                       # 任意
model: sonnet                      # 任意
agents:                            # 任意。この workflow で agent に足す能力
  e2e-writer:
    skills: [test-and-verify]      # frontmatter の skills に足す
    mcp: [playwright]              # frontmatter の mcp に足す
    tools: [Read, Grep, Edit]      # frontmatter の tools の代わりに使う
inputs:                            # 任意。実行のたびに --input <name>=<値> で受け取る値
  spec:
    description: the test specification to work from
    file: true                     # この端末のファイル。実行はそのコピーを受け取る
  browser:
    default: chromium
    pattern: '[a-z]+'              # コマンドに届く入力には pattern が要る
env_required:                      # 任意。実行する人の shell に要る環境変数（認証情報）。名前だけの list でもよい
  E2E_PASSWORD: the password of the test user
provide: [e2e/fixtures/**]         # 任意。gitignore 済みのファイルを手元のチェックアウトからコピーする
never_commit: [e2e/test-results/**]   # 任意。ADK の既定の一覧に加えて、決してコミットしないもの

steps:                             # 必須。上から順に実行する
  - id: plan                       # agent step
    description: テストが要る画面を洗い出す
    agent: e2e-planner
    writable: []
    prompt: 画面を調べ、notes ディレクトリの targets.txt に 1 行 1 件で書く。
  - id: write                      # agent step（for_each、until、unchanged あり）
    agent: e2e-writer
    writable: [e2e/tests/**]
    unchanged: [e2e/playwright.config.ts]
    for_each:
      from: targets.txt
      max_items: 20
      on_failure: continue
    prompt: 画面 {item} の IT テストを e2e/tests/{item}.spec.ts に書く。
    until:
      command: [npm ci, npx playwright test tests/{item}.spec.ts --project {inputs.browser}]
      cwd: e2e
      env: { CI: 1 }
      timeout_minutes: 15
      agent: e2e-reviewer
      prompt: 画面 {item} の主要な操作がすべて検証されているか。
      max_retries: 3
    timeout_minutes: 30
  - id: lint                       # command step
    command: npm run lint
  - id: pr                         # pull-request step
    pull_request:
      title: "test: add e2e tests"

limits:
  max_usd: 10                      # 必須
  max_minutes: 45                  # 任意
----

表にない項目を書くと、検証で拒否されます（`unknown key …`）。検証は `aidev list workflows`（`invalid:` と表示）、`aidev run workflow <name> --dry-run`、`aidev submit workflow` が行います。

[[workflow-reference-top]]
=== トップレベル

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`name`
|文字列
|必須
|workflow の名前。ディレクトリ名と同じにします。小文字・数字・ハイフン、64 文字まで、英数字で始まる（`^[a-z0-9][a-z0-9-]{0,63}$`）。

|`description`
|文字列
|任意
|1 行の説明。`aidev list workflows`、PR のタイトルと本文に出ます。

|`objective`
|文字列
|必須
|この workflow の目的。すべての agent step の指示の先頭に入ります。

|`tool`
|文字列
|任意
|agent を動かす AI ツール（`claude`、`copilot`、`codex`、`kiro`）。`aidev.yaml` の `tools.default` にあるものだけ使えます。省略すると `aidev.yaml` の `tools.agents.<agent>.tool`、`tools.agent` の順に決まります。

|`model`
|文字列
|任意
|モデル名（`sonnet` など）。`""` を書くとモデルを指定せず、AI ツールの既定に任せます。省略すると `aidev.yaml` の `tools.agents.<agent>.model`、`tools.agent_model` の順に決まります。英数字と `. _ - : / @ [ ]`、200 文字まで。

|`agents`
|mapping
|任意
|この workflow で agent に足す能力。キーは steps（`agent:` か `until.agent:`）で使う agent の名前です（xref:workflow-reference-agents[agents]）。

|`inputs`
|mapping
|任意
|実行のたびに `--input <name>=<値>` で受け取る値の宣言。キーは入力の名前で、定義の `{inputs.<name>}` と書いた場所に入ります（xref:workflow-reference-inputs[inputs]）。

|`env_required`
|list か mapping
|任意
|実行する人の shell に設定されていなければならない環境変数（認証情報）。名前の list か、名前から説明への mapping。無ければ何も始めません（xref:workflow-reference-env-required[env_required]）。

|`provide`
|glob の list
|任意
|手元のチェックアウトで git が無視していて、最初のステップの前に実行の worktree へコピーするファイル（xref:workflow-reference-provide[provide]）。

|`never_commit`
|glob の list
|任意
|ADK の既定の一覧に加えて、実行が決してコミットしないパス（xref:workflow-reference-never-commit[never_commit]）。

|`steps`
|list
|必須
|ステップの list。1 つ以上。上から順に実行します。1 つのステップは agent step・command step・pull-request step・parallel グループのどれか 1 つで、`agent`・`command`・`pull_request`・`parallel` のどのキーを持つかで決まります（下の節）。2 つ以上持つと検証で拒否されます。

|`limits`
|mapping
|必須
|実行を止める条件。`max_usd`（必須）と `max_minutes`（任意）だけを持ちます（xref:workflow-reference-limits[limits]）。
|===

[[workflow-reference-agents]]
=== agents

agent が使える skill・MCP server・組み込みツールは、ふつう agent の frontmatter に書きます（xref:workflow-reference-agent[agent 定義]）。`agents:` は、**この workflow で使うときだけ** 足したいものを workflow.yaml に書く場所です。同じ agent を、別の workflow では別の能力で使えます。

[source,yaml]
----
agents:
  ticket-reader:
    skills: [ticket-format]        # frontmatter の skills に足す
    mcp: [azure-devops]            # frontmatter の mcp に足す
  test-writer:
    tools: [Read, Grep, Glob, Edit, Write]   # frontmatter の tools の代わりに使う
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`agents.<agent>`
|mapping
|任意
|`<agent>` は steps の `agent:` か `until.agent:` が使う agent、またはその `subagents` に挙げたサブエージェントの名前です。それ以外の名前は検証で拒否されます（`no step names agent …`）。持てるのは `skills`・`mcp`・`tools`・`subagents` だけです。

|`agents.<agent>.skills`
|list
|任意
|frontmatter の `skills` に **足す** skill。PKG、ADK 同梱の順に探し、どちらにも無ければ検証で止まります（`<workflow.yaml>: agents.<agent>: skill … is neither in …`）。

|`agents.<agent>.mcp`
|list
|任意
|frontmatter の `mcp` に **足す** MCP server（PKG の `.mcp.json` のキー）。`.mcp.json` に無い名前があると、workflow は起動前に止まります。

|`agents.<agent>.tools`
|list
|任意
|この workflow で使える組み込みツール。書くと frontmatter の `tools` の **代わりに** これを使います（足すのではありません）。省略すると frontmatter の `tools` に従います。空の list は書けません。

|`agents.<agent>.subagents`
|list
|任意
|frontmatter の `subagents` に **足す**、その agent が起動できるサブエージェント（xref:workflows-subagents[サブエージェントを指定する]）。ここに挙げたサブエージェントの名前も `agents:` のキーに書けます。
|===

* 足した能力も frontmatter の能力と同じに扱われます。Claude Code はそれだけを渡して起動し、hook もそれ以外のツールを拒否します。`tools` か `mcp` を持つ agent は Claude Code でだけ動きます。
* workflow.yaml は承認の対象なので、`agents:` を変えると workflow は承認前に戻ります。`aidev submit workflow` で PR にし、レビューを受けます。
* ステップに `skills`・`mcp`・`tools`・`subagents` は書けません（`a step does not carry …`）。ステップごとに能力を変えたいときは、別の agent にします。

[[workflow-reference-inputs]]
=== inputs

実行のたびに変わる値を、定義の決まった場所に入れる仕組みです（xref:workflows-inputs[実行ごとに変わる値を受け取る]）。`inputs:` に宣言した名前を `{inputs.<name>}` と書き、実行する人が `aidev run workflow <name> --input <name>=<値>` で渡します。

[source,yaml]
----
inputs:
  spec:
    description: the test specification to work from
    file: true
  screen:
    description: the screen to cover
    pattern: '[a-z0-9-]+'
  browser:
    default: chromium
    pattern: '[a-z]+'
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`inputs.<name>`
|mapping
|任意
|`<name>` は英小文字で始まる英小文字・数字・`_`・`-`、32 文字まで（`^[a-z][a-z0-9_-]{0,31}$`）。持てるのは下の 5 つだけです（`required` という項目はありません。`default` の無い入力が必須です）。空の mapping（`notes: {}`）は、必須で、規則の無い入力です。

|`description`
|文字列
|任意
|実行する人向けの説明。`--input` が足りないときの表示、`--dry-run` と提出の PR 本文の `## Inputs (--input name=value)` に出ます。

|`default`
|文字列
|任意
|`--input` が無いときの値。無ければ必須の入力です。検証のとき、値と同じ規則で確かめます。`file: true` の入力には書けません。

|`pattern`
|文字列
|コマンドに届く入力は必須（`path`・`file` が無ければ）
|値全体が一致すべき正規表現（200 文字まで。ADK が `^(?:…)$` で囲みます）。`[` で始まる値は YAML の list になるので、引用符で囲みます（`'[a-z]+'`）。

|`path`
|`true` / `false`
|任意
|`true` なら、値は PKG 内の相対パスです。`/` やドライブ文字で始まるもの、`..` を含むもの、テキストでない拡張子（`.xlsx`・`.docx`・`.pdf`・画像・アーカイブ）は拒否します。実行を始める前に、HEAD にコミット済みか、git が無視していて `provide` の glob に一致するかを確かめ、`provide` がコピーした後に worktree にあることも確かめます。`file` とは同時に書けません。

|`file`
|`true` / `false`
|任意
|`true` なら、値はこの端末のどこかにあるファイルのパスです（絶対パスか、シェルのカレントディレクトリからの相対パス）。存在するテキストファイルでなければなりません（拡張子の規則は `path` と同じ）。ADK は実行の worktree の `.aidev/workflows/<name>/runs/<id>/inputs/<name><拡張子>` にコピーし、`{inputs.<name>}` はその PKG 内の相対パスになります（gitignore 済み。コミットされません）。`--resume` はそのコピーを使います。`default` は書けず、`path` とは同時に書けません。
|===

`{inputs.<name>}` の規則:

* 書ける場所は `objective`、agent step の `prompt`、`until.prompt`、`until.command`、command step の `command`、`env` の値（step と `until`）です。`description`、step の `description`、`pull_request.title`、`writable`、`unchanged`、`cwd`、`until.cwd`、`for_each.from` に書くと検証で拒否されます（`… cannot name an input ({inputs.…})`）。コマンドの実行ファイル（先頭の語）にはできません（`the executable of a command (…) is fixed; an input can be an argument, not the command`）。宣言していない名前は `… names {inputs.<name>}, which inputs: does not declare` です。
* 値は実行の前に定義へ書き込まれます（コマンドでは 1 つの引数として）。`{item}` はその後で件ごとに置き換わります。値は `{` と `}` を含められません。
* 値は 1 行、1000 文字まで、制御文字なし。`pattern` があれば値全体が一致すること。
* **コマンドに届く入力**（`until.command`、command step の `command`、`env` の値に書いたもの）は `pattern`、`path: true`、`file: true` のどれかが必須です（`inputs.<name> reaches a command (…), so it needs a pattern that bounds its value (or path: true / file: true)`）。その値は、さらに固定の規則 `^[A-Za-z0-9._@][A-Za-z0-9._/@:=+-]{0,999}$` に収まり、`..` のセグメントを含まない 1 語でなければなりません（空白なし、先頭の `-` なし。`for_each` の件と同じ考え方です）。`pattern` はこれを狭められますが、広げられません。

`--input` の規則（`aidev run workflow`、`aidev estimate workflow`）:

* 入力ごとに 1 回ずつ `--input <name>=<値>`（`--input=<name>=<値>` も可）。
* 必須の入力が無い: `the workflow needs --input for: <name> (<description>)`（実行は何も始めずに終了コード 1。`--dry-run` でも同じ。`aidev estimate` は無くても見積もります）。宣言に無い名前: `the workflow declares no input "<name>" (its inputs: …)`。同じ名前が 2 回: `input <name> is given twice`。
* `--resume` には付けられません。続きの実行は `run.json` に記録された値を、渡されたときと同じ規則でもう一度確かめて使います。
* `aidev.yaml` の `workflows.<name>.inputs.<input>: <値>` に書いた値は、`--input` が無いときに使います（`--input` > `aidev.yaml` > `default`）。同じ規則で確かめ、宣言に無い名前は `aidev.yaml: workflows.<name>.inputs: the workflow declares no input "<name>"`、`file: true` の入力は `… is a file on the machine of whoever runs the workflow` で止まります。認証情報らしい名前の入力は `aidev.yaml` の読み込みで拒否されます（xref:configuration[aidev.yaml リファレンス]）。`--dry-run` の `inputs` の行には `(from aidev.yaml)` が付きます。
* 値は、`{inputs.<name>}` の場所のほか、すべての agent（確認役も）の指示の `## Inputs for this run` の節（データとして）、`--dry-run` の `inputs` の行、実行の PR 本文の `## Inputs`、最後のコミットの本文、`run.json` の `inputs`、`--log` の先頭とサマリ、`aidev modify --from-run` の記録に出ます。

[[workflow-reference-env-required]]
=== env_required

実行する人の shell に設定されていなければならない環境変数です（xref:workflows-env-required[認証情報は環境変数で受け取る]）。認証情報（パスワード、トークン）のためのもので、設定値は `inputs` か `env` に書きます。

[source,yaml]
----
env_required:
  E2E_PASSWORD: the password of the test user   # 名前: 説明
  API_TOKEN:                                    # 説明は省略できる
# 名前だけの list でも書けます
# env_required: [E2E_PASSWORD, API_TOKEN]
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`env_required`
|名前の list、または名前 → 説明の mapping
|任意
|名前は環境変数の規則（`^[A-Za-z_][A-Za-z0-9_]{0,63}$`）。`AIDEV_*` と `GIT_CONFIG*` は書けません。32 個まで。説明は 1 行で、実行する人向けのエラー、`--dry-run` の `env` の行、提出の PR 本文の `## Environment variables the run needs`、agent の指示の `## Environment variables of this run` に出ます。同じ名前を command step や `until` の `env` に書くと検証で拒否されます（`env sets <NAME>, which env_required says the shell provides`）。
|===

* `aidev run workflow` と `--dry-run` は、起動前の検査で変数が設定されているか（空でないか）を確かめます。無ければ `the environment variable <NAME> (<説明>) is not set; the workflow needs it (env_required). Export it in the shell that runs aidev; …` と表示して終了コード 1 です。`--resume` でも同じです。`--dry-run` の `env` の行は `<NAME>: set` か `<NAME>: NOT SET` です。
* 値は読みません。agent とコマンドは実行する人の shell の環境を引き継ぐので、そこから届きます。`run.json`・`log.txt`・`--log`・PR 本文・コミットの本文・agent の指示のどこにも値は入りません。

[[workflow-reference-provide]]
=== provide

手元のチェックアウトで git が無視しているファイルのうち、実行の worktree にコピーするものです（xref:workflows-provide[worktree に無いファイルを用意する]）。

[source,yaml]
----
provide: [docs/spec/**, e2e/fixtures/**]
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`provide`
|glob の list
|任意（既定 `[]`）
|固定のディレクトリかファイル名で始まる glob（`**/*.txt` は拒否: `must start with a fixed directory or file name`）。`.aidev`・`.git`・protected のパス（`never copied into a run`）、最後の名前が認証情報のファイルに見えるもの（`.env`、`.env.*`、`.npmrc`、`.netrc`、`.pypirc`、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`。`credentials never go into a run`）は検証で拒否します。
|===

* 最初のステップの前に（始めるたび。`--resume` も）、glob に一致する **無視されているファイル** を 1 ファイルずつ worktree の同じパスにコピーします（上書き）。追跡されているファイルは HEAD の内容が worktree にあり、追跡も無視もされていないファイルはコピーしません。`docs/spec/**` は docs/spec の下の無視されているすべてのファイルです。
* `secrets_paths` に一致するもの、`.aidev/`・`.git/` の下、シンボリックリンクはコピーしません（ログに `provide: <path> not copied (<理由>)`）。
* 無視されているファイルに 1 つも一致しない glob があると、`--dry-run` と実行は始める前に止まります（`provide: <glob> matches no file that git ignores in <チェックアウト> (…)`）。
* コピーしたファイルを無視する規則が、コミット済みの `.gitignore` に無ければ止まります（`provide: <file> is ignored in <チェックアウト> by a rule the repository does not carry; commit the .gitignore that ignores it, …`）。
* ログに `provide: N path(s) copied from the checkout: …`。`--dry-run` に `provide` の行、提出の PR 本文に `## Provided from the checkout` の節が出ます。

[[workflow-reference-never-commit]]
=== never_commit

ADK の既定の一覧に加えて、実行が決してコミットしないパスです（xref:workflows-never-commit[決してコミットしないもの]）。

[source,yaml]
----
never_commit: [e2e/test-results/**, e2e/playwright-report/**]
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`never_commit`
|glob の list
|任意（既定 `[]`）
|追跡されていないファイルのうち、どのステップの `writable` の中にあってもコミットしないもの。`<dir>/**` の形で、どれかのステップの `writable` の項目や `provide` の項目を覆うものは検証で拒否します（`never_commit <glob> covers what step <id> may write (…)`、`never_commit <glob> covers provide <glob>`）。
|===

ADK の既定の一覧です。これに一致する追跡されていないファイルは、`never_commit` を書かなくてもコミットされません。一覧から外すことはできません。

[source,text]
----
**/node_modules/**
**/bower_components/**
**/.pnpm-store/**
**/.yarn/cache/**
**/.venv/**
**/venv/**
**/__pycache__/**
**/*.pyc
**/.pytest_cache/**
**/.mypy_cache/**
**/.ruff_cache/**
**/.tox/**
**/.nox/**
**/.gradle/**
**/.DS_Store
**/Thumbs.db
**/*.orig
**/*.rej
----

* 対象は追跡されていないファイルだけです。git が追跡しているファイルへの変更は、どこにあってもコミットされます。
* チェックポイント、pull-request step の最後のコミット、`unchanged` の比較、失敗した件の戻し、確認役に見せる差分、新しい実行の前の未コミットの変更の検査に効きます。
* 外したものは、pull-request step のログ（`N file(s) left out as never committed (<glob>; e.g. <path>)`）、`run.json` のそのステップの `leftOut`、実行の終わりの表示（`left out, never committed: …`）、PR 本文の `## Left out` に出ます。`--dry-run` に `never commit` の行、提出の PR 本文に `## Never committed` の節が出ます。

[[workflow-reference-agent-step]]
=== agent step

agent を起動して仕事をさせるステップです。`agent` を持つステップが agent step です。

[cols="1,1,1,1,4",options="header"]
|===
|項目 |型 |必須 |既定 |説明

|`id`
|文字列
|任意
|`step-<番号>`
|ステップの名前。workflow の中で重複できません。小文字・数字・ハイフン、32 文字まで。実行記録のファイル名と `--resume` の表示に使います。

|`description`
|文字列
|任意
|なし
|レビューする人向けの説明。`--dry-run` と提出の PR 本文に出ます。agent には渡しません。

|`agent`
|文字列
|必須
|
|起動する agent の名前（英数字と `. _ -`）。`.aidev/agents/<name>.md`、無ければ ADK 同梱のものを使います。

|`prompt`
|文字列
|必須
|
|このステップでさせること。`for_each` があるときは `{item}` が必須です。`{inputs.<name>}` も書けます（xref:workflow-reference-inputs[inputs]）。

|`writable`
|glob の list
|必須
|
|このステップの agent が書けるパス。`[]` なら何も書けません。PKG のルートからの相対パスで、`/` で始まるもの、`..` を含むもの、protected のパス（`.claude/**`、`.aidev/policy.yaml` など。xref:permissions[権限と安全性]）は書けません。

|`unchanged`
|glob の list
|任意
|`[]`
|このステップが変えてはいけないパス。`writable` の中でも書けず、試行のたびに、ステップを始めたときの状態と比べます（xref:workflows-unchanged[変えてはいけない場所を決める]）。

|`env`
|mapping
|任意
|`{}`
|このステップの agent と、その `until` のコマンドの環境に足す固定の環境変数（`NAME: value`）。テストやツールが読む設定（対象環境の URL など）を渡します。command step の `env` と同じ規則で、`{inputs.<name>}` を書くとその入力は「コマンドに届く」扱いになります。`until.env` はこの上に重なります。agent の指示には `Your environment also has these set for this step` として名前と値が入ります。**秘密情報は書きません**（`env_required` で環境変数の名前を宣言します）。

|`for_each`
|mapping
|任意
|なし
|対象ごとに agent を新しく起動して繰り返します（xref:workflow-reference-for-each[for_each]）。

|`until`
|mapping
|任意
|なし
|ステップの終わりの判定。満たすまで agent を繰り返します（xref:workflow-reference-until[until]）。

|`timeout_minutes`
|数値
|任意
|30
|agent 1 回の起動の時間の上限（分）。0 より大きく 240 以下（`0.5` も可）。workflow の残り時間の方が短ければ、そちらで打ち切ります。
|===

[[workflow-reference-until]]
==== until

`command` と `agent` のどちらか、または両方を書きます。両方あるときは、コマンドがすべて通ってから agent が確認します。

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`command`
|文字列、または文字列の list
|`agent` が無ければ必須
|exit 0 になれば合格のコマンド。list は上から順に実行し、最初に失敗したところで不合格です。shell を通さないので、引用符・パイプ・リダイレクト・変数（`\|&;<>$"'` とバッククォート、`\`）は書けません。`{inputs.<name>}` は引数として書けます（実行ファイルにはできません。その入力には `pattern` か `path`・`file` が要ります）。

|`cwd`
|文字列
|任意
|コマンドを実行するディレクトリ（PKG の中）。省略すると PKG のルート。絶対パスと `..` は書けません。`command` があるときだけ書けます。

|`env`
|mapping
|任意
|コマンドに渡す環境変数（`名前: 値`）。値は 1 行の固定の文字列です。`AIDEV_` か `GIT_CONFIG` で始まる名前は書けません。PR でレビューされる値なので、秘密情報は書きません。`command` があるときだけ書けます。値に `{inputs.<name>}` を書けます（コマンドに届く入力と同じ規則です）。

|`timeout_minutes`
|数値
|任意
|コマンド 1 つの時間の上限（分）。0 より大きく 240 以下。`command` があるときだけ書けます。

|`agent`
|文字列
|`command` が無ければ必須
|確認役の agent。何も書けません。最終メッセージの最後の `VERDICT: PASS` 行で合格です（xref:workflows-until-agent[agent のレビューで終わりを判定する]）。

|`prompt`
|文字列
|`agent` があれば必須
|確認役に確認させる観点。`{inputs.<name>}` も書けます。

|`max_retries`
|整数
|任意（既定 3）
|不合格のとき、最初の試行の後に何回まで agent をやり直すか。0〜10。0 ならやり直しません。`unchanged` の検査で不合格になったときも、この回数までやり直します。`until` が無いステップはやり直しません。
|===

[[workflow-reference-for-each]]
==== for_each

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`from`
|文字列
|必須
|対象の一覧のファイル名。その実行の notes ディレクトリ（実行の worktree の `.aidev/workflows/<name>/runs/<id>/notes/`）にあり、前のステップが書きます。英数字と `. _ -`、100 文字まで。

|`max_items`
|整数
|必須
|1 回の実行で扱う件数の上限。1〜10000。一覧がこれを超えると、agent を起動せずに止まります。

|`on_failure`
|`stop` か `continue`
|任意
|1 件が失敗したとき。`stop`（既定）はそこで止まります。`continue` はその件の間に `writable` の中で変わったファイルを元に戻し、次の件へ進みます。全件が失敗したとき、費用・時間の上限に達したときは止まります（xref:workflows-unattended[人が介入せずに大きな仕事を走らせる]）。

|`parallel`
|整数
|任意（既定 1）
|同時に動かす件数。1〜16。2 以上のときは、ステップの `writable` のパスをすべて `{item}` を含む形（`e2e/tests/{item}.spec.ts` など）で書きます（xref:workflows-parallel[並列に動かす]）。
|===

一覧は 1 行 1 件です。空行と `#` で始まる行は飛ばし、行頭の `- ` と `* ` は取り除き、同じ行は 1 件にします。1 件は英数字と `. _ / @ -` の 1 語（200 文字まで、先頭は `-` 以外、`..` を含まない）です。

`{item}` は、`for_each` のあるステップの `prompt`（必須）、`writable`、`until.command`、`until.prompt` にだけ書けます。それ以外の場所に書くと検証で拒否されます。`writable` の `{item}` はその件の名前に置き換わり、その件の agent はそのパスにだけ書けます。`{item}` を含むパスは固定のディレクトリで始めます（`{item}/x.ts` は書けません）。pull-request step がコミットするのは、`{item}` より前のディレクトリ全体（`e2e/tests/{item}.spec.ts` なら `e2e/tests/**`）です。

[[workflow-reference-parallel]]
=== parallel グループ

agent step を同時に動かすステップです（xref:workflows-parallel[並列に動かす]）。

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`id`
|文字列
|任意
|グループの名前。ステップ id と同じ規則で、ステップ id と重複できません。

|`description`
|文字列
|任意
|レビュアー向けの説明。

|`parallel`
|list
|必須
|同時に動かす agent step（2〜16 個）。各要素は agent step と同じ項目を持ちます。`id` を省くと `<グループの id>-1` のように付きます。command step・pull-request step・グループは入れられません。
|===

* グループのステップは、`run.json`・`--resume`・見積もりでは普通のステップとして 1 つずつ扱われます。
* `writable` どうし、`writable` と他のステップの `unchanged` が重なり得ると検証で拒否されます。

[[workflow-reference-command-step]]
=== command step

ADK がコマンドを 1 回実行するステップです。exit 0 以外なら workflow はそこで止まります。agent は起動しません。

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`id`、`description`
|文字列
|任意
|agent step と同じです。

|`command`
|文字列
|必須
|実行するコマンド（1 行）。`until.command` と同じく shell を通しません。`{item}` は書けません。`{inputs.<name>}` は引数として書けます（実行ファイルにはできません）。

|`cwd`、`env`、`timeout_minutes`
|
|任意
|`until` の同名の項目と同じです。`timeout_minutes` を省略すると、workflow の残り時間まで（時間の上限が無ければ終わるまで）待ちます。

|`writable`
|glob の list
|任意
|コマンドが作るファイルのうち、pull-request step でコミットするもの。ADK 自身が実行するコマンドなので、書き込みの検問はかかりません。
|===

[[workflow-reference-pr-step]]
=== pull-request step

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`id`、`description`
|文字列
|任意
|agent step と同じです。

|`pull_request`
|mapping
|必須
|このキーを持つステップが pull-request step です。workflow に 1 つまでです。持てるのは `title` だけで、書かないときは `pull_request: {}` と書きます。

|`pull_request.title`
|文字列
|任意
|PR とコミットのタイトル。省略すると `aidev: <description、無ければ name>`。
|===

各ステップの変更は、ステップが通るたびにチェックポイントとしてコミット済みです。この step は、残った `writable` の範囲の変更と実行の記録を最後のコミットにし、ブランチ（`aidev/<name>`、`--dated` なら `aidev/<name>-<yyyymmddHHMM>`）を push して PR を作ります（Azure DevOps。同じブランチの PR が開いていれば本文を更新）。ブランチに起点からの変更が無ければ何もしません。追跡されていないファイルのうち ADK の既定の一覧と `never_commit` に一致するものはコミットせず、外した件数をログと PR 本文（`## Left out`）に書きます（xref:workflow-reference-never-commit[never_commit]）。`--trial` の実行では最後のコミットまで行い、push と PR は行いません（xref:workflows-trial[承認の前に試す]）。

[[workflow-reference-limits]]
=== limits

[cols="1,1,1,1,4",options="header"]
|===
|項目 |型 |必須 |既定 |説明

|`limits.max_usd`
|数値
|必須
|
|費用の上限（USD）。AI ツールが報告した費用の合計がこれに達すると、次の agent を起動せずに止まります。動いている agent は止めないので、最後の 1 回分だけ超えることがあります。費用を報告するのは Claude Code だけです。見積もりは xref:cli-estimate[aidev estimate] で出せます。`aidev run workflow --max-usd` で、その実行だけ下げられます（上げられません）。

|`limits.max_minutes`
|整数
|任意
|なし
|workflow 全体の時間の上限（分）。上限の値はありません。書かなければ、時間では止めません。Claude Code 以外の AI ツールで動く agent があるときは必須です（費用が報告されず、`max_usd` で止められないため）。`aidev run workflow --max-minutes` で、その実行だけ下げられます（書いていなければ、その実行だけ時間の上限を付けられます）。
|===

[[workflow-reference-agent]]
=== agent 定義（`.aidev/agents/<name>.md`）

frontmatter と本文の Markdown です。`aidev create agent <name>` で雛形を書けます。

[source,markdown]
----
---
name: e2e-writer
description: 画面ごとに Playwright のテストを書く。e2e-tests workflow から起動される
skills: [test-and-verify]
tools: Read, Grep, Glob, Edit, Write
mcp: []
model: inherit
---

# e2e-writer

（役割、入出力、手順、止まる条件）
----

[cols="1,1,1,4",options="header"]
|===
|項目 |型 |必須 |説明

|`name`
|文字列
|推奨
|ファイル名と同じにします（英数字と `. _ -`）。ADK が探すのはファイル名です。

|`description`
|文字列
|推奨
|いつ起動され、何をするか。`aidev list agents` と、workflow-creator が agent を選ぶときに使います。

|`skills`
|list（`[a, b]` か `a, b`）
|任意
|指示に本文を入れる skill。PKG、ADK 同梱の順に探し、どちらにも無ければ workflow は検証で止まります。workflow の `agents:` で、その workflow だけ足せます（xref:workflow-reference-agents[agents]）。

|`tools`
|list
|任意
|使える組み込みツール（`Read`、`Edit`、`Bash` など）。省略するとツールの既定のすべてです。Claude Code はこれだけを渡して起動し、hook も他のツールを拒否します。

|`mcp`
|list
|任意
|使える MCP server（PKG の `.mcp.json` のキー）。省略すると MCP server を渡しません。`.mcp.json` に無い名前があると、workflow は起動前に止まります。

|`subagents`
|list
|任意
|この agent が `Agent` ツールで起動できるサブエージェント（`.aidev/agents/<name>.md` の名前）。書くとこれ以外は起動できません。省略すると AI ツールが用意するものを使えます。`tools` を書くなら `Agent` を含めます。サブエージェントの `tools`・`mcp` はこの agent の範囲内でなければならず、サブエージェント自身は `subagents` を持てません（xref:workflows-subagents[サブエージェントを指定する]）。

|`model`
|文字列
|任意
|`inherit` にします。workflow から起動するときは使われず、workflow の `model` と `aidev.yaml` の設定に従います。サブエージェントは親の agent と同じモデルで動きます。
|===

* `tools` か `mcp` を書いた agent は、Claude Code でだけ動きます（他の AI ツールは渡すツールを絞れないため、起動前に止まります）。
* 外部システムに触る agent に `Bash` を渡さないでください。`mcp` で絞っても、`Bash` があれば MCP を通さずに外へ出られます。
* 能力は workflow ごとに `agents:` で足せますが、ステップごとに変える項目はありません。同じ workflow の中で権限が違う仕事は agent を分けます。
* agent を直すと、その agent を使うすべての workflow が変わります。

本文は、ADK が agent step の指示の先頭に入れます。その後ろに、ADK が次のものを足します。本文に同じことを書く必要はありません。

[cols="1,3",options="header"]
|===
|ADK が足すもの |中身

|Workflow と Objective
|workflow の名前、`description`、`objective`

|Task for this run
|`--task` の内容（データとして）

|Inputs for this run
|`--input` の値（データとして。`{inputs.<name>}` と書いた場所にはすでに入っています）

|Reports from the earlier steps
|前の agent step の最終報告（ステップごとに末尾 6000 文字）

|Notes of this run
|notes ディレクトリの場所と、いまあるファイル

|Step
|ステップの `prompt`。`for_each` なら今回の対象。やり直しなら前回の失敗の内容

|Rules
|書ける場所（`writable`）、変えてはいけない場所（`unchanged`）、commit しないこと、最終報告に書くこと

|Reference documents
|`aidev.yaml` の `references` のパス一覧（xref:configuration[aidev.yaml リファレンス]）
|===

確認役（`until.agent`）には、ステップの `prompt`、ステップの agent の報告、変わったファイルの一覧、差分のファイルの場所、`until.prompt`、`VERDICT:` 行で終える決まりが渡ります。

[[workflow-reference-skill]]
=== skill 定義（`.aidev/skills/<name>/SKILL.md`）

[source,markdown]
----
---
name: deploy-checklist
description: リリース前に確認する項目と順番
---

# deploy-checklist

1. ...
----

[cols="1,1,4",options="header"]
|===
|項目 |必須 |説明

|`name`
|推奨
|ディレクトリ名と同じにします。ADK が探すのはディレクトリ名です。

|`description`
|推奨
|いつ使う手順か（1 文）。

|本文
|必須
|手順。agent の frontmatter の `skills` に名前があると、その agent の指示に本文がそのまま入ります。
|===

[[workflow-reference-records]]
=== 実行記録（`runs/<id>/run.json`）

`aidev run workflow` が、実行の worktree の `.aidev/workflows/<name>/runs/<id>/` に実行しながら書きます（gitignore 済み）。見積もり（xref:cli-estimate[aidev estimate]）・`--resume`・`aidev modify --from-run` は、手元のチェックアウトと各 worktree の `run.json` を合わせて読みます。

[cols="1,4",options="header"]
|===
|項目 |中身

|`runId`、`name`、`hash`
|実行の id（開始時刻）、workflow の名前、開始時の `workflow.yaml` の hash

|`approvedRef`、`approvedSha`
|承認の基準にした ref（`origin/main` など）と、その commit。`--trial` の実行では両方 `null`

|`trial`、`trialHash`
|`--trial` の実行なら `true` と、始めたときのレビュー対象のファイル（`workflow.yaml` と agent・skill）のハッシュ（`sha256:…`）。続けるときに同じであることを確かめます。試験でない実行は `false`（`trialHash` なし）

|`startedAt`、`finishedAt`、`startedBy`
|開始・終了の時刻と、実行したユーザー名（記録用）

|`branch`、`worktree`、`baseSha`、`task`、`inputs`
|動いたブランチ（`aidev/<name>`、`--dated` なら日付付き、`--trial` なら `aidev/<name>.trial`）、実行の worktree のパス、起点の commit、`--task` の内容、`--input` の値（`default` を含む。`file: true` の入力は実行記録の `inputs/` にあるコピーのパス）

|`steps`
|ステップごとの `id`、`kind`、`ok`、`attempts`、通ったときのチェックポイントのコミット（`checkpoint`）。agent step は最後の結果の要約（`result`）、確認役の報告（`review`）、コマンドの出力のファイル（`log`）、agent が拒否されたツール呼び出し（`denied`。`Write src/x.ts` のような行、20 件まで）。`for_each` は件ごとの `items`（件ごとの `checkpoint`。`on_failure: continue` で失敗した件は `failed: true` と `reason`）と、失敗した件の数（`failed`）。pull-request step は決してコミットしないものとして外した件数（`leftOut`。glob ごと）と、push したか（`pushed`。`--trial` では `false`）

|`calls`
|agent を起動するたびに 1 件: `step`、`role`（`agent` か、確認役の `until`）、`agent`、`item`（`for_each` の件）、`attempt`、`tool`、`model`、`ok`、`costUsd`、`durationMs`、拒否されたツール呼び出しの数（`denials`。あるときだけ）

|`done`、`stopReason`
|最後まで終わったか、止まった理由

|`agentRuns`、`costUsd`
|agent の起動回数と、報告された費用の合計（`--resume` した分も含む）

|`pr`、`resumes`
|作った PR（`--trial` では `{ ok: false, trial: true, reason, branch, description }`）、`--resume` した時刻と再開したステップ
