[[cli-reference]]
== CLIリファレンス

`aidev`はNode.js {node-min-version}以上で動くCommonJS CLIです。command routingの正本は`cli/bin/aidev.js`、optionの正本は各`cli/commands/*.js`の`FLAGS`です。

[[cli-general]]
=== 共通構文

[source,text]
----
aidev <command> [subcommand] [options]
----

helpとversionはrepository検出より前に処理されるため、Git repository外でも実行できます。

[source,bash]
----
aidev --help
aidev --version
aidev <command> --help
----

未知のcommandとoptionはエラーです。boolean flagは`--flag=false`形式も解釈します。`update`以外のcommandは、current directoryからGit rootを探索します。

[NOTE]
====
helpはcommand module単位でflagを表示します。同じmodule内の特定subcommandでは意味を持たないflagも表示・受理される場合があります。以下の各節で有効な使い方を確認してください。
====

[[cli-json]]
=== `--json`

`--json`はautomation向け出力を意図していますが、現行版では全経路が「stdoutに単一JSON documentだけ」という契約を満たしていません。特に`sync`、一部の`permission`、`task`、`workflow`経路ではhuman-readable textが先に出る場合や、dry-runでJSONを出さない場合があります。

新しいautomationでは、対象commandと失敗経路を実環境で検証してからparserを接続してください。`check`、`doctor`、`knowledge`、`init`、`kit apply`、`update`の主要JSON経路は分離を意識していますが、version更新時にもcontract testを推奨します。

[[cli-dry-run]]
=== `--dry-run`

`--dry-run`は原則としてworktreeへの変更を行いません。ただしfetchによるremote-tracking ref更新や、remote state cache更新などの副作用はあり得ます。network accessまで禁止するflagではありません。

[[cli-exit-codes]]
=== 終了コード

[cols="1,2,4",options="header"]
|===
|code |分類 |意味

|`0`
|OK
|commandが成功しました。

|`1`
|GENERAL
|一般エラー、agent失敗、workflow失敗です。

|`2`
|DRIFT
|static asset driftです。`check --strict`ではwarningの昇格にも使います。

|`3`
|PERMISSION
|policy未配置、policy違反、書き込み拒否です。

|`4`
|WIKI_INCONSISTENT
|`src`とknowledge対象SHAの不一致、または重大なWiki整合性エラーです。
|===

複数問題がある`check`では、drift、permission、Wikiの順序を考慮した実装上のcodeが返ります。出力内容も必ず確認してください。

[[cli-init]]
=== `aidev init`

wrapper固有設定、`.claude/`、`.aidev-lock`を初期化します。policyとWikiは別commandです。

[source,text]
----
aidev init [--dry-run] [--resume] [--yes] [--force]
           [--org <name>] [--project <name>]
           [--repository <name>] [--wrapper-repository <name>]
           [--name <package>] [--tracking-branch <branch>]
           [--agent-model <model>] [--json]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--dry-run`
|生成・更新予定を表示し、worktreeを書き換えません。

|`--resume`
|中断した初期化またはconfig再生成側の処理を継続します。Wiki buildのresumeではありません。

|`--yes`
|非対話実行を選択します。推測できない必須値は個別optionで渡します。

|`--force`
|既存kit assetの衝突を上書きし得ます。復旧用途に限定します。

|`--org` / `--project`
|Azure DevOps organizationとprojectを指定します。

|`--repository`
|対象PKG repository名を指定します。

|`--wrapper-repository`
|wrapper repository名を指定します。

|`--name`
|`package.name`を指定します。

|`--tracking-branch`
|PKGのtracking branchを指定します。

|`--agent-model`
|`model.agent`の初期値を指定します。

|`--json`
|結果をJSONで出力します。
|===

前提はGit wrapper repositoryです。`src/`がない場合は警告します。既存assetがkitと異なる場合は既定でexit 2です。

[[cli-update]]
=== `aidev update`

launcherが指すCLI専用checkoutを固定`origin/main`からfast-forward-onlyで更新します。callerのwrapperは対象外です。

[source,text]
----
aidev update [--dry-run] [--json]
----

CLI checkoutがclean、`main`、non-detachedで、remoteと分岐していない必要があります。fetchはdry-runでもremote-tracking refを更新し得ます。

[[cli-kit-apply]]
=== `aidev kit apply`

中央kitの管理対象をwrapperへ適用します。

[source,text]
----
aidev kit apply [--remote <name>] [--ref <ref>]
                [--dry-run] [--force] [--json]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--remote`
|更新元remoteです。通常は`upstream`です。

|`--ref`
|更新元refです。通常は`main`です。

|`--dry-run`
|fetchと差分計算を行い、worktree適用をしません。

|`--force`
|kit由来fileのlocal driftを破棄して適用します。

|`--json`
|結果をJSONで出力します。
|===

通常はclean worktreeとdriftなしが必要です。現行対象は`templates/claude-assets`、`CLAUDE.md`、`.mcp.json`、`cli`、`scripts`です。

[[cli-check]]
=== `aidev check`

static asset、policy、3SHA、Wiki hand editを検査します。

[source,text]
----
aidev check [--strict] [--json] [--no-remote]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--strict`
|remote ahead、pending proseなどのwarningもfailure（通常exit 2）にします。

|`--json`
|検査結果をJSONで出力します。

|`--no-remote`
|remote取得を行わず、local状態を中心に検査します。
|===

`.aidev-ejected`があるrepositoryでは管理解除済みとして検査をskipし、0を返します。

[[cli-doctor]]
=== `aidev doctor`

local実行環境とrepository構成を診断します。

[source,text]
----
aidev doctor [--json]
----

Node.js、platform、Git、repo shape、submodule、remotes、policy、model、PAT環境変数の存在、proxy、remote/3SHAを確認します。PAT値は表示しません。Claude Code、`npx`、Azure DevOps API loginの実試験はしません。

[[cli-plan]]
=== `aidev plan`

`init`、`kit apply`、`sync`に関係する概算と次の変更を表示します。

[source,text]
----
aidev plan [--json] [--no-remote]
----

worktreeは変更しませんが、remote state cacheを更新し得ます。

[[cli-knowledge]]
=== `aidev knowledge build|status`

[source,text]
----
aidev knowledge build [options]
aidev knowledge status [--json] [--no-remote]
----

moduleが受理するoptionは次のとおりです。

[cols="2,4",options="header"]
|===
|option |説明

|`--scope <glob>`
|buildのgeneration targetsを狭めます。evidenceは狭めません。

|`--refresh`
|差分と既存pendingを再評価してqueueします。

|`--resume`
|既存checkpointから継続します。

|`--dry-run`
|変更予定を表示します。

|`--json`
|結果またはstatusをJSONで出力します。

|`--force`
|検出したhand editなどを上書きし得ます。

|`--no-remote`
|主にstatusでremote確認を省略します。

|`--agent`
|knowledge-builderによるprose生成を有効にします。

|`--agent-name <name>`
|起動するAgent名を指定し、agent executionを有効にします。

|`--agent-timeout <ms>`
|agent timeoutを一時変更します。

|`--agent-model <model>`
|agent modelを一時変更します。
|===

`--agent-timeout`または`--agent-model`だけではagentを起動しません。buildには`src/`と有効なconfigが必要です。3SHA不一致はstatusでもexit 4になり得ます。

[[cli-permission]]
=== `aidev permission configure|reconfigure|show`

[source,text]
----
aidev permission configure [--approve] [--force] [--dry-run] [--json]
aidev permission reconfigure [--approve] [--force] [--dry-run] [--json]
aidev permission show [--json]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--approve`
|生成したcandidateを`.aidev/policy.yaml`へ昇格します。

|`--force`
|保護を弱める承認など、通常拒否される高リスク変更を明示します。

|`--dry-run`
|candidate内容と変更予定だけを表示します。

|`--json`
|結果をJSONで出力します。ただし一部承認・エラー経路のstdout混在に注意します。
|===

初回は`configure`、既存policy変更は`reconfigure`を使用します。`show`はpolicy未配置時にbuilt-in floorを表示し、exit 3になります。

[[cli-sync]]
=== `aidev sync`

PKG tracking branchへの追従、structured Wiki更新、任意prose生成、commit/push、wrapper PRを処理します。

[source,text]
----
aidev sync [--to <sha>] [--dry-run] [--no-pr]
           [--resume | --abort] [--check-only]
           [--json] [--force]
           [--agent] [--agent-name <name>]
           [--agent-timeout <ms>] [--agent-model <model>]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--to <sha>`
|fetch済みtracking tipから到達可能なtarget commitを指定します。

|`--dry-run`
|targetと変更予定を確認します。fetchは発生し得ます。

|`--no-pr`
|wrapper PRを作らずlocal結果を残します。

|`--resume`
|残存sync leaseに対応する処理を続行します。

|`--abort`
|`src`をoriginal SHAへ戻してsync leaseを解放します。

|`--check-only`
|同期状態の検査を中心に実行します。

|`--json`
|JSON出力を意図しますが、現行経路ではheadingやstatus textが混在する場合があります。

|`--force`
|一部安全検査を越える復旧optionです。通常運用では使用しません。

|`--agent` / `--agent-name`
|prose Agentを起動します。

|`--agent-timeout` / `--agent-model`
|agent実行のtimeoutとmodelを一時変更します。
|===

config、初期化済み`src/`、tracking branch fetchが必要です。失敗時はleaseを意図的に残します。

[[cli-task]]
=== `aidev task list|show|resume|advance|abandon`

既存の`.aidev/tasks/*.json`を操作する部分実装です。task作成commandとAzure DevOpsからのcache再構築はありません。

[source,text]
----
aidev task list [--all] [--json]
aidev task show <task-id> [--json]
aidev task resume <task-id> [--dry-run] [--json]
aidev task advance [<task-id>] [--state <state>] [--reason <text>]
                    [--dry-run] [--json]
aidev task abandon <task-id> [--reason <text>] [--dry-run] [--json]
----

moduleは`--json --all --dry-run --force --state --reason --no-remote`を受理しますが、`--force`と`--no-remote`は現行実装で意味を持たない経路があります。bulk `advance`はlocal cached taskだけを列挙し、必要なPR stateをAzure DevOps APIで再確認します。fresh CI agentではcacheがなくno-opになり得ます。

[[cli-workflow]]
=== `aidev workflow new|approve|run|list`

[source,text]
----
aidev workflow new <name> [--force] [--dry-run] [--json]
aidev workflow approve <name> [--dry-run] [--json]
aidev workflow run <name> [--max-iterations <n>] [--max-minutes <n>]
                         [--resume] [--dry-run] [--json]
aidev workflow list [--json]
----

moduleは`--json --force --dry-run --yes --max-iterations --max-minutes --resume`を受理します。`--yes`は現行実装で意味を持ちません。

nameは小文字英数字で始まり、小文字英数字とdashだけ、最大64文字です。`new`は`workflow.yaml`と`steps.js`を固定scaffoldします。`approve`は両fileのcontent hashを`approval.json`へ保存します。`run`はapproved bytesだけを実行し、hard ceilingは10 iterations、60分、同一failure 3回です。

[[cli-eject]]
=== `aidev eject`

kit管理からrepositoryを外します。

[source,text]
----
aidev eject --dry-run [--keep-assets]
aidev eject --yes [--keep-assets] [--force] [--json]
----

[cols="2,4",options="header"]
|===
|option |説明

|`--yes`
|高影響操作への明示確認です。

|`--dry-run`
|削除・保持予定だけを表示します。必ず先に実行します。

|`--json`
|結果をJSONで出力します。

|`--force`
|有効leaseなどの保護を越え得ます。緊急復旧用途です。

|`--keep-assets`
|`.claude/`などのstatic assetを残します。
|===

`src/`、`knowledge/`、`aidev.yaml`、`workflows/`は既定で残し、`.aidev-ejected`を作ります。branch policyとCIは別途、人間が解除します。

[[cli-internal]]
=== 内部command

==== `aidev hook`

[source,text]
----
aidev hook session-start|guard-write|quality-gate|session-stop
           [--input <json>] [--json]
----

Claude hookのJSON stdin contractです。通常の対話操作には使用しません。

==== `aidev mcp azure-devops`

[source,text]
----
aidev mcp azure-devops [--dry-run] [--json]
----

PAT、organization、projectを実行時に解決し、固定版Azure DevOps MCPをstdio起動します。`--dry-run`と`--json`では解決情報を表示し、serverを起動しません。
