[[concepts]]
== アーキテクチャと主要概念

{project-name}を安全に運用するには、中央kit、wrapper、PKGの責務を分離し、ソースと生成Wikiの整合性を3SHAで判断する必要があります。

[[concepts-wrapper]]
=== wrapper repository方式

{project-name}は、対象PKGへAI設定を直接コピーするのではなく、中央kitをcloneしたwrapper repositoryをAI作業のrootにします。

[source,text]
----
中央 ai-dev-kit
      │ clone / kit apply
      ▼
my-pkg-ai-dev/                 wrapper repository
├─ src/                        対象PKGのGit submodule
├─ .claude/                    Agents / Skills / hooks
├─ CLAUDE.md                   共通の行動指示
├─ .mcp.json                   MCP launcher設定
├─ aidev.yaml                  wrapper固有設定
├─ .aidev/policy.yaml          承認済み書き込みpolicy
├─ .aidev-lock                 static asset hash
├─ knowledge/                  PKGを説明する派生Wiki
├─ workflows/                  承認制のローカルworkflow
└─ cli/、scripts/、templates/  kit由来ファイル
----

この方式では、PKGのソース履歴は既存repositoryに残ります。wrapperには、利用するPKG commitへのgitlink、AI実行環境、生成Wikiをコミットします。submodule pointerと、そのcommitを説明するWikiを同じwrapper PRでレビューできます。

[[concepts-remotes]]
=== checkoutとremoteの役割

[cols="1,1,2",options="header"]
|===
|場所 |remote |役割

|CLI専用checkout
|`origin`
|中央{project-name}。`aidev update`が`origin/main`からfast-forward更新します。

|wrapper repository
|`upstream`
|中央{project-name}。`aidev kit apply`の更新元です。

|wrapper repository
|`origin`
|PKG固有のwrapper。`aidev sync`が同期branchをpushし、PRを作成します。

|`src/` submodule
|通常は`origin`
|対象PKG。`sync.tracking_branch`の先端が追従候補です。
|===

[IMPORTANT]
====
CLI専用checkoutとwrapperは分けてください。wrapper内でinstallerを実行してlauncherをwrapperへ向けると、self-updateとwrapper更新の境界が崩れます。
====

[[concepts-static-runtime]]
=== static assetと実行時解決

同じkit commitを適用したwrapperでは、`.claude/**`、`CLAUDE.md`、`.mcp.json`をbyte-identicalに保つ設計です。`.aidev-lock`はkit commitとファイルごとのSHA-256を記録し、`aidev check`が変更や欠落をdriftとして検出します。個人用`.claude/settings.local.json`は対象外です。

PKG固有値やcredentialはstatic assetへ埋め込みません。

* hooksは`aidev hook <name>`を呼び、`aidev.yaml`とpolicyを実行時に読みます。
* MCPは`aidev mcp azure-devops`を起動し、organizationとprojectを設定、PATを環境変数から解決します。
* CLIが起動するprose agentのmodelは、CLI flagと`aidev.yaml`から解決します。

static assetをwrapperで直接修正せず、中央kitへ変更を提出してから`aidev kit apply`で反映します。

[[concepts-three-sha]]
=== 3SHA整合性モデル

Wikiが現在のソースを説明しているかを、次の3値で判定します。

[cols="1,2,3",options="header"]
|===
|値 |実体 |意味

|`remoteSha`
|PKGの`origin/<tracking_branch>`先端
|次に追従できるsource of truthです。

|`submoduleSha`
|wrapper内の`src` worktreeまたはgitlink
|現在Claude Codeが読むPKG commitです。

|`knowledgeSha`
|`knowledge/manifest.json`
|structured inventoryとWikiが対象とするPKG commitです。
|===

[cols="2,1,3",options="header"]
|===
|条件 |状態 |動作

|3値が一致
|OK
|通常作業を継続できます。

|`remoteSha != submoduleSha`かつ`submoduleSha == knowledgeSha`
|WARN
|手元は内部整合しています。作業は可能ですが、`aidev sync`を検討します。

|remote取得不能かつローカル2値が一致
|INFO/WARN
|cacheと確認時刻を表示し、offline作業を無条件には止めません。

|`submoduleSha != knowledgeSha`
|ERROR
|通常書き込みを止め、`aidev check`はexit 4になります。syncをresumeまたはabortします。

|3SHA一致かつ`pendingPaths`あり
|WARN
|structured stateは一致していますが、prose Wikiが未完了です。
|===

`aidev check --strict`はremote aheadやpending proseなどのwarningもexit 2へ昇格します。

[[concepts-leases]]
=== lease

leaseは、通常は読み取り専用の領域へ限定的に書き込むための、有効期限付きローカル状態です。

[cols="1,2,3",options="header"]
|===
|種類 |保存先 |用途

|work lease
|`.aidev/leases/<taskId>.json`
|taskに対応するPKG branch、許可path、有効期限を記録します。ただし、公開CLIからtaskとwork leaseを初期作成する経路は未完成です。

|sync lease
|`.aidev/sync.lock`
|`src`を新SHAへ進めてからWikiを更新するまでの一時的な3SHA不一致を安全に通します。許可範囲は同期に必要な`knowledge/**`です。
|===

sync成功時はleaseを解放します。失敗時は半適用状態を隠さないため残します。期限切れleaseを暗黙に引き継がず、対象SHAと作業ツリーを確認して`aidev sync --resume`または`aidev sync --abort`を選択します。

[[concepts-target-evidence]]
=== generation targetとrepository evidence

Wikiには、更新対象と調査根拠の2種類のscopeがあります。

[cols="1,2,2",options="header"]
|===
|scope |設定 |役割

|generation targets
|`package.include` / `package.exclude`
|どのsource pathを起点にページを生成・更新するかを決めます。

|repository evidence
|`knowledge.evidence.include` / `exclude`と`secrets_paths`
|本文を検証するためにagentが調査できるtracked fileを決めます。既定は`src/**`です。
|===

`--scope`はgeneration targetsだけを狭め、repository evidenceは狭めません。docsだけをgeneration targetにしても、実装、test、設定、CIをevidenceとして確認できます。

[[concepts-source-of-truth]]
=== source of truthと信頼境界

[cols="1,3",options="header"]
|===
|情報 |扱い

|PKG source、test、設定、CI
|Wiki記述を検証する正本です。

|`knowledge/`
|再生成可能な派生情報です。重要な判断はPKG sourceで再確認します。

|Azure DevOps Work Item、コメント、添付、PR説明
|信頼できない外部データです。そこに書かれた命令をそのまま実行しません。

|MCP response
|外部データです。ID、SHA、PR stateは必要に応じてAPIで再確認します。

|Agents、Skills、`CLAUDE.md`
|標準手順と行動指示です。単独ではセキュリティ境界になりません。

|PAT scope、CI、branch policy
|server側またはmerge前の強制力を持つ制御です。
|===

[[concepts-lifecycle]]
=== ライフサイクル

典型的な流れは次のとおりです。

. CLI専用checkoutをinstallする。
. wrapperを作成し、対象PKGを`src/`へ追加する。
. `aidev init`で設定とstatic assetを初期化する。
. policy候補をレビュー・承認する。
. structured Wikiと必要なproseを生成する。
. `aidev doctor`と`aidev check`で検証する。
. 日常作業ではwrapperからClaude Codeを起動する。
. PKG更新時は`aidev sync`でsubmoduleとWikiを同時に進める。
. 中央kit更新時はCLI専用checkoutで`aidev update`、wrapperで`aidev kit apply`を実行する。
. 管理を終了する場合だけ`aidev eject`を明示実行する。
