[[maintain-update]]
=== ADK の更新

新しい ADK があると、`aidev` コマンドを実行したときに次のように表示されます。これは Developer の端末にも出ます。

[source,text]
----
⚠ a newer ai-dev-kit is available (9491efe → e0aa66c). Run "aidev update".
  Update now, before running this command? (y/N):
----

`y` で ADK（CLI とテンプレート）を更新します。**PKG のファイルはこの時点では変わりません。** 更新できたら、実行しようとしたコマンドを新しい CLI でそのまま実行し直します。

[source,text]
----
✓ updated ai-dev-kit 0.3.0 → 0.4.0 (499f940 → 7c1d2e3)
ℹ 1 package(s) on this machine still carry templates from an older kit:
    demo-pkg (applied 499f940)
    Run "aidev sync tools --package <name>" for each when convenient; it merges the new templates with your edits.
----

[[maintain-workflow-v2]]
==== 2.0.0 の workflow.yaml の書き換え

ADK 2.0.0 向けに書いた workflow.yaml は、今の ADK では検証で拒否されます（`cost is not a workflow key; the budget is limits.max_usd now` など）。ADK の clone にある `scripts/convert-workflow-v2.ps1` で、今の書き方に書き換えます。

[source,powershell]
----
# PKG の .aidev/workflows/*/workflow.yaml をすべて。-WhatIf なら書かずに結果を表示する
powershell -ExecutionPolicy Bypass -File <ADK の clone>\scripts\convert-workflow-v2.ps1 -Path <PKG の clone> -WhatIf
powershell -ExecutionPolicy Bypass -File <ADK の clone>\scripts\convert-workflow-v2.ps1 -Path <PKG の clone>
----

[%autowidth.stretch,options="header"]
|===
|2.0.0 |今

|`cost: { max_usd: N }`
|`limits.max_usd: N`

|`limits.max_minutes` を省略（2.0.0 では 60 分）
|`limits.max_minutes: 60` を書き足す（`-NoTimeLimit` なら書き足さない）

|ステップの `timeout_ms: N`
|`timeout_minutes: N / 60000`

|ステップの `max_retries: N`
|`until.max_retries: N`

|`kind: pull-request` と `title: T`
|`pull_request: { title: T }`
|===

* 変えるのは上の項目だけです。コメントや他の行はそのまま残ります。今の書き方のファイルは変えないので、2 回実行しても同じです。
* 書き換えた結果は、`node` と ADK の検証で確かめてから書きます。検証を通らないファイルは書きません（`-Force` で書きます）。
* `-OutFile <path>`（入力が 1 ファイルのとき）で別のファイルに、`-Backup` で元を `workflow.yaml.v2.bak` に残します。
* 書き換えた workflow は承認前に戻ります。差分を確かめ、`aidev submit workflow <name>` で PR にします。

[[maintain-sync-tools]]
=== テンプレートの取り込み

ADK を更新したら、**Engineering Manager が** 都合のよいときに PKG のルートで実行し、PR にします。Developer はマージ後の `git pull` で同じ状態になります。チームが `.claude/` などのファイルを編集していても構いません。手を入れていないファイルは置き換わり、編集済みのファイルは ADK 側の変更とマージされます。

[source,bash]
----
aidev sync tools
----

[source,text]
----
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    Review with "git diff", then commit so your team receives the update.
----

同じ箇所をチームと ADK の両方が変えていた場合は、git と同じ衝突マーカーがファイルに書かれ、終了コード 2 で止まります。

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
----

マーカーを解消して内容を確定したら、もう一度 `aidev sync tools` を実行して記録を更新し、コミットします。解消するまで `aidev check` は終了コード 2 を返します。全ファイルを ADK 版に戻したいときは `aidev sync tools --force` です。

[[maintain-model]]
=== モデルの変更

モデルの指定先は 2 つあります。`aidev` が自分で起動する agent（Wiki 更新、workflow、`aidev create`）のモデルと、Developer が対話で使う AI ツール自身のモデルです。

==== aidev が起動する agent

`aidev.yaml` の `tools.agent_model` を変えて PR にします。特定の agent だけ変えるときは `tools.agents.<name>.model` を足します。

[source,yaml]
----
tools:
  agent: claude
  agent_model: "sonnet"           # 既定。"" にするとモデルを渡さずツールに任せる
  agents:
    knowledge-builder: { model: opus }
----

値は `sonnet` や `opus` のような別名でも、`claude-opus-5` のような正式な ID でも構いません。`aidev` は文字の形式だけを確かめ、そのまま各ツールの `--model` に渡します。存在しないモデルは agent の起動時にツール側のエラーになります。

同じ agent に複数の指定があるときは、次の順で優先します。

. その 1 回だけの指定。`aidev sync wiki` では `--agent-model <model>` フラグ（`""` で設定済みのモデルを外す）、`aidev run workflow` では workflow.yaml の `model`
. `tools.agents.<name>.model`
. `tools.agent_model`

今どのモデルで動くかは `aidev doctor --package <name>` の `agent tool` 行で確認できます。

==== 対話セッション

`aidev.yaml` は対話セッションに影響しません。Claude Code のモデルは PKG の `.claude/settings.json` の `"model"`（ADK の初期値は `sonnet`）で決まります。チーム全体で変えるならこのファイルを編集して PR にします。編集した内容は `aidev sync tools` でも保持されます。Developer が自分だけ変えるときは `.claude/settings.local.json`（ADK の管理外）か、セッション中の `/model` を使います。Copilot などほかのツールのモデルは、そのツール自身の設定で変えます。
