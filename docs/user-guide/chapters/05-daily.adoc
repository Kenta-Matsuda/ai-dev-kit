[[daily]]
== 日常の使い方

メンバーが毎日することは 3 つです。作業前に `aidev check` を見る。コミットしたら hook の指示どおり Wiki を追従させる（手動なら `aidev sync wiki`）。AI に任せる仕事は `aidev run workflow` で実行し、できた PR をレビュアーに渡す。

kit が新しいと言われたら `aidev update` します。PKG への取り込み（`aidev sync tools`）は導入担当者が PR にします。

[[daily-check]]
=== aidev check の読み方

[source,bash]
----
aidev check
----

2 行目の記号と文で、次にすることが決まります。

[%autowidth.stretch,options="header"]
|===
|表示 |すること

|`✅ the Wiki describes HEAD (…)`
|何もしなくて構いません。

|`⚠️ the Wiki describes … but N file(s) differ at HEAD … — run "aidev sync wiki"`
|コードが進んで Wiki が古くなっています。AI ツールの中なら次のコミット後に hook が更新を始めます。今すぐなら xref:daily-wiki[aidev sync wiki]。作業は続けられます。

|`⚠️ N page(s) still await prose regeneration`
|本文が未生成のページがあります。`aidev sync wiki` を実行します（hook の指示が出ていればそのとおりに）。

|`⚠️ origin/main has moved ahead …`
|`main` があなたの作業ブランチより先に進んでいます。区切りの良いところで merge か rebase をし、`aidev sync wiki` を実行します。

|`⚠️ origin/main has new commits …`
|`git fetch` してから `aidev check` をもう一度実行します。

|`ℹ️ remote unverified …`
|remote に届きませんでした（offline や proxy）。手元は整合しているので作業は続けられます。

|`❌ LLM Wiki has not been generated yet …`
|Wiki がありません。**この間、AI の書き込みはすべて止まります。** `git pull` で来るはずなら pull します。来ないなら導入担当者に確認するか、`aidev init` を実行します。
|===

その他の表示は xref:troubleshooting-status[トラブルシューティング] を見てください。

続く行では、`tool config` と `policy` を確認します。`tool config` は `applied from kit <sha>` で始まり、チームが編集したファイル数（`customised`）や、新しいテンプレートがあること（`newer templates available: "aidev sync tools"`）を添えます。`CONFLICTS` なら `aidev sync tools` の衝突が未解消、`kit hooks missing` なら `.claude/settings.json` から hooks が消えています（xref:daily-apply[aidev sync tools]）。`policy` が `missing` なら導入担当者に `aidev create policy --approve` を依頼します。

=== Wiki の使われ方

AI は `CLAUDE.md` の指示に従い、ソースを読む前に `.aidev/knowledge/index.md` と `overview.md` を読みます。Wiki の各記述は根拠ファイルへのリンクを持ち、AI はリンク先で裏を取ります。

あなたが Wiki を手で直す必要はありません。間違いを見つけたら、ソース側（コメントや構造）を直して、次の更新で反映させます。手編集は検出され、次の生成で `--force` を求められます（xref:knowledge-handedit[手編集しない理由]）。

[[daily-wiki]]
=== Wiki をコードに追従させる

Wiki は今いるブランチの HEAD を説明します。コードをコミットするたびに、Wiki も同じブランチに別のコミットとして積みます。

AI ツールのセッションで `git commit` すると、hook が構造を更新し、本文が必要ならセッションに「knowledge-builder をサブエージェントで起動し、終わったら `aidev sync wiki --no-agent` を実行する」と指示します。セッションがそのとおりに進めると、`.aidev/knowledge/` が `aidev: update Wiki for <sha12>` としてコミットされます。Wiki が遅れたままセッションを終えようとすると 1 回だけ止められます。

手動で行うなら次を実行します。生成対象に未コミットの変更があると止まるので、先にコミットします。

[source,bash]
----
aidev sync wiki
----

[source,text]
----
✓ manifest and 1 shard(s) written for 9f8e7d6
ℹ running the knowledge-builder agent: 7 generation target(s) in 1 batch(es) of up to 20
✓ batch 1/1 complete: 7/7 in 4m 2s ($0.5533)
✓ committed the Wiki as c0ffee1 (aidev: update Wiki for 9f8e7d6c5b4a)
----

ソースのコミットと Wiki のコミットを同じ PR に入れ、レビューする人は両方を見ます。

* 途中で止まったら同じコマンドで再開します。
* `main` の上で実行すると、`aidev/wiki-<sha12>` ブランチにコミットして PR を作ります（xref:knowledge-publish[tracking branch の上で更新する]）。
* 夜間 pipeline が `main` の Wiki を PR にしているチームでは、マージ後に `git pull` で受け取ります。

[[daily-workflow]]
=== AI に仕事をさせる

承認済みの workflow（`main` にマージされた定義）は、メンバーの誰でも実行できます。

[source,bash]
----
git fetch origin
aidev list workflows
aidev run workflow implement --task "Work Item 1234 を実装する"
----

workflow は自分のブランチ `aidev/<name>-<yyyymmddHHMM>` で動き、終わると PR を作ります（Azure DevOps。`generic` では push 済みのブランチから手で作ります）。**できた PR をレビュアーに渡すところまでがあなたの仕事です。** 中身の責任は、workflow を承認した人と PR をレビューする人にあります。

`main` にない workflow、`main` の内容から変えた workflow は実行できません。新しい仕事をさせたいときは導入担当者に相談します。詳しくは xref:workflows[AI に仕事をさせる] を見てください。

[[daily-update]]
=== aidev update — kit を更新する

新しい kit があると、PKG でコマンドを実行したときに次のように表示されます。

[source,text]
----
⚠ a newer ai-dev-kit is available (9491efe → e0aa66c). Run "aidev update".
  Update now, before running this command? (y/N):
----

`y` で kit（CLI とテンプレート）を更新します。PKG のファイルはこの時点では変わりません。更新できたら、実行しようとしたコマンドを新しい CLI でそのまま実行し直します。

[source,text]
----
✓ updated ai-dev-kit 0.3.0 → 0.4.0 (499f940 → 7c1d2e3)
ℹ 1 package(s) on this machine still carry templates from an older kit:
    C:\work\demo-pkg (applied 499f940)
    Run "aidev sync tools <package>" for each when convenient; it merges the new templates with your edits.
----

[[daily-apply]]
=== aidev sync tools — 新しいテンプレートを PKG に取り込む

kit を更新したら、**導入担当者** が都合のよいときに PKG のルートで実行し、PR にします。メンバーはマージ後の `git pull` で同じ状態になります。チームが `.claude/` などのファイルを編集していても構いません。手を入れていないファイルは置き換わり、編集済みのファイルは kit 側の変更とマージされます。

[source,bash]
----
aidev sync tools
----

[source,text]
----
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    Review with "git diff", then commit so your team receives the update.
----

同じ箇所をチームと kit の両方が変えていた場合は、git と同じ衝突マーカーがファイルに書かれ、終了コード 2 で止まります。

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
----

マーカーを解消して内容を確定したら、もう一度 `aidev sync tools` を実行して記録を更新し、コミットします。解消するまで `aidev check` は終了コード 2 を返します。全ファイルを kit 版に戻したいときは `aidev sync tools --force` です。

[[daily-review]]
=== レビュアーがすること

{project-name} を使う開発では、次の PR が届きます。いずれも人間がマージします。

[%autowidth.stretch,options="header"]
|===
|PR |誰が作るか |見るところ

|導入・設定の PR（`aidev.yaml`、`.aidev/policy.yaml`、`.claude/**` など）
|導入担当者
|`secrets_paths` に漏れが無いか。policy の `writable` を広げていないか。`aidev check` が通っているか。

|ソースと Wiki の PR
|メンバー
|ソースの変更に加えて、`aidev: update Wiki for <sha12>` のコミットが入っているか。Wiki の記述がソースと食い違っていないか（Wiki の各記述は根拠ファイルへのリンクを持ちます）。

|workflow の定義の PR（`aidev: workflow <name>`）
|導入担当者
|**マージが承認です。** `objective`（何をさせるか）、`scope.writable`（どこを書いてよいか）、`cost.max_usd` と `limits`（いくらまで、何分まで）、`until` と `command` の内容。参照する `.aidev/agents/`・`.aidev/skills/` のファイルも同じ PR に入ります。→ xref:workflows-review[workflow の PR を見る]

|workflow の成果物の PR
|メンバー（実行した人）
|PR 本文に workflow 名・run id・起点のコミット・費用が書かれています。差分が `scope.writable` の中に収まっているか、テストが通っているか、`objective` どおりか。
|===
