[[cli-task]]
== aidev task

issue-to-pr タスクの進行状態を扱います。

=== 書式

[source,text]
----
aidev task list [--all] [--json]
aidev task show <taskId> [--json]
aidev task resume <taskId> [--dry-run] [--json]
aidev task advance [<taskId>] [--state <STATE>] [--reason <text>] [--dry-run] [--json]
aidev task abandon <taskId> [--reason <text>] [--dry-run] [--json]
----

=== 説明

`issue-to-pr` agent が進めるタスクの状態を、ローカルキャッシュ `.aidev/tasks/<taskId>.json` で管理します。正本は Azure DevOps の PR と Work Item で、`advance` と `resume` は PR の状態を見て進めます。マージはしません。タスクの開始も行いません（`issue-to-pr` agent が行います）。

[source,text]
----
IMPLEMENTING → PKG_PR_OPEN → PKG_PR_MERGED → SYNCHRONIZING → WIKI_PR_OPEN → DONE
                   │              │              └── SYNC_FAILED ──(resume)──┘
                   └── PKG_PR_ABANDONED          WIKI_PR_ABANDONED / BLOCKED
----

=== サブコマンド

[%autowidth.stretch,options="header"]
|===
|サブコマンド |動作

|`list`
|未完了タスクを一覧する。`--all` で終了したものも含める

|`show <taskId>`
|状態、Work Item、ブランチ、PR、次に取り得る状態を表示する

|`resume <taskId>`
|進められるところまで進め、次に人間または agent がすることを表示する

|`advance [<taskId>]`
|PR の状態を見て 1 段階進める。id を省くと未完了タスクを順に処理する

|`abandon <taskId>`
|放棄し、作業リースを解放する。PR は閉じない
|===

=== オプション

[%autowidth.stretch,options="header"]
|===
|オプション |説明

|`--json`
|JSON で出力する

|`--all`
|`list`: 終了したタスクも含める

|`--dry-run`
|遷移を表示するだけで書かない

|`--state <STATE>`
|`advance <taskId>`: PR を見ずにこの状態へ進める（遷移図で許される場合のみ）

|`--reason <text>`
|`advance --state` / `abandon`: 記録に残すメモ
|===

=== 終了コード

[%autowidth.stretch,options="header"]
|===
|コード |条件

|0
|成功（進まなかった場合も 0）

|1
|タスク記録が無い、許されない遷移、PR API の失敗、`advance`（id 無し）で 1 つ以上失敗
|===

=== 例

[source,bash]
----
aidev task list
aidev task advance wi-4711
aidev task resume wi-4711
aidev task abandon wi-4711 --reason "requirements changed"
----

夜間 pipeline で全タスクを進める:

[source,bash]
----
aidev task advance
----
