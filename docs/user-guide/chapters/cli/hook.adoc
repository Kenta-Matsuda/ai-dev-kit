[[cli-hook]]
== aidev hook

AI ツールの hook から呼ばれる内部コマンドです。人が直接実行するものではありません。

=== 書式

[source,text]
----
aidev hook session-start [--tool <tool>]
aidev hook guard-write [--input <file>] [--tool <tool>]
aidev hook quality-gate [--input <file>] [--tool <tool>]
aidev hook after-bash [--input <file>] [--tool <tool>]
aidev hook session-stop [--input <file>] [--tool <tool>]
----

=== 説明

kit が置く hook 設定から AI ツールが起動します。stdin で hook の入力（JSON）を受け取り、stdout に判定（JSON）を返します。動作を確かめたいときは `--input <file>` で入力ファイルを渡せます。ネットワークにも LLM にも触れないので、ツールの hook の時間制限（既定 30 秒）に収まります。

[%autowidth.stretch,options="header"]
|===
|サブコマンド |いつ |動作

|`session-start`
|セッション開始
|Wiki の状態（`[ai-dev-kit] head=… knowledge=… tracking=…` と判定）と進行中の publish をセッションのコンテキストとして返す

|`guard-write`
|書き込みの前
|書き込み先のパスを policy で判定し、`allow` / `deny` と理由を返す。判定できないときは `deny`。`aidev run workflow` のステップの中では、いま動いているステップの `writable` で判定し、その agent の frontmatter（`tools`・`mcp`）に無いツールの呼び出しも `deny` にする。Claude Code では MCP ツールの呼び出しでも呼ばれる。workflow の外の MCP の呼び出しには何も返さない（許可するかは AI ツール自身の設定が決める）

|`quality-gate`
|ファイル編集の後
|PKG のファイルを編集した後に `quality_gates` を実行し、失敗の出力を返す

|`after-bash`
|シェルコマンドの後
|HEAD が変わり、Wiki が遅れていて木がきれいなら、構造の更新（inventory・manifest・ページ削除）を行う。改名だけならそのままコミットする。本文が必要なら `.aidev/knowledge/.cache/plan.json` を書き、batch ごとに knowledge-builder をサブエージェント起動して最後に `aidev sync wiki --no-agent` を実行するようセッションに指示する。生成対象に未コミットの変更があれば、そのファイルを挙げるだけで何もしない

|`session-stop`
|セッション終了
|Wiki が HEAD より遅れている（または本文が未完了）のに木がきれいなら、1 回だけ終了を拒否して `after-bash` と同じ指示を出す。2 回目は警告付きで通す。未コミットの変更があれば止めない。ai-dev-kit 開発者の端末ではさらに振り返りを求める
|===

=== ツールごとの hook 設定

`--tool` で出力の形をツールに合わせます。既定は `claude` です。

[%autowidth.stretch,options="header"]
|===
|ツール |hook 設定 |注意

|Claude Code
|`.claude/settings.json`
|実機で検証済み。`guard-write` は `PreToolUse` で、ファイルを書くツール・`Bash`・MCP ツール（`mcp__` で始まる名前）の前に呼ばれる。`after-bash` は `PostToolUse` の `Bash` matcher から呼ばれる

|GitHub Copilot CLI
|`.github/hooks/aidev.json`
|サブエージェントの中では hook が動かないため、knowledge-builder は agent 定義で `.aidev/knowledge/**` だけを書くよう制限している。未検証

|OpenAI Codex CLI
|`.codex/hooks.json`
|プロジェクトが trusted であること。初回の `codex` 起動時に答えるか、`~/.codex/config.toml` に `projects."<path>".trust_level = "trusted"` を書く。未検証

|Kiro CLI
|`.kiro/agents/aidev.json`
|hook は agent 定義の中にあるので、`kiro-cli chat --agent aidev` で起動する。`postToolUse` はコンテキストを注入できないため、指示は Stop hook が出す。サブエージェントの中では hook が動かない。未検証
|===

=== 終了コード

判定を返せば 0 です（`deny` でも 0。判定は JSON の中です）。hook 名や `--tool` が不明なら 1 です。

=== 例

`guard-write` の判定を手で確認する:

[source,bash]
----
cat > /tmp/hook.json <<'EOF'
{"tool_name":"Write","tool_input":{"file_path":"src/api/auth.ts"}}
EOF
aidev hook guard-write --input /tmp/hook.json
----

[source,json]
----
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "ai-dev-kit: \"src/api/auth.ts\" is read-only (**). this session was not started by \"aidev run workflow\"; PKG source is written only inside the writable of an approved workflow step. …"
  }
}
----
