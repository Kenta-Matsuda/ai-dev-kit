[[cli-sync]]
== aidev sync

この PKG を、進んだ側に追従させます。`tools` は ADK のテンプレートをこの PKG のツール設定へ、`wiki` は HEAD を LLM Wiki へ、`workflow <name>` は ADK の標準 workflow の新しい版を、この PKG が複製して直した workflow へ。

=== 書式

[source,text]
----
aidev sync tools [--package <name|path>] [--dry-run] [--force] [--json]
aidev sync wiki [--package <name|path>] [options]
aidev sync workflow <name> [--from <standard>] [--package <name|path>] [--dry-run] [--force] [--json]
----

`--package` を省略するとカレントの PKG が対象です。`--package` には xref:cli-list[`aidev list packages`] に出る名前か、PKG のパスを渡します。`aidev update` のあと、複数の PKG を 1 か所から追従させるときに使います。

[[cli-sync-tools]]
=== aidev sync tools

ADK の最新テンプレートを、この PKG の AI ツール設定に取り込みます。

端末にある ADK（`aidev update` で更新したもの）のテンプレートを、`aidev.yaml` の `tools.default` にあるツールぶん PKG に適用します。`aidev init` が初回に置いたファイルをチームが編集していても構いません。`apply` はコピーではなく **マージ** として動きます。

[%autowidth.stretch,options="header"]
|===
|ファイルの状態 |apply の動作

|前回の適用から手を入れていない
|新しいテンプレートに置き換える

|編集済みで、ADK 側は変わっていない
|そのまま残す

|編集済みで、ADK 側も変わった
|前回適用したテンプレートを基準に 3-way マージする。同じ箇所が変わっていれば git と同じ衝突マーカーを書き、終了コード 2 で止まる

|ADK が配布をやめた
|手を入れていなければ削除、編集済みなら残す

|`tools.default` にツールを足した
|そのツールのファイルを新しく置く
|===

衝突したファイルは PKG 開発チームが解消します。マーカーを消して内容を確定したら、もう一度 `aidev sync tools` を実行します。マーカーが消えたファイルは「解消済み」として記録され、`aidev check` が通るようになります。解消するまで `aidev sync tools` はそのファイルに触れず、`aidev check` は終了コード 2 を返します。

適用結果は PKG の通常の差分です。`git diff` で確認し、コミットして PR にします。マージ後、他の Developer は `git pull` だけで同じ状態になります。

マージの基準になるのは、前回適用時の ADK のコミットにあったテンプレートです。ADK の clone にその履歴が無い場合（shallow clone など）はマージできず、そのファイルは衝突として報告され、手で直すか `--force` で ADK 版にします。

==== オプション

[%autowidth.stretch,options="header"]
|===
|オプション |説明

|`--dry-run`
|何が変わるかを表示し、何も書かない（記録も更新しない）

|`--force`
|全ファイルを ADK 版に置き換える。ローカルの編集と衝突は捨てる

|`--json`
|JSON で出力する
|===

==== 終了コード

[%autowidth.stretch,options="header"]
|===
|コード |条件

|0
|適用した、または最新だった

|1
|`aidev.yaml` が無い、ADK にテンプレートが無い

|2
|衝突が残っている（新しく発生したもの、または前回のマーカーが未解消）
|===

==== 例

[source,bash]
----
aidev sync tools --dry-run
aidev sync tools
----

別の PKG を、どこからでも:

[source,bash]
----
aidev list packages
aidev sync tools --package demo-pkg
----

[source,text]
----
aidev sync tools
✓ applied 3 change(s) for claude
    ~ .claude/agents/knowledge-builder.md
    ~ CLAUDE.md (merged with your edits)
    - .claude/skills/old-skill/SKILL.md (no longer shipped)
    2 file(s) with local edits kept as they are
    Review with "git diff", then commit so your team receives the update.
----

衝突がある場合（終了コード 2）:

[source,text]
----
✗ 1 file(s) need your attention:
    ! .claude/settings.json — the kit and this package changed the same lines; conflict markers were written
    Resolve the conflict markers (or keep your version / take the kit's), then run "aidev sync tools" again
    to record the result. "aidev sync tools --force" takes the kit version of every file instead.
----

[[cli-sync-wiki]]
=== aidev sync wiki

今いるブランチの HEAD に合わせて LLM Wiki を更新し、`.aidev/knowledge/` を別コミットとして積みます。前回から変わったファイルと前回未完了のファイルだけを対象にし（差分）、消えたファイルのページを削除し、inventory と manifest を書いてから knowledge-builder agent を batch ごとに起動して本文を書きます。すべて終わったら `.aidev/knowledge/`（と `.aidev/.gitignore`）だけを `aidev: update Wiki for <sha12>` としてコミットします。

生成対象（`aidev.yaml` の `package.include`）に未コミットの変更があると、そのファイルを列挙して止まります。先にコミットするか stash します。`.aidev/knowledge/` や ADK の設定ファイルが汚れているのは構いません。

本文が残っている間は終了コード 1 で、コミットしません。`.aidev/knowledge/.cache/plan.json` に残りの batch が書かれます。同じコマンドをもう一度実行すると checkpoint から続きます。

`--no-agent` は inventory と manifest だけを書き、本文は未生成のまま残します（終了コード 1）。hook の指示でサブエージェントが本文を書いたあとの仕上げに使います。このとき完了報告を取り込み、残りが無ければコミットします。

`--no-commit` はコミットせず、更新した Wiki を作業ツリーに残します。導入時に設定と Wiki を 1 つの PR に入れるときに使います。

手編集された Wiki ページがあると止まります（`--force` で上書き）。

[[cli-sync-wiki-publish]]
==== tracking branch の上で実行したとき

`main`（tracking branch）を checkout している場合、または `--branch` を付けた場合は、一時 worktree `.aidev/cache/wiki-worktree/` で更新し、`aidev/wiki-<sha12>` ブランチにコミットして push し、PR を作ります（Azure DevOps で `sync.auto_pr` が `true` かつ PAT があるとき。`generic` hosting では手で作ります）。あなたの checkout は触りません。本文が完成したときだけ push します。

途中で失敗すると lease（`.aidev/sync.lock`）と worktree が残ります。同じコマンドで続き、`--abort` で捨てます。

==== オプション

[%autowidth.stretch,options="header"]
|===
|オプション |説明

|`--scope <path>`
|このパス配下のページだけ作り直す。調査範囲は PKG 全体のまま

|`--full`
|差分ではなく全ページを作り直す

|`--dry-run`
|何が対象になるかを表示し、何も書かない

|`--json`
|JSON で出力する

|`--force`
|手編集された Wiki ページを上書きする。中断した publish の lease を引き継ぐ

|`--no-commit`
|コミットせず、更新した Wiki を作業ツリーに残す

|`--branch`
|一時 worktree で更新し、`aidev/wiki-<sha12>` ブランチにコミットして PR を作る（tracking branch 上では自動）

|`--no-push`
|`--branch` と併用: ローカルの `aidev/wiki-<sha12>` にコミットするだけで、push と PR はしない

|`--abort`
|中断した `--branch` の publish を捨てる（worktree を消し、lease を解放する）

|`--no-agent`
|inventory と manifest だけ書き、本文は後回しにする。完了報告があれば取り込む

|`--agent-name <name>`
|knowledge-builder の代わりにこの agent を起動する

|`--agent-tool <tool>`
|agent を動かす AI ツール（`claude`、`copilot`、`codex`、`kiro`）。`aidev.yaml` の `tools.default` にあるものだけ。既定は `tools.agents.<name>.tool`、無ければ `tools.agent`

|`--agent-timeout <ms>`
|agent 1 回の時間予算（既定 1800000 = 30 分）

|`--agent-model <model>`
|agent のモデル。`""` でツールの既定に任せる

|`--agent-batch-size <n>`
|agent 1 回に渡すファイル数（既定 20）

|`--survey`
|必ず最初に `overview.md` と `index.md` を書き直す

|`--no-survey`
|`overview.md` と `index.md` を書き直さない
|===

==== 終了コード

[%autowidth.stretch,options="header"]
|===
|コード |条件

|0
|Wiki が HEAD を説明していてコミットした、または何もする必要が無かった。`--dry-run`、`--abort`

|1
|本文が未完了（`--no-agent`、agent の失敗・時間切れ・途中終了。再実行で続行できる）。生成対象に未コミットの変更がある。手編集があり `--force` が無い。`--scope` に一致するファイルが無い。別の target の publish が中断したまま（`--abort` か `--force`）。`tools` でも `wiki` でもない object を指定した
|===

==== 例

初回の生成（Engineering Manager。コミットは PR と一緒に自分で行う）:

[source,bash]
----
aidev sync wiki --no-commit
----

更新する（止まっても同じコマンドで再開）:

[source,bash]
----
aidev sync wiki
----

何が対象になるか確認だけする:

[source,bash]
----
aidev sync wiki --dry-run
----

[source,text]
----
aidev sync wiki (dry run)
  target               9f8e7d6 (HEAD of feature/login)
  wiki describes       1a2b3c4
  generation targets   163
  ...
  queued now           7
✓ dry run complete; nothing was written.
    would then run the knowledge-builder agent with Claude Code for 7 generation target(s) in 1 batch(es).
----

hook の指示でサブエージェントが本文を書いたあと、報告を取り込んでコミットする:

[source,bash]
----
aidev sync wiki --no-agent
----

`src/api` 配下だけを、小さい batch で作り直す:

[source,bash]
----
aidev sync wiki --scope src/api --agent-batch-size 10
----

全ページを作り直す（手編集も捨てる）:

[source,bash]
----
aidev sync wiki --full --force
----

`main` の Wiki を PR で更新する（夜間 pipeline と同じ）:

[source,bash]
----
aidev sync wiki --branch
----

中断した publish を捨てる:

[source,bash]
----
aidev sync wiki --abort
----

[[cli-sync-workflow]]
=== aidev sync workflow

`aidev create workflow <name> --from <standard>` で複製した workflow に、ADK の標準 workflow の新しい版を取り込みます。この PKG で直したところ（`cwd`、パス、`inputs`、agent の手順）は保ちます。`aidev sync tools` がテンプレートにするのと同じ 3-way merge です。

複製したときに `.aidev/workflows/<name>/standard.json` が書かれています（複製元の標準 workflow の名前、ADK の commit、ファイルごとの ADK 版と書いた内容のハッシュ）。これを元に、ADK の標準 workflow のファイル（`workflow.yaml`、agent、skill）ごとに次のどれかになります。

[%autowidth.stretch,options="header"]
|===
|結果 |条件 |すること

|`+ <path>`（created）
|ADK の標準 workflow に増えたファイル
|書く

|unchanged
|すでに同じ
|何もしない

|`~ <path>`（updated）
|この PKG で編集していない。ADK が変えた
|ADK 版に置き換える（`--force` なら全ファイル）

|kept
|この PKG で編集した。ADK は複製時から変えていない
|そのまま

|`~ <path> (merged with your edits)`
|この PKG で編集し、ADK も変えた。重ならない
|複製時の ADK 版を base に 3-way merge した結果を書く

|`! <path>`（conflict）
|両方が同じ行を変えた
|git 形式の衝突マーカーを書き、終了コード 2。マーカーを解消してからもう一度実行する（記録が更新される）。マーカーが残っている間は実行を拒否する

|`! <path>`（conflict、base 無し）
|編集したが、複製時の版が記録に無いか ADK の checkout の履歴に無い
|手で merge する（`git diff --no-index <ADK の file> <PKG の file>`）か、`--force` で ADK 版にする

|`= <path>`（retired）
|記録にあるが ADK の標準 workflow から無くなった
|そのまま残す
|===

取り込んだあと、定義を検証します（通らなければ終了コード 1 と理由）。結果は `git diff` でレビューし、`aidev submit workflow <name>` で提出します。承認されるのは提出してマージされた版なので、取り込んだだけでは実行は変わりません（`--trial` で先に試せます）。

**`standard.json` が無い複製**（記録が入る前に複製したもの）は、`--from <standard>` で複製元を名指しします。ADK の checkout の履歴から、複製の各ファイルと一致する最も新しい版を探して base にし（`no standard.json was there; the copy matches the kit's … at <commit> (N of M file(s))`）、記録を書きます。どのファイルも一致しなければ base が無く、編集したファイルは conflict（base 無し）になります。

==== オプション

[%autowidth.stretch,options="header"]
|===
|オプション |説明

|`--from <standard>`
|`standard.json` が無い複製の、複製元の標準 workflow の名前。記録があるときは一致していなければならない

|`--dry-run`
|何が変わるかを表示し、何も書かない（記録も更新しない）

|`--force`
|全ファイルを ADK 版に置き換える。ローカルの編集と衝突は捨てる

|`--json`
|JSON で出力する（`ok`、`from`、`kitCommit`、`baseCommit`、`bootstrapped`、`created`、`updated`、`merged`、`kept`、`retired`、`unchanged`、`conflicts`、`problem`）
|===

==== 終了コード

[%autowidth.stretch,options="header"]
|===
|コード |条件

|0
|取り込んだ、または最新だった

|1
|workflow が無い、`standard.json` が無くて `--from` も無い、`--from` が記録と違う、ADK にその標準 workflow が無い、取り込んだ結果が検証を通らない

|2
|衝突が残っている（新しく書いたマーカー、base 無し、または前回のマーカーが未解消）
|===

==== 例

ADK を更新してから、複製した `e2e-tests` に取り込む:

[source,bash]
----
aidev update
aidev sync workflow e2e-tests --dry-run     # 何が変わるかを先に見る
aidev sync workflow e2e-tests
git diff                                    # レビューしてから
aidev submit workflow e2e-tests
----

[source,text]
----
aidev sync workflow e2e-tests
✓ took 3 change(s) from the kit's playwright-tests into workflow e2e-tests
    ~ .aidev/agents/playwright-test-writer.md
    ~ .aidev/skills/playwright-testing/SKILL.md
    ~ .aidev/workflows/e2e-tests/workflow.yaml (merged with your edits)
    Review with "git diff", then "aidev submit workflow e2e-tests" (the reviewed copy is what runs; try it first with "aidev run workflow e2e-tests --trial").
----

記録の無い複製に、複製元を名指しして取り込む:

[source,bash]
----
aidev sync workflow e2e-tests --from playwright-tests
----
