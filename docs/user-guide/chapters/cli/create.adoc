[[cli-create]]
== aidev create

workflow・agent・skill のファイルを書きます。書くだけで、実行も提出もしません。`policy` は書き込み権限 policy の候補を作り、`--approve` で置きます。

=== 書式

[source,text]
----
aidev create workflow <name> [--describe "<text>"] [--force] [--dry-run] [--json]
aidev create agent <name> [--describe "<text>"] [--force] [--dry-run] [--json]
aidev create skill <name> [--force] [--dry-run] [--json]
aidev create policy [--approve] [--force] [--dry-run] [--json]
----

=== 説明

[%autowidth.stretch,options="header"]
|===
|object |書くもの

|`workflow <name>`
|`.aidev/workflows/<name>/workflow.yaml`。既定は空の雛形。`--describe "<text>"` で workflow-creator agent（`aidev.yaml` の `tools.agent`）に YAML と必要な `.aidev/agents/`・`.aidev/skills/` を書かせる。書いたあと検証し、結果と次の手順を表示する

|`agent <name>`
|`.aidev/agents/<name>.md`。frontmatter（`name`、`description`、`skills: []`、`tools`、`mcp: []`、`model: inherit`）と、入出力契約・手順・停止条件の見出しを持つ雛形。`skills`・`tools`・`mcp` はその agent が使えるもの（xref:workflows-agents-skills[agent と skill]）。`--describe "<text>"` で agents-creator agent に書かせる。書いたあと frontmatter の `name` がファイル名と一致するか、`tools`・`mcp` の書き方が正しいかを検証する

|`skill <name>`
|`.aidev/skills/<name>/SKILL.md`。frontmatter（`name`、`description`）と手順の雛形。`--describe` は使えない（skill は人が書く手順書）

|`policy`
|`.aidev/policy.candidate.yaml`（書き込み権限 policy の候補）。`aidev.yaml` の `secrets_paths` と ADK の既定から作る。`--approve` で `.aidev/policy.yaml` として置き、候補を消す（人間の判断）。policy が既にあっても同じ（`secrets_paths` を変えたときなど）。今の policy より保護が減る候補は `--force` が無いと終了コード 3。候補は手で編集しても反映されない。チームが足す `writable` は置いた後の `.aidev/policy.yaml` を直接編集して PR にする（`create policy --approve` で消える）。名前は取らない
|===

既存の workflow を一部だけ直すときは、xref:cli-modify[`aidev modify workflow <name> --describe "…"`] を使います。`create workflow --describe --force` は今の定義を見ずに、説明だけから書き直します。

名前は小文字・数字・ハイフンです。ADK が同梱する agent は仕組みのもの（knowledge-builder、workflow-creator、agents-creator、permission-setting）だけで、開発作業をする agent は PKG が作ります。同名なら PKG のものが優先されます。書いたあとは編集し、名前で参照し（agent は workflow のステップの `agent: <name>`、skill は agent の frontmatter の `skills: [<name>]`）、`aidev submit workflow <workflow>` で workflow と一緒に PR にします。

=== オプション

[%autowidth.stretch,options="header"]
|===
|オプション |説明

|`--describe <text>`
|`workflow` / `agent`: 自然言語で書く。workflow-creator / agents-creator agent がファイルを書く

|`--approve`
|`policy`: 作り直した候補を `.aidev/policy.yaml` として置く

|`--force`
|`workflow` / `agent` / `skill`: 既存を上書きする。`policy`: 保護が減る候補でも置く

|`--dry-run`
|書く内容を表示し、何も書かず、agent も起動しない

|`--json`
|JSON で出力する
|===

=== 実行中の表示

`--describe` で agent が動いている間は、agent がツールを呼ぶたびに 1 行ずつ表示します（経過時間、ツール名、対象）。agent が起動したサブエージェントの動きは字下げして表示します。15 秒以上何も来ないときだけ「still running」の行を出します。`--json` ではこの表示は出ません。

----
ℹ starting workflow-creator via claude (sonnet)…
     0:04  Read aidev.yaml
     0:05  Glob packages/**
     1:07  Agent agents-creator: Create test-writer PKG agent
     1:20    Read packages/backend/package.json
     1:52    Write .aidev/agents/test-writer.md
     2:30  Write .aidev/workflows/unit-tests/workflow.yaml
✓ wrote .aidev/workflows/unit-tests/workflow.yaml (3 step(s); writable: packages/**/*.test.ts) in 2m 41s ($0.3120)
----

=== 終了コード

[%autowidth.stretch,options="header"]
|===
|コード |条件

|0
|書いた。`--dry-run`

|3
|`policy --approve` で保護の弱化を検出した（`--force` 無し）

|1
|object や名前が無い・不正。既にあって `--force` が無い。`--describe` を skill に付けた。agent が失敗した（`--describe`）。`policy` に名前を付けた
|===

=== 例

自然言語から作る（Engineering Manager）。workflow-creator が YAML を書き、必要な agent・skill は agents-creator に書かせる:

[source,bash]
----
aidev create workflow e2e-tests --describe "tests/e2e/ に主要画面の Playwright テストを書いて PR にする"
----

PKG 固有の agent と skill を作る:

[source,bash]
----
aidev create agent release-notes --describe "CHANGELOG と PR から release notes の下書きを書く"
aidev create skill deploy-checklist
----

[source,text]
----
✓ wrote .aidev/skills/deploy-checklist/SKILL.md from the template
    edit it, list it in an agent's frontmatter (skills: [deploy-checklist]), then "aidev submit workflow <workflow>"
----

policy の候補を作り、読んでから置く:

[source,bash]
----
aidev create policy
git diff --no-index .aidev/policy.yaml .aidev/policy.candidate.yaml
aidev create policy --approve      # 保護を弱める差分があるときは --force も付ける
----
