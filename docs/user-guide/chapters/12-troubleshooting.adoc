[[troubleshooting]]
== トラブルシューティング

問題が発生したら、force optionやstate file削除を先に行わず、現在のrepository、SHA、lease、diffを保全します。

[[troubleshooting-baseline]]
=== 基本診断

wrapper rootで次を実行します。

[source,bash]
----
git status --short
git remote -v
git submodule status --recursive
aidev doctor
aidev knowledge status
aidev check
----

CLI内部の予期しないerrorでstack traceが必要な場合だけ、現在のshellに`AIDEV_DEBUG=1`を設定して再現します。出力へsecretが含まれないことを確認して共有します。

[[troubleshooting-symptoms]]
=== 症状別クイックリファレンス

[cols="2,4",options="header"]
|===
|症状 |確認と対処

|`aidev`が見つからない
|CLI専用checkoutからinstallerを再実行し、新しいterminalを開きます。POSIXでは`~/.local/bin`または`AIDEV_BIN_DIR`が`PATH`にあるか確認します。

|`aidev update`がwrapperを検出して停止する
|launcherがwrapperを指しています。固定のCLI専用checkoutを用意し、そこからinstallerを再実行します。

|installerがwrapperからの実行を拒否する
|正しい安全動作です。中央kitを別の安定したpathへcloneし、そのcheckoutで実行します。

|`init`が`.claude/`の衝突で停止する
|`init --dry-run`と`git diff`で確認します。必要な変更は中央kitへ移し、安易に`--force`を使いません。

|`aidev.yaml` parse/validation error
|YAML indentation、required fields、型、integer範囲を確認します。`model`はmapping、credentialは環境変数名だけにします。

|`check`がexit 2
|static assetがlockと不一致、または`--strict`でwarningが昇格しています。`kit apply --dry-run`と出力のseverityを確認します。

|`check`がexit 3
|`permission show`を実行します。policy未配置ならcandidateを生成・review・承認します。

|`check`がexit 4
|`src`と`knowledgeSha`が不一致です。残存sync leaseを確認し、`sync --resume`または`--abort`を選びます。

|`pending targets`が残る
|`knowledge build --refresh --agent`を実行し、Claude Code、timeout、model、agent最終診断を確認します。

|agentがexit 0なのにcommandが失敗する
|transportは成功してもpendingが減っていないno-progress判定です。checkpointとClaude最終回答を確認します。

|`sync lease is present`
|前回のoriginal/target SHA、`src`、`knowledge/`差分を確認してresumeまたはabortします。fileを手で消しません。

|同期PRが作成されない
|`sync.auto_pr`、`wrapper_repository`、PAT環境変数、wrapper `origin`、push/PR権限を確認します。local branchとworktreeも確認します。

|MCPが接続できない
|PAT期限・scope、`npx`、npm registry、proxy、証明書、organization/project設定を確認します。

|quality gateが毎回遅い
|PostToolUseは設定された全gateを実行します。targetedで非対話のcommandへ見直します。

|他メンバーとmodelや挙動が違う
|`.claude/settings.local.json`、`ANTHROPIC_MODEL`、CLIの`--agent-model`、`aidev.yaml`を区別して確認します。

|`--json`をparseできない
|対象commandがhuman textを混在させる既知経路か確認します。stdout単一JSONを前提にせず、version固定とcontract testを行います。

|scheduled `task advance`が何もしない
|fresh CI agentには`.aidev/tasks` cacheがありません。現行版はAzure DevOpsからcacheを再構築しません。
|===

[[troubleshooting-exit-2]]
=== exit 2: driftまたはstrict warning

まずstrictなしで実行し、static driftとwarningを区別します。

[source,bash]
----
aidev check
aidev check --strict
aidev kit apply --dry-run
git diff -- .claude CLAUDE.md .mcp.json .aidev-lock
----

static assetをwrapperで直接直さず、中央kitの正しいversionを`kit apply`します。個人設定は`.claude/settings.local.json`へ移します。

strictだけが失敗する場合は、remote ahead、pending proseなどのwarningを出力から特定します。

[[troubleshooting-exit-3]]
=== exit 3: policy

[source,bash]
----
aidev permission show
aidev permission configure --dry-run
----

初回なら次を実行します。

[source,bash]
----
aidev permission configure
# candidateをreview
aidev permission configure --approve
----

既存policyの変更は`reconfigure`です。保護を弱める差分に`--force`が必要な場合、なぜ必要かをreview記録へ残します。

[[troubleshooting-exit-4]]
=== exit 4: Wiki不整合

現在値とleaseを確認します。

[source,bash]
----
aidev knowledge status
git status --short
git diff --submodule=log -- src
git diff -- knowledge
----

[cols="2,3",options="header"]
|===
|状況 |対応

|前回syncを同じtargetへ続けたい
|`aidev sync --resume`を実行します。

|誤targetまたは同期を取り消したい
|local変更が混ざっていないことを確認し、`aidev sync --abort`を実行します。

|leaseなしで`src`だけが進んでいる
|手動submodule変更の由来を確認し、正規の`sync`へ戻します。manifestだけを手修正しません。

|knowledgeだけが手編集されている
|差分をsource/agent指示へ移し、buildし直します。
|===

[[troubleshooting-agent]]
=== knowledge agentの失敗

. PATH上に`claude`があることを別terminalで確認します。
. `knowledge.agent_timeout_ms`または`--agent-timeout`がPKG規模に十分か確認します。
. `knowledge/.cache/agent-task-*.json`のtarget/evidence件数を確認します。secret内容は共有しません。
. `knowledge/manifest.json`の`checkpoint.pendingPaths`を確認します。
. generation targetが空、またはexcludeし過ぎていないか確認します。
. evidenceが`src/**`を含み、必要なtest/config/CIを調査可能か確認します。
. `aidev knowledge build --refresh --agent`で再開します。

一部だけ完了した場合もcheckpointを利用できます。生成済みpageを削除して最初からやり直す前に、pendingだけを再queueします。

[[troubleshooting-sync-pr]]
=== syncは成功したがPRがない

次を順番に確認します。

. `aidev.yaml`の`sync.auto_pr`がtrueか。
. `azure_devops.wrapper_repository`が正しいか。
. `azure_devops.auth_env`が指すenvironmentにPATがあるか。
. wrapperの`origin`が正しいAzure DevOps repositoryか。
. Git pushとPR作成のpermissionがあるか。
. `ai/sync-*` local/remote branchが作られているか。
. 既存open PRまたはsuperseded注記があるか。

PAT値をdiagnostic commandやissueへ貼り付けないでください。

[[troubleshooting-mcp]]
=== Azure DevOps MCP

設定解決をserver起動なしで確認します。

[source,bash]
----
aidev mcp azure-devops --dry-run
aidev mcp azure-devops --json
npx --version
----

確認項目は、PAT environment、organization、project、npm registry到達性、corporate proxy、TLS certificateです。packageは固定版ですが、初回にはregistryから取得するnetwork accessが必要です。

[[troubleshooting-update]]
=== updateできない

`aidev update`は安全のため、dirty、`main`以外、detached、divergedなCLI checkoutを更新しません。launcherが指すpathを確認し、そのcheckoutで次を確認します。

[source,bash]
----
git status --short
git branch --show-current
git remote -v
git log --oneline --decorate -5
----

local変更が必要なら通常branchへcommit/PRし、CLI専用checkout自体は中央`main`へ戻します。`reset --hard`で未退避作業を消さないでください。

[[troubleshooting-report]]
=== 問題を報告するとき

次を含めると再現しやすくなります。

* `aidev --version`とNode.js version
* OSとshell
* commandと終了コード（secret引数を除く）
* `doctor`、`check`のredact済み出力
* 3SHAの短縮値
* current branchとremoteの役割
* leaseの種類、target/original SHA、期限（credentialを除く）
* 最小再現手順

PAT、token、private repository URLに含まれるcredential、Work Itemの機密本文、agent task fileのsecret内容は添付しません。
