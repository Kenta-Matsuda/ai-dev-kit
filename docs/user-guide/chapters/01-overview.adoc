[[overview]]
== {project-name} とは

{project-name} は、 AI 駆動開発のベストプラクティスに基づき、チーム開発を支援する開発キットです。

[[overview-flow]]
=== {project-name} を用いた開発プロセス

.開発の流れ（① 導入、② 日々の開発、③ AI に仕事を任せる）
[mermaid]
----
sequenceDiagram
  participant O as 導入担当者
  participant M as メンバー
  participant R as レビュアー

  rect rgb(232, 243, 250)
    Note over O,R: ① 導入（PKG につき 1 回）
    O->>O: aidev init（設定・policy）→ aidev sync wiki（Wiki）
    O->>R: PR
    R->>R: 設定と Wiki を確認してマージ
    M->>M: git pull → aidev init → claude
  end

  rect rgb(233, 247, 240)
    Note over O,R: ② 日々の開発
    M->>M: claude で開発 → git commit
    M->>M: hook が Wiki を追従（別コミット）
    M->>R: PR（ソース + Wiki）
    R->>R: 両方を見てマージ
  end

  rect rgb(242, 237, 255)
    Note over O,R: ③ AI に仕事を任せる
    O->>O: aidev create workflow #60;name#62;
    O->>R: aidev submit workflow → PR
    R->>R: 定義をレビューしてマージ（= 承認）
    M->>M: aidev run workflow #60;name#62;
    M->>R: PR（成果物）
    R->>R: 成果物をレビューしてマージ
  end
----

=== 誰が何をするか

[%autowidth.stretch,options="header"]
|===
|役割 |人数 |すること |章

|全員
|各端末で 1 回
|自分の端末に `aidev` を入れる。
|xref:install[端末に aidev を入れる]

|導入担当者
|PKG につき 1 人
|PKG に {project-name} を導入し、policy を承認し、Wiki を生成して PR にする。その後も、開発規約の生成、workflow の定義と提出、kit の新しいテンプレートの取り込み（`aidev sync tools`）を PR にする。**PKG 固有の設定を決めるのはこの 1 人**で、メンバーは何も決めません。
|xref:setup-owner[導入担当者の手順]、xref:workflows[AI に仕事をさせる]

|メンバー
|全員
|`git pull` → `aidev init` → `claude`。コミットのたびに Wiki を追従させる。承認済みの workflow を `aidev run workflow` で実行し、できた PR をレビュアーに渡す。
|xref:setup-member[メンバーの手順]、xref:daily[日常の使い方]

|レビュアー
|チームが決める
|3 種類の PR をレビューしてマージする: 導入・設定の PR、ソースと Wiki の PR、workflow の定義と成果物の PR。branch policy で必須レビュアーにしておく。
|xref:daily-review[レビュアーがすること]

|CI
|—
|PR ごとに `aidev check` を実行してマージを止める。夜間に `main` の Wiki を追従させる。
|xref:automation[自動化]
|===

{project-name} 本体（CLI、同梱の workflow・agent・skill）を保守するのは kit の開発者で、このガイドの対象外です。

=== 責任の分け方

AI が作った成果物（PR）に責任を負うのは、**実行した人ではなく、レビューした人**です。

* workflow の定義（何をさせるか、どこを書いてよいか、いくらまで使うか）は、導入担当者が書き、レビュアーが PR で承認します。
* 成果物は、実行したメンバーではなく、その PR をレビューしてマージする人が確認します。
* kit は PR を作りますがマージしません。マージは常に人間が行います。

=== しないこと

* PR をマージしません。
* 実機で検証済みの AI ツールは Claude Code です。GitHub Copilot CLI・OpenAI Codex CLI・Kiro CLI は各ツールの非対話モードに沿ったアダプタで起動できますが、kit の保守者は実機で確認していません。hook の設定は 4 つのツールすべてに置きますが、実機で確認しているのは Claude Code だけです。
* 対応する hosting は Azure DevOps と `generic`（git のみ。PR は手動）だけです。
* サンドボックスではありません。hook と policy は「うっかり」を止める仕組みです。最終的な守りは token の権限と branch policy です。

=== 用語

[%autowidth.stretch,options="header"]
|===
|用語 |意味

|PKG
|{project-name} を導入する対象リポジトリの clone。`aidev` はその中で実行します。

|kit
|{project-name} 本体の clone。`aidev` コマンドの実体です。端末に 1 つです。

|LLM Wiki
|`.aidev/knowledge/` に生成される、AI 向けの説明ページ群。コードから作った派生情報で、正本ではありません。

|tracking branch
|Wiki が追いかけるブランチ。workflow の承認の基準にもなります。通常は `main` です。

|policy
|`.aidev/policy.yaml`。AI が書いてよいパス、書けないパス、常に禁止のパスを決めます。

|workflow
|`.aidev/workflows/<name>/workflow.yaml`。AI にさせる仕事の目的・書いてよい範囲・手順・上限を書いた YAML です。

|承認済み
|workflow の定義（と、それが参照する PKG 内の agent・skill）が `origin/main` にあるものと同じであること。PR のマージが承認です。

|agent / skill
|agent は AI ツールに渡す役割の定義（`.aidev/agents/<name>.md`）、skill は手順書（`.aidev/skills/<name>/SKILL.md`）。kit にも同梱され、workflow から名前で参照します。
|===
