[[troubleshooting]]
== トラブルシューティング

症状から対処を引く表です。メッセージは `aidev` が実際に表示する英文です。

[[troubleshooting-install]]
=== インストール

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`aidev` が見つからない
|新しいターミナルを開きます。それでも駄目なら、起動スクリプトのディレクトリが PATH にあるか確認します。Windows は `%LOCALAPPDATA%\ai-dev-kit\bin`（ユーザー環境変数の PATH に追加）、POSIX は `export PATH="$HOME/.local/bin:$PATH"` を profile に追加します。直らなければ installer を再実行します。

|`node not found` / `node vXX is too old`
|Node.js {node-min-version} 以上を入れて installer を再実行します。

|`this looks like a package that uses ai-dev-kit, not the kit itself`
|PKG の中で installer を実行しています。ADK の clone で実行します。

|`… checkout must be on branch main`
|ADK の clone で `git switch main` してから実行します。

|`aidev doctor` で +
`⚠ claude not found on PATH` / `is too old`
|Claude Code {claude-min-version} 以上を入れます。Wiki の生成にはこれが必要です。
|===

[[troubleshooting-status]]
=== aidev check の表示

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`not an ai-dev-kit package (no aidev.yaml); nothing to check`
|PKG の clone の中で実行します。未導入なら xref:setup-owner[PKG への導入]。

|`[exit 1] workflow <name> is invalid: …`
|`.aidev/workflows/<name>/workflow.yaml` が検証を通りません。表示された項目を直します（xref:troubleshooting-workflow[workflow]）。

|`❌ LLM Wiki has not been generated yet`
|`git pull`。それでも無ければ `aidev sync wiki`。この間、AI の書き込みは止まります。

|`⚠️ the Wiki describes … but N file(s) differ at HEAD`
|`aidev sync wiki`。AI ツールの中なら次のコミット後に hook が始めます。

|`⚠️ N page(s) still await prose regeneration`
|`aidev sync wiki`。hook の指示が出ていればそのとおりに進め、最後に `aidev sync wiki --no-agent`。

|`⚠️ origin/main has moved ahead`
|区切りの良いところで merge か rebase をし、`aidev sync wiki`。

|`tool config  CONFLICTS in N file(s)`
|`aidev sync tools` の衝突が未解消です。該当ファイルのマーカー（`<<<<<<<` / `=======` / `>>>>>>>`）を解消し、`aidev sync tools` を実行して記録を更新し、コミットします。

|`tool config  ADK hooks missing …`
|ADK の hooks が消えています。`aidev sync tools --force` で ADK 版に戻すか、hooks を手で戻します。

|`tool config  not recorded — run "aidev init"`
|`aidev init` を実行します。

|`policy  missing`
|`aidev create policy --approve`。

|`⚠ a stale publish lease is present`
|tracking branch への publish が途中で止まっています。`aidev sync wiki` で続けるか、`aidev sync wiki --abort` で捨てます。

|`⚠ N Wiki page(s) edited by hand since generation`
|編集を捨ててよければ次の `aidev sync wiki` に `--force` を付けます。残したい内容はソース側に移します。

|`ℹ️ remote unverified`
|remote に届きません。作業は続けられます。proxy の設定を確認します。
|===

[[troubleshooting-exit]]
=== aidev check の終了コード

[cols="1,2,3",options="header"]
|===
|終了コード |表示 |対処

|1
|`workflow <name> is invalid: …`
|`workflow.yaml` の表示された項目を直し、`aidev submit workflow` で提出し直します。

|2
|`tool configuration file(s) carry unresolved conflict markers` / `the ADK's hooks are missing`
|衝突マーカーを解消して `aidev sync tools` を実行するか、`aidev sync tools --force` で ADK 版にします。チームの編集そのものは 2 になりません。

|2
|`.aidev/materialized.json is missing`
|`aidev init` を実行してコミットします。

|3
|`.aidev/policy.yaml not found`
|`aidev create policy --approve`。

|3
|`failed to parse .aidev/policy.yaml`
|`aidev create policy --approve` で置き直します。

|4
|`LLM Wiki has not been generated yet`
|`aidev sync wiki` を実行します（完了すると自分でコミットします）。

|4
|`N inventory inconsistency/ies`
|`aidev sync wiki --full`。

|4
|`a stale publish lease is present`
|`aidev sync wiki` で続けるか、`aidev sync wiki --abort`。

|2（`--strict`）
|`the Wiki describes … but N file(s) differ at HEAD` / `N page(s) still await prose`
|`aidev sync wiki` を実行し、Wiki のコミットを同じ PR に入れます。
|===

[[troubleshooting-agent]]
=== Wiki の生成

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`N generation target(s) have uncommitted changes; the Wiki describes commits only`
|列挙されたファイルをコミット（または stash）してから再実行します。

|`⚠ the knowledge-builder agent did not run`
|`aidev doctor` の AI ツールの行を直し、同じコマンドを再実行します。

|`✗ the knowledge-builder agent ran out of time`
|同じコマンドで再開します。繰り返すなら `--agent-batch-size 10` を付けます。

|`✗ knowledge-builder made no Wiki progress: 0/N`
|続く `Claude Code result:` を読みます。`permission denial(s)` があれば `.claude/settings.json` の deny 設定を確認し、必要なら `aidev sync tools --force` で ADK 版に戻します。

|`⚠ N completion report(s) were rejected`
|同じコマンドで再実行します。続くなら `--full`。

|`✗ … left the Wiki checkpoint invalid …`
|生成中にブランチを切り替えたか、コミットしました。元の HEAD に戻して再実行するか、新しい HEAD で `aidev sync wiki` を実行します。

|`⚠ N generation target(s) still need prose; the Wiki was not committed.`
|本文が残っています。同じコマンドで再開します。hook の流れなら、残りの batch をサブエージェントに渡してから `aidev sync wiki --no-agent`。

|hook の指示が出たのにセッションが Wiki を更新しない
|`aidev sync wiki` を手で実行します。Stop hook の拒否は 1 回だけなので、2 回目の終了は通ります。

|`✗ N Wiki page(s) were edited by hand …`
|`--force` を付けるか、編集内容をソース側に移します。

|`✗ --scope <path> matched no files …`
|`aidev.yaml` の `package.include` に含まれるパスを指定します。
|===

[[troubleshooting-publish]]
=== tracking branch への publish

`main` の上で `aidev sync wiki` を実行したとき（または `--branch`）の表示です。

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`✗ an interrupted publish is present (…; target …)`
|別の HEAD に対する publish が途中で止まっています。`aidev sync wiki --abort` で捨てるか、`--force` で引き継ぎます。同じ HEAD なら同じコマンドで続きます。

|`✗ the Wiki is not complete (N target(s) still queued); nothing was published.`
|本文が残っています。同じコマンドで同じ worktree の続きを行うか、`--abort` で捨てます。

|`✗ publish failed: …`
|原因を直して同じコマンドで続けます。lease と worktree は残っています。やり直すなら `--abort`。

|`⚠ AZURE_DEVOPS_PAT is not set; …`
|環境変数を設定して再実行するか、push 済みのブランチから手で PR を作ります。

|`ℹ hosting.type is generic; …` / `ℹ sync.auto_pr is false; …`
|正常です。手で PR を作ります。

|`✓ the Wiki already describes …; nothing to do.`
|`main` の Wiki は最新です。PR 待ちなら `aidev check` にブランチ名が出ます。マージ後に `git pull`。

|`✗ --branch publishes a commit; it cannot be combined with --no-commit`
|`--no-commit` を外します。
|===

[[troubleshooting-permission]]
=== 権限拒否

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|Claude が `… is read-only (**). this session was not started by "aidev run workflow"` と報告
|正常です。対話中の AI は PKG のソースを書けません。AI にソースを書かせる仕事は workflow として定義し、ステップの `writable` に範囲を書いて PR にします（xref:permissions-source[ソースを AI に書かせるには]）。

|`aidev run workflow` 中に `… workflow <name> is approved but the writable of step <id> (…) does not cover this path`
|そのパスは、いま動いているステップの範囲外です。必要なら Engineering Manager がそのステップの `writable` を広げて提出し直します。

|`aidev run workflow` 中に `… is not among the tools of agent <name> (…)` +
`… is not among the MCP servers of agent <name> (…)`
|agent の frontmatter か workflow の `agents:` で与えていないツールを使おうとしました。必要なら Engineering Manager がそのどちらかを直して提出し直します。権限の違う仕事なら、別の agent にします。

|`aidev run workflow` 中に `… workflow <name> is not approved: …`
|実行中に定義が変わったか、`origin/main` が動きました。実行を止め、`git fetch origin` と `aidev list workflows` で状態を確かめます。

|`… is protected (.claude/**)`
|正常です。ADK のファイルは ADK への PR で変えます。

|`Wiki consistency error … All writes are blocked`
|Wiki が無いか読めません。`aidev sync wiki`（または `git pull` で受け取る）。

|`policy could not be evaluated (…); write blocked`
|`aidev check` で確認し、`aidev create policy --approve` で置き直します。

|`aidev create policy --approve` が +
`this candidate weakens the policy in force` で止まる
|`git diff --no-index .aidev/policy.yaml .aidev/policy.candidate.yaml` で差分を確認し、意図どおりなら `--force` を付けます。

|`.aidev/policy.yaml: agents.<name> grants no longer exist`
|古い policy に `agents` 節が残っています。削除してコミットします。ソースを書く範囲は workflow の各ステップの `writable` に書きます。
|===

[[troubleshooting-workflow]]
=== workflow の実行

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`workflow <name> is not approved: … is not on origin/main yet`
|定義の PR が未マージです。マージ済みなら `git fetch origin`。手元の定義をそのまま試すなら `aidev run workflow <name> --trial` です（xref:workflows-trial[承認の前に試す]）。

|`workflow <name> is not approved: … differs from origin/main`
|手元で定義（または参照する agent・skill）を変えています。`git checkout origin/main -- .aidev/workflows/<name>/` で戻すか、 Engineering Manager が提出し直します。

|`workflow <name> is not approved: origin/main is not available in this clone`
|`git fetch origin` を実行します。

|`aidev list workflows` が `invalid: …`
|`workflow.yaml` が検証を通りません。表示された項目（`objective` が無い、agent step に `writable` が無い、`limits.max_usd` が無い、知らない項目がある、上限超過、`until` が文字列（`until:` の下に `command:` を書く）、`until.command` に引用符やパイプ、`protected` のパスなど）を直します。

|`agent <name> is neither in .aidev/agents/ nor bundled with the kit`
|agent 名の誤りか、PKG 固有の agent が未コミットです。名前を直すか、`.aidev/agents/<name>.md` を同じ PR に入れます。

|`agent <name> uses the MCP server <server>, which .mcp.json does not register` +
`agent <name> uses MCP (…) but .mcp.json does not exist in this PKG`
|agent の `mcp` にある server が、PKG の `.mcp.json` にありません（または `.mcp.json` がありません）。`.mcp.json` に server を登録するか、agent の `mcp` を直します。

|`agent <name> is given tools (in its frontmatter or the workflow's agents:), and <tool> cannot be limited to them; run it with claude`
|`tools` や `mcp` を書いた agent は Claude Code でしか起動しません。`aidev.yaml` の `tools.agent`（または workflow の `tool`）を `claude` にします。

|`agent <name> names subagents, but .claude/settings.json does not send Agent calls to "aidev hook guard-write"`
|PKG の `.claude/settings.json` が、サブエージェントの起動を hook で確かめる前のものです。`aidev sync tools` で更新してコミットします（xref:workflows-subagents[サブエージェントを指定する]）。

|`subagent <name> may use …, which its parent <agent> may not`
|サブエージェントの `tools`・`mcp` が親の agent より広いです。サブエージェントの frontmatter を狭めるか、親に足します。

|`<agent> may start only the subagents <a>, <b> (not <type>)`（hook が拒否）
|workflow の step の agent が、`subagents` にないサブエージェントを起動しようとしました。必要なら agent の frontmatter か workflow の `agents:` の `subagents` に足し、workflow を提出し直します（xref:workflows-subagents[サブエージェントを指定する]）。

|`steps <a> and <b> run at the same time but may write the same paths`
|parallel グループのステップの `writable` が重なり得ます。ステップごとに別のディレクトリにします（xref:workflows-parallel[並列に動かす]）。

|`for_each.parallel needs every writable path to name the target as {item}`
|件を同時に動かすには、`writable` を件ごとのパス（`e2e/tests/{item}.spec.ts` など）で書きます。

|`the worktree of aidev/<name> (…) has uncommitted changes, left by a run that stopped in the middle of a step`
|実行の worktree に、止まった実行の途中の変更があります。`--resume last` で続けるか、表示されたコマンドで捨ててから実行します（xref:workflows-worktree[実行の worktree とブランチ]）。

|`another run (…, process N) is working in …`
|同じ worktree で実行が動いています。終わるのを待ちます。

|`aidev/<name> has work that conflicts with …`
|ブランチの前の成果と今の起点が衝突しています。worktree で `git merge` して解決するか、`--dated` で別のブランチにします。

|`the worktree of aidev/<name> (…) does not hold the approved workflow <name>`
|ブランチの定義が承認済みの版と違います。worktree で承認済みの版をマージするか、`--dated` で実行します。

|実行の worktree で `npm` のコマンドが `not found` や `Cannot find module` で失敗する
|worktree には git が無視するもの（`node_modules` など）がありません。workflow の最初に `command: npm ci` のステップを置きます（入れたものはコミットされません）。gitignore 済みのデータ（仕様書、フィクスチャ）は `provide:` で手元のチェックアウトからコピーします（xref:workflows-provide[worktree に無いファイルを用意する]）。

|`step <id>: <command> was not found on PATH, so "…" could not run`
|command step か `until.command` の実行ファイルが PATH にありません。インストールするか、PATH を通します。何も始まっていません。

|`the workflow needs --input for: <name> (…)` +
`the workflow declares no input "<name>" (its inputs: …)` +
`input <name>: "<値>" does not match its pattern (…)`
|workflow が `inputs:` で宣言した入力を `--input <name>=<値>` で渡します。宣言の一覧は `aidev run workflow <name> --dry-run` の `## Inputs (--input name=value)` に出ます（xref:workflows-inputs[実行ごとに変わる値を受け取る]）。何も始まっていません。

|`input <name>: <path> is not committed; a run starts from HEAD (…)` +
`input <name>: <path> is ignored by git and no provide: entry copies it into the run (…)`
|`path: true` の入力が実行の worktree に届きません。コミットするか、`provide:` に足すか、`file: true` の入力にして渡します（xref:workflows-provide[worktree に無いファイルを用意する]）。

|`provide: <glob> matches no file that git ignores in <チェックアウト> (…)`
|手元のチェックアウトに、その glob に一致する gitignore 済みのファイルがありません。ファイルを置くか、`provide` の項目を外します。何も始まっていません。

|`provide: <file> is ignored in <チェックアウト> by a rule the repository does not carry; commit the .gitignore that ignores it, …`
|そのファイルを無視する規則がコミットされていません（`.git/info/exclude` や、コミット前の `.gitignore`）。`.gitignore` に書いてコミットします。

|`run <id> was a trial run; resume it with --trial` +
`run <id> was not a trial run; resume it without --trial` +
`workflow <name> has no recorded run that was not a trial (pass --trial to continue the last trial)`
|`--resume` は同じ種類の実行だけを続けます。試験（`--trial`）を続けるときは `--trial` を付け、普通の実行なら外します（xref:workflows-trial[承認の前に試す]）。

|`the definition of <name> (or an agent or skill it uses) changed since trial run <id> started; start a new trial`
|試験を始めたあとに定義（または agent・skill）が変わっています。`--resume` なしで、もう一度 `--trial` で実行します。

|`the checkpoints of run <id> are no longer on <branch> (…); start a new run`
|終わったステップのチェックポイントがブランチに残っていません（後の試験がブランチを戻した、マージ後にブランチを進めた）。`--resume` なしで新しく実行します。

|`step <id>: "git … push" pushes; a trial run pushes nothing`
|`--trial` では push する command step や `until.command` を実行できません。試験の間は外すか、別の確認方法にします。

|`N file(s) changed outside what the steps may write, by a command step or past the guard; not committed: …`
|実行は止まっていません。command step が `writable` の外に書いたか、agent が検問を通らずに書いています。コミットされていないので、要るものなら Engineering Manager がそのステップの `writable` を広げます。

|`step <id>: the tool was refused N call(s): … (a path outside writable? see run.json "denied")`
|実行は止まっていません。agent が `writable` の外や、与えられていないツールを呼んで拒否されています。`run.json` のそのステップの `denied` に一覧があります。仕事に要るなら `writable` か agent の `tools` を直します。

|`workflow stopped — step <id>: the until check still fails after N retries (…)` +
`… the same failure repeated`
|agent が `until` を満たせませんでした（テストが通らない、または確認役の agent が合格にしない）。終わったステップまではブランチ `aidev/<name>` のチェックポイントにあります。手で直せる原因なら worktree で直して `aidev run workflow <name> --resume last` で続けます（xref:workflows-resume[止まった実行を続ける]）。原因が定義にあるなら `aidev modify workflow <name> --from-run last` で直させます（xref:workflows-fix-from-run[止まった実行から直す]）。

|`workflow stopped — step <id>: cost limit of $N reached` +
`… time limit of N minutes exceeded`
|上限に達しました。`--task` を小さくするか、 Engineering Manager に上限の見直し（定義の PR）を相談します。

|`branch aidev/<name> is ready; hosting.type is generic; open the pull request by hand`
|正常です。push 済みのブランチから手で PR を作ります。

|`the pull request could not be opened: … must not be longer than 4000 characters`
|Azure DevOps は 4000 文字を超える PR 本文を受け付けません。aidev は本文を 4000 文字に収めて送るので、古い ADK で出ることがあります。`aidev update` で ADK を更新します。push は済んでいるので、今回の PR は全文（`aidev run workflow` は実行記録の `pull-request.md`、`aidev submit workflow` は `.aidev/cache/submit/<name>.md`）を短くして手で作ります。

|`the pull request could not be opened: …`
|push は済んでいます。`AZURE_DEVOPS_PAT` と PR 作成の権限を確認し、手で PR を作ります。

|`--describe` のあと `the agent finished, but the workflow does not validate: …`
|workflow-creator が書いた YAML を表示された項目に沿って直し、`aidev submit workflow` します。
|===

[[troubleshooting-update]]
=== ADK の更新後

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`tool config` 行に `newer templates available …`
|都合のよいときに PKG で `aidev sync tools` し、差分をコミットして PR にします。

|`aidev check` が終了コード 2 になった
|`git pull`。それでも 2 なら、`aidev check` で衝突マーカーか hooks の欠落かを確認し、解消して `aidev sync tools` を実行します。

|`✗ N file(s) need your attention` +
`conflict markers were written`
|チームの編集と ADK の変更が同じ箇所です。マーカーを解消して `aidev sync tools` を実行し、コミットします。ADK 版にしてよければ `aidev sync tools --force` です。

|`edited locally and the template it was based on …`
|ADK の clone に前回のコミットがありません（shallow clone など）。ADK の clone で `git fetch --unshallow` するか、手で直すか `aidev sync tools --force` にします。

|`✗ the ADK checkout has diverged from origin/main`
|ADK の clone にローカルコミットがあります。捨ててよければ `git reset --hard origin/main`。

|workflow が `cost is not a workflow key`、`timeout_ms is timeout_minutes now`、`max_retries is written inside until now`、`a pull-request step is written as pull_request: …` で拒否される
|ADK 2.0.0 の書き方です。`scripts/convert-workflow-v2.ps1` で書き換えます（xref:maintain-workflow-v2[2.0.0 の workflow.yaml の書き換え]）。
|===

[[troubleshooting-windows]]
=== Windows 固有

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|PowerShell で `aidev.ps1` が実行ポリシーで止まる
|`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`、または `aidev.cmd` を明示して実行します。
