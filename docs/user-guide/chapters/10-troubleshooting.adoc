[[troubleshooting]]
== トラブルシューティング

症状から対処を引く表です。メッセージは `aidev` が実際に表示する英文です。

[[troubleshooting-install]]
=== インストール

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`aidev` が見つからない
|新しいターミナルを開きます。POSIX では `export PATH="$HOME/.local/bin:$PATH"` を profile に追加します。それでも駄目なら installer を再実行します。

|`node not found` / `node vXX is too old`
|Node.js {node-min-version} 以上を入れて installer を再実行します。

|`this looks like a package that uses ai-dev-kit, not the kit itself`
|PKG の中で installer を実行しています。kit の clone で実行します。

|`… checkout must be on branch main`
|kit の clone で `git switch main` してから実行します。

|`aidev doctor` で +
`⚠ claude not found on PATH` / `is too old`
|Claude Code {claude-min-version} 以上を入れます。Wiki の生成にはこれが必要です。
|===

[[troubleshooting-status]]
=== aidev status / aidev check の表示

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`⚠ this directory is not set up for ai-dev-kit`
|PKG のルートに移動します。未導入なら xref:setup-owner[導入担当者の手順]。

|`❌ LLM Wiki has not been generated yet`
|`git pull`。それでも無ければ `aidev init`（または `aidev knowledge update`）。この間、AI の書き込みは止まります。

|`⚠️ the Wiki describes … but N file(s) differ at HEAD`
|`aidev knowledge update`。AI ツールの中なら次のコミット後に hook が始めます。

|`⚠️ N page(s) still await prose regeneration`
|`aidev knowledge update`。hook の指示が出ていればそのとおりに進め、最後に `aidev knowledge update --no-agent`。

|`⚠️ origin/main has moved ahead`
|区切りの良いところで merge か rebase をし、`aidev knowledge update`。

|`tool config  CONFLICTS in N file(s)`
|`aidev apply` の衝突が未解消です。該当ファイルのマーカー（`<<<<<<<` / `=======` / `>>>>>>>`）を解消し、`aidev apply` を実行して記録を更新し、コミットします。

|`tool config  kit hooks missing …`
|kit の hooks が消えています。`aidev apply --force` で kit 版に戻すか、hooks を手で戻します。

|`tool config  not recorded — run "aidev init"`
|`aidev init` を実行します。

|`policy  missing`
|`aidev permission configure --approve`。

|`⚠ a stale publish lease is present`
|tracking branch への publish が途中で止まっています。`aidev knowledge update` で続けるか、`aidev knowledge update --abort` で捨てます。

|`⚠ N Wiki page(s) edited by hand since generation`
|編集を捨ててよければ次の `aidev knowledge update` に `--force` を付けます。残したい内容はソース側に移します。

|`ℹ️ remote unverified`
|remote に届きません。作業は続けられます。proxy の設定を確認します。
|===

[[troubleshooting-exit]]
=== aidev check の終了コード

[cols="1,2,3",options="header"]
|===
|終了コード |表示 |対処

|2
|`tool configuration file(s) carry unresolved conflict markers` / `the kit's hooks are missing`
|衝突マーカーを解消して `aidev apply` を実行するか、`aidev apply --force` で kit 版にします。チームの編集そのものは 2 になりません。

|2
|`.aidev/materialized.json is missing`
|`aidev init` を実行してコミットします。

|3
|`.aidev/policy.yaml not found`
|`aidev permission configure --approve`。

|3
|`failed to parse .aidev/policy.yaml`
|`aidev permission reconfigure --approve` で置き直します。

|4
|`LLM Wiki has not been generated yet`
|`aidev knowledge update` を実行します（完了すると自分でコミットします）。

|4
|`N inventory inconsistency/ies`
|`aidev knowledge update --full`。

|4
|`a stale publish lease is present`
|`aidev knowledge update` で続けるか、`aidev knowledge update --abort`。

|2（`--strict`）
|`the Wiki describes … but N file(s) differ at HEAD` / `N page(s) still await prose`
|`aidev knowledge update` を実行し、Wiki のコミットを同じ PR に入れます。
|===

[[troubleshooting-agent]]
=== Wiki の生成

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`N generation target(s) have uncommitted changes; the Wiki describes commits only`
|列挙されたファイルをコミット（または stash）してから再実行します。

|`⚠ the knowledge-builder agent did not run`
|`aidev doctor` の AI ツールの行を直し、同じコマンドを再実行します。

|`✗ the knowledge-builder agent ran out of time`
|同じコマンドで再開します。繰り返すなら `--agent-batch-size 10` を付けます。

|`✗ knowledge-builder made no Wiki progress: 0/N`
|続く `Claude Code result:` を読みます。`permission denial(s)` があれば `.claude/settings.json` の deny 設定を確認し、必要なら `aidev apply --force` で kit 版に戻します。

|`⚠ N completion report(s) were rejected`
|同じコマンドで再実行します。続くなら `--full`。

|`✗ … left the Wiki checkpoint invalid …`
|生成中にブランチを切り替えたか、コミットしました。元の HEAD に戻して再実行するか、新しい HEAD で `aidev knowledge update` を実行します。

|`⚠ N generation target(s) still need prose; the Wiki was not committed.`
|本文が残っています。同じコマンドで再開します。hook の流れなら、残りの batch をサブエージェントに渡してから `aidev knowledge update --no-agent`。

|hook の指示が出たのにセッションが Wiki を更新しない
|`aidev knowledge update` を手で実行します。Stop hook の拒否は 1 回だけなので、2 回目の終了は通ります。

|`✗ N Wiki page(s) were edited by hand …`
|`--force` を付けるか、編集内容をソース側に移します。

|`✗ --scope <path> matched no files …`
|`aidev.yaml` の `package.include` に含まれるパスを指定します。
|===

[[troubleshooting-publish]]
=== tracking branch への publish

`main` の上で `aidev knowledge update` を実行したとき（または `--branch`）の表示です。

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`✗ an interrupted publish is present (…; target …)`
|別の HEAD に対する publish が途中で止まっています。`aidev knowledge update --abort` で捨てるか、`--force` で引き継ぎます。同じ HEAD なら同じコマンドで続きます。

|`✗ the Wiki is not complete (N target(s) still queued); nothing was published.`
|本文が残っています。同じコマンドで同じ worktree の続きを行うか、`--abort` で捨てます。

|`✗ publish failed: …`
|原因を直して同じコマンドで続けます。lease と worktree は残っています。やり直すなら `--abort`。

|`⚠ AZURE_DEVOPS_PAT is not set; …`
|環境変数を設定して再実行するか、push 済みのブランチから手で PR を作ります。

|`ℹ hosting.type is generic; …` / `ℹ sync.auto_pr is false; …`
|正常です。手で PR を作ります。

|`✓ the Wiki already describes …; nothing to do.`
|`main` の Wiki は最新です。PR 待ちなら `aidev status` にブランチ名が出ます。マージ後に `git pull`。

|`✗ --branch publishes a commit; it cannot be combined with --no-commit`
|`--no-commit` を外します。
|===

[[troubleshooting-permission]]
=== 権限拒否

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|Claude が `… is read-only (**)` と報告
|正常です。既定では agent は PKG のソースを書けません。編集させたいパスは `.aidev/policy.yaml` の `agents.<name>.writable`（`aidev agent run` で起動した agent だけ）か `writable` に足します（xref:permissions-source[ソースを agent に編集させるには]）。

|`… is writable for agent issue-to-pr only on branch aidev/issue-*`
|policy の `branch` 条件に合わないブランチにいます。そのブランチに checkout するか、`branch` を見直します。

|`aidev agent run` で起動したのに `… has no grant in .aidev/policy.yaml`
|policy に `agents.<name>` がありません。足してコミットします。

|`… is protected (.claude/**)`
|正常です。kit のファイルは kit への PR で変えます。

|`Wiki consistency error … All writes are blocked`
|Wiki が無いか読めません。`aidev knowledge update`（または `git pull` で受け取る）。

|`policy could not be evaluated (…); write blocked`
|`aidev permission show` で確認し、`aidev permission reconfigure --approve` で置き直します。

|`reconfigure --approve` が +
`this candidate weakens the policy in force` で止まる
|`git diff --no-index .aidev/policy.yaml .aidev/policy.candidate.yaml` で差分を確認し、意図どおりなら `--force` を付けます。
|===

[[troubleshooting-update]]
=== kit 更新後

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|`tool config` 行に `newer templates available …`
|都合のよいときに PKG で `aidev apply` し、差分をコミットして PR にします。

|`aidev check` が終了コード 2 になった
|`git pull`。それでも 2 なら、`aidev status` で衝突マーカーか hooks の欠落かを確認し、解消して `aidev apply` を実行します。

|`✗ N file(s) need your attention` +
`conflict markers were written`
|チームの編集と kit の変更が同じ箇所です。マーカーを解消して `aidev apply` を実行し、コミットします。kit 版にしてよければ `aidev apply --force` です。

|`edited locally and the template it was based on …`
|kit の clone に前回のコミットがありません（shallow clone など）。kit の clone で `git fetch --unshallow` するか、手で直すか `aidev apply --force` にします。

|`✗ the kit checkout has diverged from origin/main`
|kit の clone にローカルコミットがあります。捨ててよければ `git reset --hard origin/main`。
|===

[[troubleshooting-windows]]
=== Windows

[%autowidth.stretch,options="header"]
|===
|症状 |対処

|PowerShell で `aidev.ps1` が実行ポリシーで止まる
|`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`、または `aidev.cmd` を明示して実行します。

|hook が `aidev` を見つけられない
|新しいターミナルで `claude` を起動します。installer が PATH を追加済みです。

|`Place this policy now?` などの質問が出ずに終わる
|stdin が端末ではありません（IDE の統合ターミナルの一部、パイプ）。通常のターミナルで実行するか、`--yes` / `--approve` で値を渡します。

|`spawnSync git ETIMEDOUT`
|remote への確認が 3 秒で timeout しました。作業は続けられます。proxy を確認します。
|===
